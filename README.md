# FAVMOA · 팹모아

자주 찾는 링크를 한곳에, 팹모아.

**FAVMOA 0.1.26**은 어느 웹사이트에서든 열 수 있는 Chrome 사이드 패널에 링크를 **그룹 → 하위 그룹 → 링크**로 정리하는 확장입니다. 각 그룹은 링크와 더 작은 하위 그룹을 함께 담을 수 있습니다. 로그인 없이 이 Chrome 프로필에 저장하고, 기기 간 이동은 **JSON 백업·복원**으로 진행합니다. 최소 **Chrome 116**이 필요합니다. 0.1.11부터 공개키로 개발용 확장 ID를 고정했습니다. **키 없는 0.1.10 이하에서 처음 전환할 때는 백업·별도 설치·가져오기로 진행하세요.** 0.1.11~0.1.25에서는 JSON 백업 후 같은 폴더에 업데이트하고 새로고침하면 됩니다.

## 이번 버전에서 사용하기

- 고정 확장 ID: `ebbgmhdbonpillbfjapebljagnbjembj` — 동일 공개키를 포함한 패키지는 컴퓨터·폴더가 달라도 같은 ID
- 웹 주소부터 입력해 링크 저장 — 이름은 선택 사항이며 비우면 사이트 주소를 사용, 저장 위치 선택은 접힌 상태로 시작
- 현재 페이지 저장, 그룹·하위 그룹 접기, 검색과 링크 위치 변경
- 그룹 안에 링크와 하위 그룹을 함께 정리하고, 그룹을 내용물 전체와 함께 이동
- 링크·그룹을 다른 그룹으로 드래그앤드롭, 하위 그룹을 최상위로 이동 — 기존 이동 메뉴도 유지
- **선택 → 여러 링크 고르기 → 선택 이동…**으로 한 번에 그룹 변경, 한 번의 되돌리기로 복구
- 현재 페이지의 저장 위치 표시, 이미 열린 링크는 기존 탭으로 전환, 별도 새 탭 열기
- 선택한 Chrome 북마크만 복사해서 가져오기 — 가져오기 버튼을 눌렀을 때만 권한 요청
- 기존 Moa의 Notion 트리를 새 보관함으로 가져오기 — 원본은 유지하고 복사본만 생성
- JSON 백업·복원과 복원 전 목록의 별도 안전 사본 1개, 최근 작업 되돌리기
- 상단 로컬 저장 안내와 백업 바로가기, 복원 전 현재·가져올 목록 개수 비교
- 첫 링크 시작 안내, 검색 지우기, 보관함 이름 변경
- Notion도 다른 서비스처럼 일반 링크로 저장·열기 — 사이트 안에 별도 메뉴나 화면을 넣지 않음
- 상단 **테마**에서 시스템 설정·밝게·어둡게 선택, 여섯 가지 색상 조합과 사용자 지정 강조색·배경색 미리보기
- 팔레트 아이콘이 있는 **테마** 버튼, 그룹·하위 그룹별 색상 표식·트리 연결선·연한 배경

0.1.26은 **여러 링크 선택 후 한 번에 이동**을 추가합니다. 명시적으로 **선택**을 누른 동안만 체크박스와 제목으로 링크를 고르며 링크 열기·드래그는 잠시 멈춥니다. **보이는 링크 모두 선택**은 현재 검색과 접힘 상태에서 실제 표시된 링크에만 적용하고, 화면 밖에 숨겨진 선택은 유지하면서 개수로 알려줍니다. 이동 전 전체 선택 수와 숨겨진 항목 수를 확인하고, 성공한 이동 전체를 한 번의 되돌리기로 복구할 수 있습니다. 취소·오류는 목록을 바꾸지 않으며 오류 뒤 선택은 유지합니다. 데이터 형식·권한·확장 ID·클라우드 보류 상태는 그대로입니다. 검증 범위는 [0.1.26 QA](docs/QA-0.1.26.md)에 구분합니다.

**Google 연결·Drive 백업은 보류했습니다.** 0.1.14부터 Google 인증 권한·API 호스트 권한·OAuth 설정을 넣지 않으며 클라우드 코드를 실행하거나 배포 ZIP에 포함하지 않습니다. 기존 구현과 공개 설정은 소스에 보존합니다. 자동 기기 간 동기화·동시 변경 병합·Drive 하위 폴더 탐색은 제공하지 않습니다.

0.1.25는 **링크 클릭 때 잠깐 나타났다 사라지는 문구**를 제거합니다. 제목과 **현재·열림** 배지는 그대로 유지하고 접근성용 처리 상태만 즉시 갱신합니다. 정상 이동은 화면을 밀어내지 않는 스크린리더 안내로, 실패는 보이는 오류로 구분하며 기존 저장 안내를 덮어쓰지 않습니다. 새 보관함을 만들면 바로 선택하고 이전 검색어를 비웁니다. 입력 오류는 해당 칸에 표시하고 포커스를 옮기며, 저장 중에는 대화상자의 입력·버튼을 잠그고 실패하면 원래 편집 상태로 복구합니다. 저장 형식·권한·확장 ID는 유지합니다. 검증 범위와 남은 한계는 [0.1.25 QA](docs/QA-0.1.25.md)에 구분합니다.

0.1.24에서 수정한 **링크의 첫 클릭 보존**은 유지합니다. 탭·포커스 정보가 화면상 같으면 목록을 다시 그리지 않고, 누르는 동안 도착한 탭·목록 갱신은 클릭 처리가 끝난 뒤 반영해 누르고 있는 링크를 보존합니다. 드래그 직후의 자동 클릭 차단은 유지하되 새로 누르는 클릭까지 막지 않습니다. 당시 재현·회귀 검사와 실제 Chrome 확인 범위는 [0.1.24 QA](docs/QA-0.1.24.md)에 보존합니다.

0.1.23에서 추가한 **드래그앤드롭 이동·링크 열기 응답·`+ 그룹` 버튼**은 유지합니다. 링크와 사용자 그룹을 다른 그룹에 놓아 옮기고, 하위 그룹을 최상위로 옮길 수 있습니다. 기존 이동 메뉴와 되돌리기도 유지합니다. 탭 조회를 병렬 처리하며 처리 중인 같은 링크의 일반 클릭을 합쳐 중복 열기를 방지합니다. 당시의 **여는 중** 문구는 0.1.25에서 조용한 피드백으로 대체했습니다. `+ 그룹`은 테마 강조색의 보조 버튼으로 표시합니다. 확장 내부 대기 감소와 원본 웹사이트의 로딩 속도는 별개입니다. 당시 검증과 한계는 [0.1.23 QA](docs/QA-0.1.23.md)에 보존합니다.

0.1.22에서 추가한 **같은 그룹의 제목과 링크를 연한 그룹색 배경으로 묶는 표시**는 유지합니다. 하위 그룹은 각각 자기 색을 사용하고, 색을 지정하지 않은 그룹은 기본 배경을 유지합니다. 테마에 맞춰 배경 농도를 조정하며 중첩이 깊어져도 색이 계속 진해지지 않습니다. 당시 검증과 한계는 [0.1.22 QA](docs/QA-0.1.22.md)에 보존합니다.

0.1.21에서 추가한 **그룹별 색상과 테마 팔레트 아이콘**은 유지합니다. 그룹의 **더보기 → 그룹 색상**에서 색상 선택기나 HEX 값으로 정하고 저장합니다. 미분류 그룹을 포함해 하위 그룹마다 독립적으로 정하며, 그룹 색은 보관함 데이터에 포함되어 JSON 백업·되돌리기와 함께 보존됩니다. **색상이 들어간 백업은 0.1.21 이상에서만 열 수 있습니다.** 당시 검증 범위는 [0.1.21 QA](docs/QA-0.1.21.md)에 보존합니다.

0.1.20에서 추가한 **내 취향에 맞는 테마**는 그대로 유지합니다. 강조색과 밝은 모드·어두운 모드의 배경색을 미리 본 뒤 저장하거나 취소합니다. 글자·버튼·포커스 색은 배경과의 대비를 계산해 결정합니다. 테마 설정은 링크 보관함과 별도로 이 Chrome 프로필에 저장되며 링크 JSON 백업에는 포함하지 않습니다. 당시 검증 범위는 [0.1.20 QA](docs/QA-0.1.20.md)에 보존합니다.

0.1.19부터 **Notion 전용 내부 화면을 종료하고 Chrome 사이드 패널 하나만 사용**합니다. Notion 수신함 옆 메뉴·내부 트리·즐겨찾기 DOM 수집은 제공하지 않습니다. 기존 `nfs:` 데이터는 삭제하거나 자동 이전하지 않으며, 사용자가 **기존 Moa 목록 가져오기**를 실행할 때만 새 보관함으로 복사합니다. 범용 보관함·확장 ID·공개키·로컬 저장·JSON 백업은 유지합니다. 당시 검증 범위는 [0.1.19 QA](docs/QA-0.1.19.md)에 보존합니다.

과거 0.1.18은 **확인한 Notion 링크 경로 보존·미확인 주소 열기 방지**를 다룬 내부 화면 수정입니다. 해당 화면은 0.1.19부터 배포하지 않으며, 당시 검증과 한계는 [0.1.18 QA](docs/QA-0.1.18.md)에 역사 기록으로 보존합니다.

과거 0.1.17은 **현재 Notion 페이지의 전체 경로를 보존**하는 핫픽스입니다. 페이지 주소를 ID만으로 재구성하면서 원래 경로가 사라지는 동작을 수정합니다. 기존 사용자 데이터·schema 2·저장 키·확장 ID·권한은 변경하지 않습니다. 확인한 동작과 한계는 [0.1.17 QA](docs/QA-0.1.17.md)에 기록합니다.

0.1.16은 섹션 단계를 없애고 재귀 그룹을 도입합니다. 데이터 형식은 schema 2이며, 사용자 섹션은 이름과 내용을 유지한 하위 그룹으로, 자동 미분류 섹션의 링크는 부모 그룹의 직접 링크로 변환합니다. 변경 범위·이전 규칙은 [재귀 그룹 전환](docs/RECURSIVE-GROUPS-0.1.16.md), 당시 자동 검사 **367/367**, 합성 UI·ZIP 검증과 미검증 범위는 [0.1.16 QA](docs/QA-0.1.16.md)에 보존합니다. 구형 브라우저 검사에는 최초 7/8 뒤 재실행 8/8의 간헐 실패가 있었으며 수정 완료로 판정하지 않았습니다. 확장 ID·공개키·권한과 기존 Notion 원본 저장소는 유지합니다.

0.1.15의 밝은 중성색·글자 크기·목록 중심 스타일을 유지합니다. 당시 조사한 공식 사례와 적용 결과는 [UI 리프레시](docs/UI-REFRESH-0.1.15.md), 당시 전후 화면·328개 자동 검사·8개 합성 브라우저 검사와 한계는 [디자인 QA](design-qa.md)에 보존합니다. 이 과거 검사 숫자는 0.1.16 검증 결과가 아닙니다.

0.1.14의 점검과 개선 근거는 [UX 점검](docs/UX-AUDIT-0.1.14.md), 당시 확인한 동작과 남은 검증 범위는 [검증 결과](docs/QA-0.1.14.md)를 참고하세요. 이전 Google 연결 시도의 결과는 [0.1.13 검증 기록](docs/QA-0.1.13.md)에 보존합니다.

제품의 전체 목표와 구현 범위는 [FAVMOA PRD](docs/PRD.md), 상세 안내는 [확장 README](extension/notion-favorite-sections/README.md)에 있습니다.

## 설치·업데이트

1. **기존 버전에서 JSON 백업을 먼저 저장합니다.** 저장소를 다운로드하거나 배포 ZIP `favmoa-v0.1.26.zip`을 압축 해제합니다. 키 없는 0.1.10 이하 사용자는 이전 설치와 **별도 폴더**를 사용합니다. 0.1.11~0.1.25 사용자는 기존 설치 폴더의 파일을 업데이트하고 확장 카드의 새로고침을 누릅니다.
2. Chrome의 `chrome://extensions`에서 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**에서 `manifest.json`이 있는 폴더를 선택합니다. 소스를 받은 경우 `extension/notion-favorite-sections`입니다.
4. 도구 모음에 FAVMOA를 고정하고 아이콘을 누르면 사이드 패널이 열립니다.
5. 이미 열려 있던 Notion 탭도 새로고침합니다. 이전 버전이 넣었던 내부 메뉴가 사라지고 Chrome 사이드 패널만 사용합니다.

**0.1.10 이하 → 0.1.11 이상 전환:** 기존 확장에서 JSON으로 내보내기 → 새 고정 ID 확장을 별도 폴더에 설치 → JSON 가져오기 → 링크 이름·개수·분류 확인 순서입니다. 기존 확장을 삭제하거나 초기화하지 마세요. **0.1.9 사용자는 원래 설치 폴더에서 키 없는 0.1.10으로 먼저 업데이트하고, ‘기존 Moa 목록 가져오기’로 범용 보관함에 복사한 뒤 JSON을 내보내야 합니다.** 원본 구형 Notion 트리까지 다른 ID에 직접 복원하는 기능은 아닙니다. 자세한 절차는 [ID 고정과 안전한 이전](docs/EXTENSION-IDENTITY.md)에 있습니다.

0.1.11 이후 같은 공개키의 업데이트는 기존 설치 폴더에서 새로고침하면 됩니다. **같은 ID라도 다른 컴퓨터·Chrome 프로필의 로컬 데이터는 자동으로 복사되지 않습니다.** 원래 기기에서 JSON 백업을 저장하고 새 기기에서 불러오세요. 두 구형·신형 확장이 함께 설치되어 Notion 메뉴가 중복되면 목록 확인 뒤 구형 확장은 삭제하지 말고 비활성화하세요.

새 보관함의 **기존 Moa 목록 가져오기**는 이 확장에 남아 있는 Notion 트리를 명시적으로 복사합니다. 종료된 전용 화면의 원본 워크스페이스 트리·제목 캐시·저장 키는 지우지 않습니다. 자동 이전·자동 동기화나 Notion 즐겨찾기의 새 수집은 하지 않습니다. 데이터가 다른 확장 ID나 Chrome 프로필에 있으면 원래 설치에서 JSON으로 내보낸 뒤 가져오세요.

### 0.1.16 데이터 이전과 이전 버전으로 돌아가기

범용 보관함의 기존 schema 1 목록과 JSON 백업은 schema 2로 변환해 읽습니다. 사용자 섹션은 하위 그룹이 되고, 자동 생성된 미분류 섹션은 별도 단계를 만들지 않고 링크를 부모 그룹에 직접 둡니다. **이름이 ‘미분류 섹션’인 사용자 섹션을 이름만 보고 합치지 않습니다.** 종료된 Notion 전용 화면의 원본 저장소는 변경하지 않습니다.

**0.1.16이 내보낸 schema 2 백업은 0.1.15 이하에서 읽을 수 없습니다.** 새 형식 목록에 구형 코드를 덮어씌우는 다운그레이드는 지원하지 않습니다. 되돌아갈 필요에 대비해 업데이트 전 schema 1 JSON을 별도 파일로 보관하세요. 이후 새 버전에서 한 편집은 업데이트 전 백업에 포함되지 않습니다. JSON 불러오기는 변환 후에도 전체 교체이며 자동 병합이 아닙니다.

## 여러 링크를 한 번에 옮기기

1. 링크 목록 위의 **선택**을 누릅니다. 이 모드에서는 체크박스나 제목을 눌러 선택하고, 링크를 열거나 끌어 옮기지 않습니다.
2. 여러 링크를 고릅니다. **보이는 링크 모두 선택**은 펼쳐진 그룹과 검색 결과에 표시된 링크만 선택·해제합니다. 검색·접힘으로 숨겨진 선택은 유지되고 **화면 밖 …개 포함**으로 표시됩니다.
3. **선택 이동…**을 눌러 전체 선택 수와 숨겨진 항목 수를 확인하고 목적지 그룹을 지정한 뒤 **이동**합니다. 이미 목적지에 있는 링크는 위치와 순서를 유지하며, 모두 같은 목적지에 있으면 이동할 필요가 없다고 안내합니다.
4. 잘못 옮겼으면 다른 편집을 하기 전에 **되돌리기**를 한 번 누릅니다. 일괄 이동 전체를 복구합니다.

이동 창을 취소하면 목록은 바뀌지 않고 선택은 유지합니다. 오류가 나도 부분 이동하지 않으며 선택을 유지하되, 최신 목록에서 제거된 링크는 선택에서 제외합니다. **선택 종료**나 Escape로 모드를 끝내면 임시 선택을 비웁니다. 검색칸에 검색어가 있으면 첫 Escape는 검색어만 지우고 다음 Escape가 선택 모드를 종료합니다. 보관함을 바꾸면 선택은 초기화됩니다. 선택 상태는 로컬 목록·JSON 백업에 저장하지 않습니다. 일반 모드의 링크 열기·드래그앤드롭은 그대로입니다.

## 나만의 테마

1. 사이드 패널 상단에서 팔레트 아이콘이 있는 **테마**를 누릅니다.
2. **시스템 설정·밝게·어둡게** 중 하나를 선택합니다. 시스템 설정은 기기의 밝기 모드 변경을 따릅니다.
3. 여섯 가지 기본 색상 조합 중 하나를 고르거나 **강조색·밝은 배경·어두운 배경**을 색상 선택기 또는 `#RRGGBB` 값으로 지정합니다.
4. 패널에 미리 적용된 모습을 확인한 뒤 **저장**합니다. **취소**하면 저장 전 테마로 돌아갑니다.

**기본 테마로**는 편집 중인 미리보기만 기본값으로 바꾸며, 저장해야 확정됩니다. 테마 변경과 초기값 복원은 링크·그룹·되돌리기 기록을 변경하지 않습니다. 테마는 이 Chrome 프로필 전체의 FAVMOA 보관함에 적용되며 다른 컴퓨터와 동기화하거나 링크 JSON 백업에 넣지 않습니다. JSON 목록 복원·로컬 목록 초기화도 테마를 바꾸지 않습니다.

## 그룹별 색상

1. 색을 바꿀 그룹의 **더보기 → 그룹 색상**을 엽니다.
2. 색을 고르거나 `#RRGGBB`로 입력한 뒤 **저장**합니다. 취소하면 기존 색을 유지합니다.
3. 색을 없애려면 **기본 색상 → 저장**을 누릅니다. 그룹 이름·링크·하위 구조는 바뀌지 않습니다.

색상은 이름 옆 표식·트리 연결선과 제목·링크를 감싸는 연한 배경에 표시합니다. 상위 그룹을 바꿔도 하위 그룹의 색은 자동으로 바뀌지 않으며, 색을 지정하지 않은 그룹은 기본 배경을 사용합니다. 중첩 그룹의 배경색이 투명하게 겹쳐 진해지지 않고, 밝은·어두운 테마와 사용자 배경에서 읽기 쉽도록 농도를 조절합니다. 미분류 그룹도 색을 정할 수 있지만 이름 변경·이동·삭제 보호는 유지합니다.

그룹 색상은 테마와 달리 보관함의 선택적 `color` 필드에 저장되므로 최근 작업 되돌리기와 JSON 백업에 포함됩니다. 기존 색상 없는 schema 1·2 백업을 그대로 가져올 수 있습니다. **색상 필드가 포함된 schema 2 백업은 0.1.20 이하에서 거부되므로 0.1.21 이상으로 복원하세요.** 색을 지정한 저장소 위에 구버전을 덮어씌우는 다운그레이드는 지원하지 않습니다. 업데이트 전 백업은 따로 보관하세요.

### 다음에 검토할 개선점 — 아직 미구현

- **고정·최근 링크:** 깊은 그룹을 매번 펼치지 않고 자주 쓰는 링크로 바로 이동하기.
- **키보드 위치 이동:** 링크와 그룹을 마우스 없이 더 빠르게 옮기기.

위 두 항목은 후속 제안이며 이번 릴리스에 구현한 기능이 아닙니다.

## 로컬 저장과 JSON 백업

**백업 · 가져오기 · 설정 → JSON 백업 저장**으로 전체 보관함을 파일에 보관합니다. **JSON 백업 불러오기…**에서 현재·가져올 보관함과 링크 개수를 비교하고 적용합니다. 복원은 **현재 전체 보관함을 교체**하며 합치기가 아닙니다. 파일에는 제목·URL·분류가 포함되므로 안전하게 보관하세요. 확장을 삭제하기 전에도 파일 백업이 필요합니다.

목록이 교체되면 **복원 직전 목록의 안전 사본 1개**를 별도 저장합니다. 이 사본은 일반 편집·일반 되돌리기·패널 재열기 후에도 유지되며, 다음 JSON 복원으로 목록이 바뀌면 그때의 직전 목록으로 대체됩니다. **복원 전 목록 복구…**를 성공적으로 실행하면 사본은 사용 완료됩니다. 복구 작업 자체는 다음 변경 전까지 일반 **되돌리기**로 한 번 취소할 수 있습니다. 안전 사본은 파일 백업을 대신하지 않습니다.

전체 catalog는 간결한 UTF-8 JSON 기준 **5MiB**, 가져올 백업 파일은 포장 정보를 포함해 **6MiB**까지 허용합니다. 현재 목록·일반 되돌리기·복원 전 안전 사본으로 최대 3개 catalog를 저장합니다. **schema 1에서 처음 실제 변경을 저장할 때 이전 원본 3종의 사본이 추가될 수 있으므로 전체 저장 공간이 3개 catalog로 제한되는 것은 아닙니다.** 기존 Notion 데이터와 캐시도 공간을 차지해 실제 저장 가능한 목록 크기는 Chrome 저장소 한도에 따라 5MiB보다 작을 수 있습니다. 공간 부족·파일 검증 실패·충돌이 발생하면 오류를 확인하고 현재 목록을 먼저 JSON으로 보관하세요. 1MiB는 1,048,576바이트입니다.

필수 권한은 `storage`, `sidePanel`, `tabs`이며 `bookmarks`는 선택 권한입니다. 사이트에 주입하는 콘텐츠 스크립트는 없습니다. 비공개 원본을 열려면 해당 서비스의 로그인과 접근 권한이 필요합니다. 원본 문서·Drive 파일·Chrome 북마크는 수정하지 않으며 페이지 본문·서비스 로그인 쿠키를 수집하지 않습니다.

## 보류한 Google 연동

공개 클라이언트 ID와 범위는 [보류 설정](extension/notion-favorite-sections/config/google-cloud.deferred.json), 구현은 기존 소스에 보존합니다. 이 설정과 클라우드 모듈은 배포 ZIP에서 제외하고 `CLOUD_ENABLED=false`를 검사합니다. 오래된 화면에서 보낸 클라우드 요청도 `CLOUD_PAUSED`로 응답하며 인증·네트워크·저장 데이터 변경을 실행하지 않습니다. 기존에 저장된 연결 메타데이터도 지우지 않습니다. Google 인증과 실계정 Drive 백업·복원은 검증되지 않았으며 이번 릴리스의 사용 경로가 아닙니다.

## 개발·검증

Node.js가 필요합니다. 테스트·로컬 데모·패키징에는 별도 npm 패키지가 필요하지 않습니다.

```sh
npm test
npm run check:extension-package
npm start
```

- 범용 패널 데모: `http://127.0.0.1:4173/extension/notion-favorite-sections/sidepanel/sidepanel.html`
- 과거 Notion 합성 데모(종료된 화면·배포 제외): `http://127.0.0.1:4173/extension/notion-favorite-sections/test/browser-live-demo.html`
- 과거 Notion 회귀 검사(현행 사용 화면 아님): `http://127.0.0.1:4173/extension/notion-favorite-sections/test/browser-suite.html`
- 포트 변경: `PORT=4174 npm start`

로컬 데모는 합성 페이지·북마크와 별도 저장소를 사용합니다. 실제 열린 탭·Chrome 북마크·확장 저장소 동작은 설치한 확장에서 별도로 확인해야 합니다. `npm test`는 Node 검사이며 실제 브라우저 동작 완료를 의미하지 않습니다. 보존된 Google 구현의 테스트는 모의 응답으로만 실행하며 실계정 연결 증거가 아닙니다.

```sh
npm run package:extension
node extension/notion-favorite-sections/scripts/package-extension.mjs --verify artifacts/favmoa-v0.1.26.zip
```

ZIP은 `artifacts/favmoa-v0.1.26.zip`에 생성되고 Git에서는 제외합니다. 동일 소스·버전은 동일한 ZIP을 생성합니다. 공개키와 별도 ID 고정 메타데이터를 비교하여 키 제거·변경을 배포 전에 차단합니다. Google 권한·OAuth 설정·클라우드 런타임과 종료된 Notion 내부 UI는 배포 대상이 아닙니다. 서명 개인키는 `.private/`에만 보관하며 Git과 ZIP에 포함하지 않습니다. 아이콘 재생성에만 `sharp`가 필요합니다. 다음 패치 버전은 **0.1.27**입니다. 상표·도메인·스토어 이름 확보와 웹스토어 등록은 별도이며 이 저장소는 공식 Notion 또는 Google 제품이 아닙니다.
