# FAVMOA · 팹모아

**0.1.33 · Chrome 116 이상.** 어느 사이트에서든 Chrome 사이드 패널에서 링크를 `그룹 → 하위 그룹 → 링크`로 정리합니다. 각 그룹은 링크와 하위 그룹을 함께 담는 같은 종류의 분류입니다. 로그인 없이 이 Chrome 프로필의 로컬 저장소를 사용하며, 백업과 기기 간 이동은 JSON 파일로 진행합니다. Google 연결·클라우드 백업은 보류했습니다. Notion 전용 내부 화면은 종료하고 Chrome 사이드 패널만 사용합니다. Moa에서 **FAVMOA · 팹모아**로 이름이 바뀌었으며, 저장 키·기존 확장 소스 경로·책갈피 심벌은 유지합니다. 0.1.11부터 공개키 기반 고정 ID를 사용합니다.

0.1.33은 **그룹 이동·일괄 링크 이동의 충돌 복구**를 추가합니다. 최신 목록 검토로 원래 보관함·이동할 그룹·선택 링크와 유효한 목적지 선택을 유지하며 최신 저장 목록을 읽어 확인합니다. 이동할 하위 트리·링크의 내용이나 위치, 목적지 경로가 바뀌었다면 명시적으로 확인한 뒤 별도로 이동해야 합니다. 삭제된 출발 그룹·선택 링크·보관함은 자동 대체하지 않고, 일부 링크만 이동하지 않습니다. 사라지거나 이동 불가능해진 목적지는 직접 다시 선택해야 합니다. 검토만으로 이동하거나 변경을 자동 재적용하지 않으며 삭제·초기화·백업 확인창의 충돌 복구는 후속 개선 대상입니다. schema 2·저장 키·권한·확장 ID는 유지합니다. 검증 범위와 한계는 [0.1.33 QA](../../docs/QA-0.1.33.md)에 구분합니다.

0.1.32의 **보관함·그룹 추가와 이름 변경, 그룹 색상 변경의 충돌 복구**도 유지합니다. **입력 유지하고 최신 목록 검토**로 이름·색상 입력을 유지하며 최신 저장 목록을 읽어 확인합니다. 대상의 이름·색상·경로가 바뀌었다면 명시적으로 확인한 뒤 별도로 저장해야 합니다. 삭제된 보관함·그룹·상위 그룹은 자동 재생성하거나 다른 위치로 바꾸지 않고 입력을 복사하거나 취소할 수 있게 남깁니다. 새 보관함 추가는 이전 보관함의 삭제와 무관하게 검토 후 진행할 수 있습니다. 당시 검증 범위와 한계는 [0.1.32 QA](../../docs/QA-0.1.32.md)에 보존합니다.

0.1.31의 **수동 링크 추가·수정과 단일 링크 이동의 충돌 복구**도 유지합니다. 충돌하면 **입력 유지하고 최신 목록 검토**로 작성한 값을 유지하며 최신 저장 목록을 읽어 확인합니다. 대상 링크의 내용·위치가 바뀌었다면 최신 값을 검토하고 명시적으로 확인한 뒤 별도로 저장해야 합니다. 삭제된 기존 링크·보관함은 자동 재생성하지 않고, 새 링크의 목적지가 사라졌다면 직접 다시 선택해야 합니다. 확인만으로 저장하거나 최신 변경을 자동으로 덮어쓰지 않습니다. 당시 검증 범위와 한계는 [0.1.31 QA](../../docs/QA-0.1.31.md)에 보존합니다.

0.1.30의 **열린 탭·북마크 가져오기 창의 충돌 복구**도 유지합니다. 저장 충돌 뒤에도 선택과 검색어를 유지하고 **선택 유지하고 최신 목록 검토**로 바뀐 보관함을 읽어 검토할 수 있습니다. 이미 저장된 선택은 제외 개수를 알려주며, 삭제된 목적지 그룹·보관함은 직접 다시 선택해야 합니다. 확인은 읽기만 하고, 사용자가 다시 담기를 눌러야 저장합니다. 원본 탭·북마크 재조회, 북마크 권한 재요청, 자동 덮어쓰기는 하지 않습니다. 당시 검증 범위와 한계는 [0.1.30 QA](../../docs/QA-0.1.30.md)에 보존합니다.

0.1.29의 **그룹 접기·펼치기와 내용 편집의 되돌리기 분리**도 유지합니다. 링크 추가·이동·이름이나 색상 변경 뒤 그룹을 접거나 펼쳐도 마지막 내용 편집을 취소할 수 있습니다. 편집 뒤 직접 바꾼 접힘 상태는 유지하며, 접기·펼치기 자체는 되돌리기 이력을 만들지 않습니다. **마지막 내용 편집 1회** 정책을 유지하고 여러 단계 되돌리기는 제공하지 않습니다. schema 2·저장 키·권한·확장 ID·복원 전 안전 사본은 유지합니다. 당시 검증 범위와 한계는 [0.1.29 QA](../../docs/QA-0.1.29.md)에 보존합니다.

0.1.28의 **북마크 가져오기와 열린 탭 담기의 통일된 선택 흐름**도 유지합니다. 북마크 제목·URL·폴더 경로로 검색하고 보이는 항목 전체 선택·숨겨진 선택 수·200개씩 더 보기를 제공합니다. 두 가져오기 창의 **선택 해제**는 검색어를 유지하면서 숨겨진 선택까지 해제합니다. 선택 0개 저장 방지와 최대 1,000개 선택 제한, 긴 제목 정리, 읽기 중 취소와 오래된 결과 무시를 적용합니다. 하나의 원자적 저장 후 목적지 그룹을 펼치고 한 번의 되돌리기로 추가 전체를 취소합니다. schema 2·권한·확장 ID·클라우드 보류 상태는 유지합니다. 당시 검증 범위와 한계는 [0.1.28 QA](../../docs/QA-0.1.28.md)에 보존합니다.

0.1.27에서 추가한 **열린 탭 담기**는 유지합니다. 현재 Chrome 프로필의 모든 일반 창에서 필요한 웹 탭을 골라 그룹에 링크로 복사하며 시크릿 탭·이미 저장한 링크·중복 탭은 제외합니다. 기존 `tabs` 권한을 사용하고 원래 탭은 닫거나 이동하지 않습니다. 당시 검증 범위와 한계는 [0.1.27 QA](../../docs/QA-0.1.27.md)에 보존합니다.

0.1.26에서 추가한 **여러 링크 선택 후 한 번에 이동**은 유지합니다. **선택** 모드에서 체크박스나 제목으로 링크를 고르고 **선택 이동…**으로 목적지 그룹을 정합니다. 보이는 링크만 전체 선택하고 검색·접힘으로 숨겨진 선택은 개수로 안내합니다. 한 번에 저장하고 한 번의 되돌리기로 복구하며, 취소·오류는 부분 이동하지 않습니다. 일반 모드의 링크 열기·드래그는 유지하고 선택 중에는 오조작을 막습니다. schema 2·저장 키·권한·확장 ID와 클라우드 보류 상태는 바꾸지 않습니다. 당시 검증과 한계는 [0.1.26 QA](../../docs/QA-0.1.26.md)에 보존합니다.

0.1.25는 **링크 클릭 때 잠깐 나타났다 사라지는 문구**를 없앱니다. 제목과 **현재·열림** 배지는 유지하며 접근성용 처리 상태만 즉시 갱신합니다. 정상 이동은 스크린리더에 조용히 안내하고 실패는 화면에 표시하므로 저장 안내나 목록 위치를 매번 바꾸지 않습니다. 새 보관함은 만든 직후 선택되고 이전 검색어는 비워집니다. 입력 오류는 해당 칸에 표시하고 포커스를 옮기며, 저장 중에는 대화상자 입력·버튼을 잠갔다가 실패하면 원래 상태로 돌립니다. 데이터 형식·권한·확장 ID는 그대로입니다. 검증과 한계는 [0.1.25 QA](../../docs/QA-0.1.25.md)에 기록합니다.

0.1.24에서 수정한 **링크의 첫 클릭 보존**은 유지합니다. 탭·포커스 갱신 결과가 화면상 같으면 목록을 유지하고, 클릭 중 도착한 변경은 클릭 처리 뒤 반영하여 누르고 있는 링크를 보존합니다. 드래그 직후의 자동 클릭은 막되 새로 누르는 클릭은 받습니다. 당시 재현·회귀 검사와 실환경 확인의 구분은 [0.1.24 QA](../../docs/QA-0.1.24.md)에 보존합니다.

0.1.23에서 추가한 **드래그앤드롭 이동·링크 열기 응답·`+ 그룹` 버튼**은 유지합니다. 링크와 사용자 그룹을 다른 그룹으로 끌어 옮기고, 하위 그룹을 최상위로 옮길 수 있습니다. 기존 이동 메뉴와 되돌리기는 유지합니다. 탭 조회는 병렬 처리하고, 처리 중인 같은 링크의 일반 클릭은 하나의 열기 요청으로 합칩니다. 당시의 **여는 중** 문구는 0.1.25에서 조용한 피드백으로 대체했고 `+ 그룹` 버튼은 테마 강조색을 사용합니다. 원본 사이트의 로딩 속도를 보장하는 변경은 아닙니다. 당시 검증과 한계는 [0.1.23 QA](../../docs/QA-0.1.23.md)에 보존합니다.

0.1.22에서 추가한 **같은 그룹의 제목과 링크를 연한 그룹색 배경으로 묶는 표시**는 유지합니다. 하위 그룹은 각자의 색을 사용하고, 지정색이 없으면 기본 배경을 사용합니다. 중첩에 따라 배경이 진해지지 않으며 테마와 글자 대비에 맞춰 농도를 조정합니다. 당시 검증 범위는 [0.1.22 QA](../../docs/QA-0.1.22.md)에 보존합니다.

0.1.21에서 추가한 **그룹별 색상과 테마 팔레트 아이콘**은 유지합니다. **더보기 → 그룹 색상**에서 미분류 그룹을 포함해 각 그룹의 색을 독립적으로 정하며, 선택한 색은 보관함·되돌리기·JSON 백업에 포함됩니다. 색상이 포함된 백업은 0.1.21 이상에서 열어야 합니다. 당시 검증 범위는 [0.1.21 QA](../../docs/QA-0.1.21.md)에 보존합니다.

0.1.20에서 추가한 **사용자 지정 테마**는 유지합니다. 상단 **테마**에서 밝기 모드와 여섯 가지 색상 조합을 선택하거나 강조색·밝은 배경·어두운 배경을 직접 지정합니다. 패널 미리보기와 저장·취소를 제공하며, 테마는 보관함과 별도로 이 Chrome 프로필에만 저장합니다. 당시 검증 범위는 [0.1.20 QA](../../docs/QA-0.1.20.md)에 보존합니다.

0.1.19부터 **Notion 안의 메뉴·내부 트리·즐겨찾기 수집을 제거**했습니다. Notion 페이지는 다른 서비스처럼 링크로 담고 원본에서 엽니다. 기존 `nfs:` 데이터는 삭제하거나 자동 이전하지 않습니다. 필요할 때 **기존 Moa 목록 가져오기**를 실행하면 새 보관함에 복사합니다. 범용 schema 2·저장 키·공개키·확장 ID는 유지합니다. 당시 검증 범위는 [0.1.19 QA](../../docs/QA-0.1.19.md)에 보존합니다.

과거 0.1.18은 **확인한 Notion 링크 경로 보존·미확인 주소 열기 방지**를 다룬 내부 화면 수정입니다. 해당 화면은 0.1.19부터 배포하지 않으며, 당시 결과는 [0.1.18 QA](../../docs/QA-0.1.18.md)에 역사 기록으로 보존합니다.

과거 0.1.17은 **현재 Notion 페이지 주소의 전체 경로를 보존**하는 핫픽스입니다. ID만으로 링크를 재구성해 원래 경로를 잃는 동작을 수정하며, 기존 사용자 데이터·schema 2·저장 키·공개키·권한은 바꾸지 않습니다. 확인한 동작과 한계는 [0.1.17 QA](../../docs/QA-0.1.17.md)에 기록합니다.

0.1.16은 섹션을 별도 분류 모델에서 없애고 재귀 그룹을 도입합니다. schema 1 이전·JSON 호환성·보호 규칙은 [재귀 그룹 전환](../../docs/RECURSIVE-GROUPS-0.1.16.md), 당시 자동 검사 **367/367**, 합성 UI·ZIP 검증과 미검증 범위는 [0.1.16 QA](../../docs/QA-0.1.16.md)에 보존합니다. 구형 브라우저 검사는 최초 7/8 뒤 재실행 8/8이었으며 이 간헐 실패가 고쳐졌다고 판정하지 않습니다. 0.1.15의 밝은 중성색·글자 크기·목록 스타일을 유지합니다.

0.1.15의 공식 사례와 적용 결과는 [UI 리프레시](../../docs/UI-REFRESH-0.1.15.md), 당시 전후 화면·328개 자동 검사·8개 합성 브라우저 검사와 한계는 [디자인 QA](../../design-qa.md)에 보존합니다. 이 숫자는 0.1.16 검증 결과가 아닙니다. 이전 기능 개선 근거는 [0.1.14 UX 점검](../../docs/UX-AUDIT-0.1.14.md), 당시 확인한 동작과 남은 범위는 [0.1.14 검증 결과](../../docs/QA-0.1.14.md)에 있습니다.

## 설치와 업데이트

1. **기존 버전에서 JSON 백업을 먼저 저장합니다.** `favmoa-v0.1.33.zip`을 압축 해제하고 계속 보관할 폴더에 놓습니다. 키 없는 이전 버전과는 **별도 폴더**를 사용하세요. 0.1.11~0.1.32에서 업데이트할 때는 기존 설치 폴더에 새 파일을 적용하고 확장 카드에서 새로고침합니다.
2. `chrome://extensions`에서 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**에서 `manifest.json`이 바로 들어 있는 폴더를 선택합니다. ZIP 파일 자체는 선택할 수 없습니다.
4. 확장 카드에 **FAVMOA 0.1.33**, ID **ebbgmhdbonpillbfjapebljagnbjembj**가 표시되는지 확인합니다.
5. 도구 모음의 FAVMOA 아이콘을 누르면 사이드 패널이 열립니다. 열려 있던 Notion 탭도 새로고침해 이전 버전의 내부 메뉴를 없앱니다.

소스로 개발한다면 `extension/notion-favorite-sections`를 로드합니다. **0.1.10 이하에서 새 고정 ID로 처음 전환할 때 기존 폴더를 덮어쓰거나 확장을 삭제하지 마세요.** 0.1.10에서 **전체 보관함 내보내기**를 먼저 실행한 뒤 새 확장을 별도 폴더에 설치하여 **백업 파일 가져오기**로 복원합니다. 구형 Notion 트리를 쓰는 경우 내보내기 전에 **기존 Moa 목록 가져오기**를 실행합니다. 0.1.9라면 원래 설치 폴더에서 **키 없는 0.1.10**으로 먼저 업데이트해 이 기능을 사용합니다. 복원 후 제목·링크 개수·분류를 확인하고 구형 확장은 필요하면 비활성화만 하세요.

0.1.11 이후 같은 공개키의 패키지는 컴퓨터·폴더가 바뀌어도 동일 ID를 유지합니다. 로컬 데이터가 기기 간 자동 복사되는 것은 아닙니다. 원래 기기에서 JSON 백업을 저장하고 새 기기에서 불러오세요. 다음 업데이트는 기존 폴더에서 진행합니다. 키와 서명 파일, 스토어 등록 시 주의 사항은 [ID 고정 안내](../../docs/EXTENSION-IDENTITY.md)를 참고하세요.

## 범용 링크 보관함

- 보관함 안에 그룹·하위 그룹을 만들고 원하는 그룹에 현재 열린 페이지 또는 웹 주소를 직접 추가합니다. 링크 입력은 **웹 주소 → 이름(선택)** 순서이며 `example.com`처럼 프로토콜을 생략한 도메인에는 HTTPS를 붙입니다. 이름을 비우면 사이트 주소를 이름으로 사용합니다.
- 새 링크의 **저장 위치**는 선택한 그룹의 경로를 요약한 접힌 상태로 시작합니다. 펼치면 최상위 또는 하위 그룹을 선택할 수 있습니다.
- 각 그룹을 독립적으로 접고 펼칩니다. 그룹에 직접 링크와 하위 그룹을 함께 둘 수 있으며, 그룹 이동 시 하위 트리 전체가 같이 이동합니다. 자기 자신이나 자손 안으로의 이동은 차단합니다.
- 링크나 사용자 그룹을 다른 그룹에 드래그앤드롭하면 해당 그룹 안으로 이동합니다. 하위 그룹은 최상위로도 옮길 수 있습니다. 위치를 바꾼 뒤 **되돌리기**를 사용할 수 있으며, 키보드 사용자는 기존 **더보기 → 다른 그룹으로 이동** 메뉴를 이용합니다. 외부 웹페이지나 다른 보관함에서 끌어온 항목을 자동으로 추가하지 않습니다.
- 사용자 그룹을 삭제해도 내용은 지우지 않습니다. 직접 링크·하위 그룹을 부모로 옮기고, 최상위 그룹의 내용은 미분류 그룹으로 옮깁니다. 미분류 그룹은 최상위에 고정되며 이름 변경·삭제·이동은 안 되지만 링크·하위 그룹은 담을 수 있습니다.
- 검색 지우기로 전체 목록으로 돌아가고, 보관함 이름 변경으로 분류 목적을 알아보기 쉽게 정리합니다.
- 현재 페이지와 일치하는 저장 링크와 경로를 표시합니다. 웹 주소가 아닌 Chrome 설정 화면 등은 추가할 수 없습니다.
- **저장 위치 보기**는 다른 보관함까지 찾아 해당 링크의 조상 그룹 경로를 펼치고 링크로 초점을 옮깁니다. 여러 곳에 있으면 현재 보관함을 우선하며, 없으면 첫 일치 위치로 이동합니다.
- 일반 모드에서 링크를 누르면 제목·배지를 바꾸지 않고 접근성 처리 상태를 갱신하며, 일치하는 기존 탭이 있으면 해당 탭으로 전환합니다. 처리 중인 같은 링크를 일반 클릭으로 반복해도 열기 요청을 중복하지 않습니다. 명시적으로 새 탭 열기를 선택하면 새로 엽니다. 탭 준비와 원본 사이트의 문서 로딩은 별개이므로 사이트·네트워크 사정에 따라 페이지가 표시되기까지 시간이 걸릴 수 있습니다.
- Chrome 북마크는 버튼을 눌렀을 때 선택 권한을 요청합니다. 검색·선택한 항목만 가져오며 Chrome 원본 북마크는 변경하지 않습니다.
- 상단 **백업** 또는 **백업 · 가져오기 · 설정**에서 JSON 파일을 저장하고 불러옵니다. 복원 전 보관함·링크 개수를 비교할 수 있으며, 복원은 **현재 전체 보관함을 교체**합니다. 기존 목록에 합치는 기능이 아닙니다.
- 로컬 초기화는 해당 보관함의 관리 항목을 비웁니다. 원본 Notion 페이지·Drive 파일·Chrome 북마크를 지우지 않습니다.

범용 트리는 저장한 링크의 사용자 분류입니다. Drive 폴더를 링크로 저장해 여는 것은 가능하지만 **Drive의 실제 하위 폴더·파일 API 탐색은 아직 제공하지 않습니다.** 모든 서비스의 내부 계층을 자동 수집하는 기능도 아닙니다.

### Chrome 북마크를 골라 담기

1. **백업 · 가져오기 · 설정 → Chrome 북마크 선택 가져오기**를 누릅니다. 북마크 읽기 권한은 이 버튼을 직접 누를 때만 요청합니다.
2. 제목·주소·원래 폴더 경로로 검색하고 체크박스나 **보이는 북마크 모두 선택**으로 고릅니다. 처음 200개를 표시하고 **더 보기**로 200개씩 늘립니다.
3. 검색 밖 선택은 유지하고 전체 개수 옆에 안내합니다. **선택 해제**로 검색어를 유지한 채 숨겨진 선택까지 모두 해제합니다. 선택 0개이면 담기 버튼은 비활성화됩니다.
4. 현재 보관함의 목적지 그룹을 선택해 최대 1,000개를 한 번에 담습니다. 이미 저장한 주소·중복을 제외하고 저장한 그룹을 펼쳐 보여줍니다. 실수하면 다른 편집 전 **되돌리기** 한 번으로 추가 전체를 취소합니다.

원래 북마크·폴더는 변경하지 않고 폴더 구조도 자동 복사하지 않습니다. 가져올 제목은 제어문자·공백을 정리하고 최대 300자로 제한하되 전체 URL은 보존합니다. 읽는 동안 취소할 수 있으며, 취소되거나 교체된 창의 늦은 결과는 새 작업에 반영하지 않습니다. 저장은 검토한 보관함·revision으로 검증하므로 충돌·실패 시 일부만 추가하지 않습니다. 충돌했다면 **선택 유지하고 최신 목록 검토**로 선택·검색어를 유지한 채 검토하세요. 이미 저장된 선택의 제외 개수를 확인하고 삭제된 목적지는 직접 다시 선택합니다. 확인만으로 저장하거나 북마크를 다시 조회·권한 요청하지 않으며, 다시 담기를 눌러야 저장합니다. 로컬 데모의 합성 북마크는 실제 Chrome 권한·북마크 조회 검증을 대신하지 않습니다.

### 열린 탭을 골라 담기

1. **열린 탭 담기**를 누릅니다. 현재 Chrome 프로필의 모든 일반 창에서 HTTP(S) 웹 탭을 가져오며 시크릿 탭과 Chrome 설정·확장 화면 등은 제외합니다.
2. 제목이나 URL로 검색하고 필요한 항목만 고릅니다. **보이는 탭 모두 선택**은 검색 결과에 표시한 항목만 선택·해제하며 검색 밖 선택은 유지하고 개수로 표시합니다. 200개씩 **더 보기**를 제공하며 **선택 해제**는 검색어를 유지한 채 숨겨진 선택까지 해제합니다.
3. 현재 보관함의 목적지 그룹을 지정하고 추가를 확정합니다. 이 보관함에 이미 저장한 링크와 중복 탭은 제외하며 한 번에 최대 1,000개를 저장합니다.
4. 잘못 담았다면 다른 편집 전에 **되돌리기**를 한 번 눌러 이번 추가 전체를 취소합니다.

목록은 대화상자를 열 때 조회한 스냅샷입니다. 새 탭이나 변경한 주소는 대화상자를 닫고 다시 열어 조회하세요. 충돌 뒤 **선택 유지하고 최신 목록 검토**는 저장된 보관함만 다시 읽으며 원본 탭 목록은 갱신하지 않습니다. 선택·검색어와 이미 저장된 선택의 제외 개수를 확인하고, 삭제된 목적지는 직접 다시 골라 별도로 담기를 누르세요. 자동 선택·자동 저장하지 않으며 취소·검증 실패·저장 오류는 일부만 추가하지 않습니다. 탭을 닫거나 다른 주소로 이동하지 않고, 이름의 공백 등을 정리한 뒤 전체 URL을 일반 링크로 복사합니다. 탭 목록과 선택 상태는 저장·동기화하지 않습니다. 페이지 본문·쿠키·세션을 수집하거나 다른 PC의 열린 탭을 복원하는 기능이 아닙니다. URL 자체에도 민감한 업무 정보가 있을 수 있으므로 필요한 항목만 명시적으로 고르세요. 새 권한·로그인·클라우드 연결은 필요하지 않습니다.

### 여러 링크를 한 번에 옮기기

1. 목록 위의 **선택**을 누르고 체크박스나 링크 제목으로 여러 항목을 고릅니다. 선택 중에는 링크를 열거나 드래그하지 않습니다.
2. **보이는 링크 모두 선택**은 검색 결과와 펼쳐진 그룹에 실제 표시된 링크만 선택·해제합니다. 숨겨진 선택은 유지되며 전체 개수 옆에 **화면 밖 …개 포함**으로 표시합니다.
3. **선택 이동…**에서 전체 선택 수와 숨겨진 항목 수를 확인하고 그룹을 지정한 뒤 **이동**합니다. 목적지에 이미 있는 링크의 순서는 유지하며, 모두 목적지에 있으면 이동 버튼을 비활성화합니다.
4. 실수했다면 다른 내용 편집 전에 **되돌리기**를 한 번 눌러 전체 이동을 복구합니다. 그룹을 접거나 펼쳐도 이 기회는 유지됩니다.

이동 취소·오류 시 목록을 바꾸지 않고 선택을 유지합니다. 다른 화면에서 링크를 제거했다면 최신 목록 확인 후 해당 선택만 제외하며 오래된 revision으로 부분 이동하지 않습니다. **선택 종료**·Escape·보관함 전환은 임시 선택을 비웁니다. 검색칸의 검색어가 있으면 첫 Escape는 검색어만 지웁니다. 선택 상태는 패널 메모리에만 두며 저장소·JSON 백업에는 넣지 않습니다. 새 권한·로그인·클라우드 동기화는 추가하지 않습니다.

### 나만의 테마

- 사이드 패널 상단의 팔레트 아이콘이 있는 **테마**에서 **시스템 설정·밝게·어둡게**를 고릅니다. 시스템 설정을 선택하면 기기의 밝기 모드 변경에 맞춰 바뀝니다.
- 여섯 가지 색상 조합을 바로 적용해 보거나 **강조색·밝은 배경·어두운 배경**을 각각 색상 선택기와 `#RRGGBB` 입력으로 지정합니다. 잘못된 색상 값은 저장하지 않습니다.
- 선택한 색은 패널 전체에 미리 적용됩니다. **저장**은 확정하고 **취소**는 저장 전 테마로 복구합니다. **기본 테마로**도 미리보기만 초기값으로 바꾸므로 저장해야 확정됩니다.
- 글자·버튼·포커스 등의 표시 색은 배경과의 대비를 계산합니다. 색만으로 선택이나 오류를 구별하지 않고 텍스트·테두리·표시 상태를 함께 사용합니다.
- 테마는 이 Chrome 프로필 전체의 FAVMOA 보관함에 공통 적용되는 별도 설정입니다. 링크·그룹·되돌리기·복원 사본과 분리하며 **링크 JSON 백업에 포함하지 않습니다.** JSON 복원·목록 초기화로 테마가 바뀌지 않습니다. 다른 컴퓨터·프로필과 자동 동기화하지 않습니다.

### 그룹별 색상

- 그룹의 **더보기 → 그룹 색상**에서 색을 선택하거나 `#RRGGBB`로 입력하고 **저장**합니다. 취소하면 기존 색을 유지합니다. 잘못된 HEX 값은 저장하지 않습니다.
- **기본 색상 → 저장**은 선택한 그룹의 색 지정만 제거합니다. 기본 색상 버튼만 누르고 취소하면 기존 지정색이 유지됩니다. 그룹 이름·링크·하위 구조는 바뀌지 않습니다.
- 색은 이름 옆 표식·트리 연결선과 그룹 제목·링크의 연한 배경에 표시하고 텍스트 이름·폴딩 상태를 함께 유지합니다. 하위 그룹은 각각 독립적이며 상위 그룹의 색을 자동으로 물려받지 않습니다. 색이 없는 그룹은 기본 배경을 사용하고, 중첩되어도 투명 배경이 누적되지 않습니다. 글자 대비가 필요한 배경에서는 농도를 줄입니다.
- 미분류 그룹도 색을 지정할 수 있습니다. 이름 변경·이동·삭제 보호는 그대로 유지됩니다.
- 그룹 색은 선택적 `color` 필드로 보관함에 저장되어 이동·되돌리기·JSON 백업·복원에 포함됩니다. 프로필별 별도 설정인 전체 **테마**와 다릅니다.
- 기존 색상 없는 schema 1·2 백업은 그대로 가져올 수 있습니다. **색상이 포함된 schema 2 백업은 0.1.20 이하에서 거부되므로 0.1.21 이상에서 복원하세요.** 색을 지정한 저장소에 구버전을 덮어씌우는 다운그레이드는 지원하지 않습니다. 업데이트 전 백업은 따로 보관하세요.

### schema 1 → 2 이전과 백업 호환성

범용 보관함은 `schemaVersion: 2`이며 `library.groups` 아래 같은 구조의 그룹을 반복합니다. 그룹은 `{id, name, collapsed, groups: [], links: [], color?}`이고, 링크는 그룹에 직접 속합니다. 0.1.21의 선택적 `color`는 `#rrggbb` 색상 값이며 지정하지 않은 그룹은 필드 없이 기존 모양을 유지합니다. 별도 `Section` 모델은 사용하지 않습니다.

기존 schema 1의 사용자 섹션은 이름·접힘·링크를 보존한 하위 그룹으로 변환합니다. 자동 미분류 섹션은 정해진 시스템 ID로 구분하여 그 링크를 부모 그룹에 직접 둡니다. 이름만 같은 사용자 섹션은 하위 그룹으로 남습니다. 이전 JSON 백업은 변환 후 불러올 수 있습니다.

GET은 변환된 모델을 반환하지만 기존 저장 데이터를 다시 쓰지 않습니다. **schema 1이 저장된 상태에서 첫 실제 변경이 성공할 때**, 기존 catalog·되돌리기·복원 안전 사본의 저장 값을 `favmoa:schema-v1-backup:v1`에 한 번 보존하고 새 형식을 저장합니다. no-op·검증 실패·저장 실패는 이전 완료로 처리하지 않습니다. 현재 저장 키는 유지하며, 구형 undo·복원 사본을 사용할 때도 새 모델로 변환합니다. 이 내부 사본은 일반 되돌리기나 JSON 복원 전 안전 사본과 다르며 별도 파일 백업을 대신하지 않습니다.

**0.1.16의 schema 2 JSON은 0.1.15 이하에서 읽을 수 없습니다.** 구형 버전으로 자동 역변환하지 않으며 새 형식 저장소 위에 구형 코드를 덮어쓰는 다운그레이드도 지원하지 않습니다. 업데이트 전 schema 1 JSON을 보관하세요. 그 파일에는 업데이트 이후의 편집이 포함되지 않습니다.

### JSON 복원과 안전 사본

**JSON 백업 저장**으로 현재 전체 보관함을 파일에 보관한 뒤, **JSON 백업 불러오기…**에서 가져올 목록을 확인하고 **전체 목록 바꾸기**를 실행합니다. JSON에는 제목·URL·분류가 포함됩니다. 파일을 안전하게 보관하고, 다른 Chrome 프로필·컴퓨터로 옮길 때도 이 경로를 사용하세요.

실제로 목록을 교체하는 JSON 복원은 **복원 직전 목록의 안전 사본 1개**를 별도 저장합니다. 일반 편집과 일반 **되돌리기**, 패널 닫기·재열기를 거쳐도 이 사본은 유지됩니다. 다음 JSON 복원으로 목록이 바뀌면 기존 사본은 그 복원 직전 목록으로 대체됩니다. 같은 목록을 다시 불러와 변경이 없다면 기존 사본을 유지합니다.

**복원 전 목록 복구…**는 현재 전체 보관함을 안전 사본으로 교체하며, 성공하면 사본은 사용 완료됩니다. 복구 자체는 다음 내용 편집 전까지 일반 **되돌리기**로 한 번 취소할 수 있지만, 소비한 안전 사본이 다시 생기지는 않습니다. 일반 되돌리기는 **마지막 내용 편집 1회**만 취소합니다. 그룹을 접거나 펼쳐도 되돌리기 기회는 유지되고 직접 바꾼 접힘 상태도 유지합니다. 다음 내용 편집은 되돌리기 대상을 새 편집으로 교체하며, 여러 단계의 편집 이력이나 접힘 조작 되돌리기는 제공하지 않습니다. 별도 안전 사본과 외부 JSON 파일 백업은 서로 다른 보호 수단이므로 확장 삭제·프로필 변경 전에는 파일을 보관하세요.

### 데이터 크기 제한

| 대상 | 0.1.33 제한 |
|---|---|
| 전체 로컬 보관함 | 검증된 전체 catalog를 간결한 UTF-8 JSON으로 직렬화한 크기 최대 5MiB |
| 로컬 백업 파일 가져오기 | 백업의 format/version/생성 시각 등 포장 정보까지 포함한 파일 최대 6MiB. 파싱 뒤 catalog 5MiB 제한도 별도 적용 |
| 로컬 catalog 사본 | 현재 목록·일반 되돌리기·복원 전 안전 사본 최대 3개. schema 1 이전 사본은 별도로 최대 3개 catalog 값을 추가 보관할 수 있음 |
| 전체 링크·트리 항목 | 링크 10,000개, 보관함·그룹·링크 합산 20,000개 |
| 열린 탭 한 번 담기 | 사용자가 선택한 새 링크 최대 1,000개. 전체 catalog 제한도 별도로 적용 |
| 그룹 깊이 | 최상위 그룹부터 최대 32단계. 구조 안전 상한이며 권장 UI 깊이가 아님 |

1MiB는 1,048,576바이트입니다. 내보내기는 불필요한 들여쓰기 없이 간결한 JSON을 생성합니다. **5MiB는 개별 catalog의 형식상 상한이며 실제 저장 가능 용량의 보장이 아닙니다.** 현재·복구 데이터 외에 schema 1 이전 사본, 기존 Notion 트리·호환 스냅샷·제목 캐시가 Chrome 저장소 한도를 함께 사용하므로 실제 가능한 목록 크기는 더 작을 수 있습니다. 특히 첫 schema 2 저장은 이전 사본을 함께 보관할 여유가 필요합니다. 제한 초과·잘못된 파일 형식·저장 충돌·저장 공간 부족이면 오류를 알리며, 현재 목록을 먼저 JSON으로 보관한 뒤 확인하세요.

## 기존 Moa 가져오기

새 보관함에서 **기존 Moa 목록 가져오기**를 선택하면 이 확장 설치에 남아 있는 Notion 워크스페이스 트리를 찾아 schema 2 재귀 그룹으로 변환한 복사본을 만듭니다. 원본 `nfs:workspace:` 트리와 `nfs:metadata:` 제목 캐시를 유지하고, 최초 가져오기 시 호환 스냅샷도 따로 남깁니다. 같은 이전 데이터의 중복 가져오기를 방지합니다. 전용 화면 종료가 원본 데이터 삭제나 자동 이전을 뜻하지는 않습니다.

가져오기는 저장된 자료만 사용하는 **일회성 복사**입니다. Notion 즐겨찾기·제목·하위 계층을 새로 수집하거나 원본과 동기화하지 않습니다. 새 링크는 원본 페이지를 연 뒤 **이 페이지 담기**로 추가하세요. 데이터가 다른 확장 설치 ID·Chrome 프로필에 있으면 자동으로 읽을 수 없으므로 원래 설치의 JSON 백업으로 옮깁니다.

## 보류한 Google 연동

0.1.14부터 Google 연결·Drive 백업·자동 기기 간 동기화를 제공하지 않습니다. 사용자 화면에서 연결과 진단 흐름을 제거하고 `CLOUD_ENABLED=false`로 고정했습니다. 오래된 패널의 `FAVMOA_CLOUD_*` 요청도 `CLOUD_PAUSED`로 차단하며, 이 요청 때문에 토큰을 조회·삭제하거나 네트워크·저장 데이터 변경을 실행하지 않습니다. 기존 연결 메타데이터는 보존합니다.

공개 OAuth 클라이언트 ID와 범위는 [config/google-cloud.deferred.json](config/google-cloud.deferred.json)에, 기존 구현은 `src/google-drive-cloud.js`, `src/cloud-client.js`, `src/connection-view.js`에 보존합니다. 이 파일들은 현재 실행 경로와 배포 ZIP에서 제외합니다. 배포 manifest에는 `identity`, Google API 호스트 권한, `oauth2` 항목이 없으며 패키지 검사가 재도입을 차단합니다. 설정 파일에는 클라이언트 secret을 넣지 않습니다.

이전 인증 실패와 미검증 범위는 [0.1.13 검증 기록](../../docs/QA-0.1.13.md)을 참고하세요. 보존된 모듈의 모의 테스트 성공은 실계정 Google 인증·Drive 저장·다른 PC 복원의 증거가 아닙니다. 연결 재개에는 별도 구현·권한·실환경 검증이 필요합니다. 현재 백업과 이전은 JSON 파일을 사용하세요.

## 역사 기록: 0.1.18까지의 Notion 내부 화면 — 현재 배포 제외

**아래 내용은 종료된 구현의 설명이며 현행 버전의 사용 방법이 아닙니다.** 소스·합성 회귀 자료는 남겨 두지만 Notion 콘텐츠 스크립트와 내부 UI는 배포하지 않습니다. 새 버전에서는 메뉴가 생기지 않는 것이 정상입니다.

0.1.18까지는 `https://app.notion.com/*` 수신함 옆 FAVMOA 메뉴에서 원본 즐겨찾기를 선택해 그룹·섹션에 추가했습니다. 다음은 당시 동작 기록입니다.

- **목록 갱신**은 이미 관리하는 항목만 확인합니다. 새 항목을 자동 추가하거나 잠시 안 보이는 항목을 삭제하지 않습니다.
- 관리 중인 제목·이모지와 관찰한 안전한 Notion 주소는 워크스페이스별 로컬 캐시에 남습니다. 표시 캐시는 현재 접근 권한을 보장하지 않습니다.
- **현재 열린 페이지**와 하위 페이지는 Notion 사이드바에 현재 로드된 계층만 표시합니다. 원본 부모 항목을 펼친 뒤 다시 열거나 목록을 갱신하면 관찰 범위가 넓어질 수 있습니다.
- 링크 이름을 누르면 원본으로 이동합니다. 하위 페이지는 별도 즐겨찾기로 자동 추가되거나 전체 계층으로 저장되지 않습니다.
- 실제 주소나 검증된 캐시 주소를 알 수 없으면 링크 열기를 비활성화합니다. 원본 Notion에서 페이지를 열거나 즐겨찾기를 펼쳐 주소를 확인한 뒤 목록을 갱신하세요. 워크스페이스 경로를 추측하거나 ID만으로 새 주소를 만들지 않습니다.
- 페이지 이동 시 관련 그룹·섹션을 펼치고 현재 위치를 표시합니다. 사용자가 다시 접은 상태는 다음 페이지 이동 전까지 유지합니다.
- 맨 아래 **FAVMOA 관리 → 초기화**는 확인 후 기존 Notion용 관리 트리만 비웁니다. 새 범용 보관함의 복사본이나 Notion 원본 즐겨찾기는 지우지 않습니다.
- **되돌리기**는 최근 관리 작업 한 건입니다. 다른 탭의 변경·페이지 새로고침·워크스페이스 전환 후 오래된 스냅샷을 덮어쓰지 않습니다.
- 원본 Notion 노드의 구조·속성을 변경하지 않습니다. 안전한 주입 위치를 찾지 못하면 메뉴를 표시하지 않고 원본 화면을 유지합니다.
- Notion 데스크톱 앱, 공개 `notion.site`의 내부 주입, 비공개 API를 이용한 전체 계층 조회는 지원하지 않습니다.

그룹과 즐겨찾기 배치는 기존 워크스페이스 키로 로컬 저장합니다. ID를 확인할 수 없고 URL 이름(slug)만 쓴 워크스페이스는 이름 변경 시 기존 트리를 자동으로 찾지 못할 수 있습니다. ID 키와 slug 키에 이미 다른 트리가 있으면 자동 병합·삭제하지 않습니다.

## 권한과 개인정보

| 권한/범위 | 사용 목적 |
|---|---|
| `storage` | 로컬 보관함, 테마 설정, 기존 트리, 표시 캐시와 복구 데이터 |
| `sidePanel` | 어느 사이트에서도 같은 패널 열기 |
| `tabs` | 현재 주소·제목, 열린 탭 표시·기존 탭 전환, 사용자가 선택한 열린 웹 탭을 링크로 담기 |
| 선택 `bookmarks` | 선택한 Chrome 북마크 가져오기. 쓰기 작업 없음 |

0.1.19부터 웹사이트에 주입하는 콘텐츠 스크립트가 없습니다. Notion 즐겨찾기나 페이지 계층을 읽지 않습니다.

범용 보관함은 제목·URL·아이콘·서비스 종류와 사용자 분류를 로컬에 저장합니다. 이 버전은 Google 로그인이나 클라우드 전송을 실행하지 않습니다. 비공개 링크를 열려면 원본 서비스의 로그인과 접근 권한이 필요합니다. 이전 버전이 저장한 Notion 트리와 제목·이모지·주소 캐시는 삭제하지 않고 수동 가져오기용으로 보존합니다. URL도 업무 정보가 될 수 있으므로 로컬 백업을 안전하게 보관하세요.

페이지 본문·로그인 쿠키를 수집하지 않습니다. OAuth client secret을 소스에 넣지 않으며 인증 토큰은 북마크/내보내기 데이터에 포함하지 않습니다. 원격 코드·광고·분석 SDK도 없습니다. 확장 저장소 접근은 `TRUSTED_CONTEXTS`로 제한합니다.

## 문제 해결

- **사이드 패널이 안 열림:** Chrome 116 이상인지 확인하고 확장 카드를 새로고침한 뒤 도구 모음의 FAVMOA 아이콘을 다시 누르세요.
- **Notion 내부 메뉴가 안 보임:** 0.1.19부터 종료한 기능입니다. Chrome 도구 모음의 FAVMOA 아이콘을 사용하세요. 이전 메뉴가 남아 있으면 확장과 Notion 탭을 새로고침합니다.
- **다른 기기에 목록이 없음:** 원래 기기에서 **JSON 백업 저장** 후 새 기기의 **JSON 백업 불러오기…**로 옮기세요. 같은 확장 ID라도 Chrome 프로필별 로컬 데이터는 자동 복사되지 않습니다.
- **이전 Google 화면이 남음:** 0.1.33으로 확장 카드를 새로고침하고 사이드 패널을 다시 여세요. Google 기능은 보류 중이며 로컬 목록을 초기화하거나 확장을 삭제할 필요가 없습니다.
- **열린 탭 목록에 없는 페이지:** 시크릿 탭, Chrome 설정·확장 화면처럼 HTTP(S)가 아닌 주소, 현재 보관함에 이미 저장한 링크, 중복 탭은 새로 담을 대상에서 제외합니다. 탭을 열거나 주소를 바꿨다면 대화상자를 닫고 다시 여세요. 로컬 데모의 합성 목록은 실제 Chrome 탭 목록이 아닙니다.

- **그룹 색상이 다른 기기에 없음:** 색을 저장한 뒤 새 JSON 백업을 만들었는지 확인하세요. 그룹 색상은 백업에 포함되며 0.1.21 이상으로 가져와야 합니다. 그룹을 바꿔도 하위 그룹의 색은 자동으로 바뀌지 않습니다.
- **복원 이후 원래 목록이 필요함:** **백업 · 가져오기 · 설정 → 복원 전 목록 복구…**를 사용하세요. 이미 복구했거나 다음 JSON 복원으로 사본이 대체됐다면 따로 저장한 JSON 파일을 확인하세요.

- **보관함·그룹 추가·이름 변경·그룹 색상의 충돌:** **입력 유지하고 최신 목록 검토**로 작성한 값과 최신 이름·색상·경로를 확인하세요. 대상이 바뀌었다면 명시적으로 확인하고 따로 저장합니다. 삭제된 보관함·그룹·상위 그룹은 대신 만들거나 다른 위치로 바꾸지 않습니다. 남아 있는 입력을 복사한 뒤 취소하고 새 작업을 시작할 수 있습니다. 새 보관함 추가는 이전 보관함이 삭제됐어도 검토 후 저장할 수 있습니다.
- **그룹 이동·일괄 링크 이동의 충돌:** 최신 목록 검토로 이동할 하위 트리·링크와 목적지 경로의 변화를 확인하세요. 변경 사항을 명시적으로 확인한 뒤 별도로 이동합니다. 사라지거나 이동 불가능해진 목적지는 직접 다시 고르고, 출발 그룹·선택 링크·보관함이 삭제됐다면 일부만 이동하지 않습니다. 창을 닫고 최신 목록에서 작업을 새로 시작하세요. 검토만으로 이동하지 않습니다.
- **그 밖의 저장 충돌:** 삭제·초기화·백업 확인창의 복구는 아직 후속 개선 대상입니다. 창을 닫고 최신 목록을 확인한 뒤 작업창을 다시 여세요. 오래된 화면의 변경을 자동으로 덮어쓰지 않습니다.
- **되돌리기를 눌러도 그룹이 접히지 않음:** 0.1.29부터 접기·펼치기는 되돌리기 대상이 아닙니다. 마지막 내용 편집만 취소하고 직접 바꾼 접힘 상태는 유지합니다. 내용 편집 없이 접기만 했다면 되돌리기가 활성화되지 않습니다.

## 역사 기록: 기존 Notion 저장소 메시지 계약

아래는 종료된 Notion 콘텐츠 스크립트의 과거 계약입니다. 현행 확장의 사용자 진입점이 아니며, 수동 가져오기를 위한 기존 데이터 형식 설명으로 남깁니다.

content script는 다음 형태로 service worker에 요청합니다.

```js
chrome.runtime.sendMessage({
  type: "NFS_STORAGE_SET", // 읽기는 NFS_STORAGE_GET
  payload: {
    workspaceKey: "stable-workspace-key",
    workspace: { schemaVersion: 1, groups: [] },
    expectedRevision: 3
  }
});
```

`GET`은 `{ ok: true, workspace?, revision }`을 반환합니다. `SET`은 마지막으로 읽은 `revision`을 `expectedRevision`으로 보내며, 성공 시 `{ ok: true, workspace, revision }`을 반환합니다. 다른 탭이 먼저 저장했다면 `{ ok: false, error, conflict: true, workspace?, revision }`을 반환합니다. 화면은 최신 상태를 보여주며 사용자가 변경을 다시 실행할 수 있습니다. 초기화도 확인 화면을 열었을 때의 revision과 빈 트리를 `SET`으로 저장하므로, 확인 이후 추가된 다른 탭의 변경을 지우지 않습니다. 되돌리기도 동일한 CAS 검증을 거치며 이전 snapshot은 현재 탭의 메모리에만 보관합니다.

service worker는 워크스페이스별 Promise queue 안에서 revision 확인과 저장을 직렬화하므로 동시 `SET` 두 개가 같은 revision을 통과할 수 없습니다. 저장 값은 `{ revision, workspace }` envelope이며, 이전 버전의 raw workspace는 최초 `GET`에서 revision 0 envelope로 자동 이관합니다. 성공한 변경은 trusted port를 통해 workspace와 새 revision을 다른 Notion 탭에 알립니다. 이전 프로필 카탈로그는 기존 트리를 찾기 위한 읽기 호환 계층으로만 남겨 둡니다.

요청자, 메시지 필드, revision, 스키마, 중복 Favorite ID, 크기 상한을 service worker 경계에서 검증합니다.

표시 캐시는 `NFS_METADATA_GET {workspaceKey}`와 `NFS_METADATA_MERGE {workspaceKey, entries:[{pageId,title,icon,href?}]}`로 읽고 갱신하며 `{ok:true,metadata:[...]}`를 반환합니다. `href`는 하위 호환 선택 필드이며, 같은 page ID의 안전한 Notion URL만 최대 4,096자로 허용합니다. 이미 관찰한 전체 경로는 새 정보의 주소가 ID만 있는 형태이거나 생략된 경우에도 유지하며, 현재 페이지의 실제 주소를 우선합니다. `nfs:metadata:` 키에 별도 저장하고 현재 관리 ID만 허용합니다. 캐시 갱신은 트리 revision이나 되돌리기 기록을 변경하지 않으며, 저장 시 같은 워크스페이스 큐에서 제거·초기화와의 경쟁을 방지합니다. 캐시의 제목이나 링크는 원본 목록의 선택 추가 권한이나 하위 계층을 증명하지 않습니다.
