# Moa · 모아

Notion 즐겨찾기를 `그룹 → 섹션 → 즐겨찾기`로 정리하는 Chrome 확장입니다. 수신함 옆 책갈피 아이콘이 있는 `Moa`를 누르면 Notion 사이드바 안에 정리 화면이 열립니다. 업무·개인 같은 그룹 안에 프로젝트별 섹션을 만들고 각각 접고 펼칠 수 있습니다.

현재 버전은 **0.1.9**이며 **Chrome 111 이상**에서 사용할 수 있습니다. 별도 로그인은 필요 없습니다. Notion 웹앱에 로그인한 상태에서 사용하고, 정리한 내용은 워크스페이스별로 이 브라우저에 저장됩니다.

이름은 **Notion Tree → Link(0.1.6) → Moa · 모아(0.1.7)** 순서로 바뀌었습니다. Moa는 즐겨찾는 페이지를 한곳에 모아둔다는 뜻을 담았으며, 책갈피 모양의 로고를 사용합니다. 저장 키와 확장 소스 경로는 유지합니다. 같은 설치 폴더에서 업데이트하면 기존 그룹·섹션을 이어서 사용할 수 있습니다.

## 압축 해제된 확장 설치

1. 배포받은 `moa-v0.1.9.zip`의 압축을 풀고, 풀린 폴더를 계속 보관할 위치에 옮깁니다.
2. Chrome 주소창에서 `chrome://extensions`를 엽니다.
3. 오른쪽 위 **개발자 모드**를 켭니다.
4. **압축해제된 확장 프로그램을 로드합니다**를 누르고, `manifest.json`이 바로 들어 있는 폴더를 선택합니다. ZIP 파일 자체는 선택할 수 없습니다.
5. 확장 카드에 **Moa 0.1.9**가 표시되는지 확인합니다.
6. `https://app.notion.com/` 탭을 새로고침합니다.

개발 중이라면 이 저장소의 `extension/notion-favorite-sections` 폴더를 바로 선택해도 됩니다. 업데이트할 때는 **확장을 삭제하지 말고 기존 설치 폴더의 파일을 새 버전으로 교체**한 뒤, 확장 카드의 새로고침 버튼과 Notion 탭 새로고침을 차례로 누르세요. 기존 설치 경로를 유지하면 정리한 로컬 데이터를 이어서 사용할 수 있습니다.

## 재현 가능한 ZIP 패키지

매니페스트와 실제 런타임 의존성만 검사하려면 저장소 루트에서 실행합니다.

```sh
npm run check:extension-package
```

Chrome 웹스토어 제출용 ZIP을 만들려면:

```sh
npm run package:extension
```

현재 릴리스는 `0.1.9`, 다음 릴리스 예정 버전은 `0.1.10`입니다. 기본 산출물은 `artifacts/moa-v0.1.9.zip`입니다. ZIP 루트에 `manifest.json`이 바로 위치하며, `README`, `test`, `scripts` 등 실행에 필요 없는 파일은 포함하지 않습니다. 파일 순서·timestamp·권한 메타데이터를 고정하므로 같은 소스와 버전에서는 동일한 SHA-256이 생성됩니다.

ZIP 자체는 `chrome://extensions`에서 바로 선택할 수 없습니다. 실제 Chrome에서 확인할 때는 새 임시 디렉터리에 압축을 푼 뒤 **압축해제된 확장 프로그램을 로드합니다**로 그 디렉터리를 선택합니다. 기존 개발용 설치와 저장 데이터를 유지하려면 원래 `extension/notion-favorite-sections` 경로를 계속 로드하고, ZIP 해제본은 별도 Chrome 프로필에서 테스트합니다.

```sh
unzip -t artifacts/moa-v0.1.9.zip
node extension/notion-favorite-sections/scripts/package-extension.mjs --verify artifacts/moa-v0.1.9.zip
```

## 사용법

1. Notion 웹앱에서 왼쪽 사이드바와 **즐겨찾기**를 펼칩니다.
2. 수신함 옆 `Moa`를 누릅니다. 사이드바가 좁으면 책갈피 아이콘만 표시되며, 아이콘을 눌러도 같은 화면이 열립니다.
3. `+ 그룹`으로 업무·개인 같은 그룹을 만들고, 그룹 오른쪽의 `+`로 프로젝트별 섹션을 만듭니다. 입력란에서 이름을 쓰고 저장하면 됩니다.
4. `+ 즐겨찾기`를 누르고 검색한 뒤 현재 렌더된 Notion 즐겨찾기에서 관리할 항목을 하나 이상 체크합니다. 선택하지 않은 항목은 자동으로 들어오지 않습니다.
5. `그룹 / 섹션` 목적지를 선택하고 `선택한 N개 추가`를 한 번 눌러 체크한 Favorite를 해당 섹션에 함께 추가합니다.
6. 그룹 화살표로 하위 섹션과 Favorite 전체를, 섹션 화살표로 그 섹션의 Favorite만 접고 펼칩니다.
7. 항목의 메뉴에서 위치를 옮기거나 순서를 바꿀 수 있습니다. 드래그 없이 키보드로도 메뉴를 사용할 수 있습니다.
8. `목록 갱신`은 Notion에서 현재 확인할 수 있는 관리 항목을 갱신합니다. 새 항목을 자동 추가하지 않으며, 잠시 보이지 않는 항목도 Moa에서 제거하지 않습니다.
9. 상단 **현재 열린 페이지**에서 지금 보고 있는 페이지를 확인합니다. 관리 중인 즐겨찾기가 아니어도 표시되며, 즐겨찾기에 자동 추가되지는 않습니다.
10. 현재 페이지와 관리 중인 즐겨찾기 옆 화살표를 누르면 **하위 페이지**를 트리로 펼칠 수 있습니다. 페이지 이름은 실제 Notion 링크이며, 클릭하면 해당 페이지로 이동합니다. `Ctrl`/`Cmd` 클릭으로 새 탭에서도 열 수 있습니다.
11. 다른 페이지로 이동하면 해당 그룹·섹션과 하위 경로를 펼쳐 현재 위치를 보여 줍니다. 그 뒤 사용자가 접은 항목은 페이지를 다시 이동하기 전까지 접힌 상태를 유지합니다.

하위 트리는 **Notion 사이드바에 현재 로드된 계층만** 표시합니다. 더 보려면 Moa를 닫고 원본 사이드바에서 해당 페이지를 펼친 뒤 다시 열거나 `목록 갱신`을 누르세요. 표시되지 않는 하위 페이지가 없다는 뜻은 아닙니다. 현재 페이지와 하위 트리는 탐색용이며, 별도 즐겨찾기 개수나 저장 데이터에 추가되지 않습니다.

`되돌리기`는 가장 최근에 추가·이동·이름 변경·삭제·초기화한 작업 한 건을 되돌립니다. 그룹을 접고 펼치거나 `목록 갱신`을 해도 취소할 작업은 유지됩니다. 브라우저 페이지 새로고침·워크스페이스 전환·다른 탭의 변경 후에는 오래된 내용으로 덮어쓰지 않도록 취소할 수 없습니다.

`초기화`는 맨 아래 **Moa 관리**에서 실행합니다. 화면 안의 확인 단계에서 승인하면 Moa에 추가한 즐겨찾기와 사용자 그룹·섹션·배치·접힘 상태를 비웁니다. Notion 원본 즐겨찾기는 유지하며, 다시 자동으로 가져오지 않습니다. 확인 중 다른 Notion 탭에서 트리가 바뀌면 초기화를 중단하고 최신 상태를 표시합니다.

`Esc`는 입력창·선택창·행 메뉴부터 한 단계씩 닫고, 마지막에 Moa를 닫습니다. `Tab`으로 Notion의 다른 영역으로 이동하거나 바깥을 누르면 Moa가 닫히면서 이동한 위치를 계속 사용할 수 있습니다.

그룹·섹션 구조와 즐겨찾기 배치는 Notion 워크스페이스 키로 `chrome.storage.local`에 자동 저장됩니다. 별도 Google 로그인, Notion OAuth, 확장 계정 프로필은 사용하지 않습니다. 워크스페이스를 구분할 수 없는 상태에서는 영구 저장을 활성화하지 않습니다. 이전 프로필 버전에서 선택된 트리가 있으면 호환용 저장 키를 이어서 사용합니다. URL 이름(slug)으로 저장한 트리만 있는 상태에서 같은 워크스페이스의 ID를 확인하면 기존 저장 키를 계속 사용합니다. 두 키에 이미 별도 트리가 있으면 ID 쪽을 사용하며, 자동 병합·삭제하지 않습니다. URL 이름 자체가 바뀌는 경우에는 기존 트리를 자동으로 찾지 못할 수 있습니다.

## 범위와 한계

- `https://app.notion.com/*`에서만 실행합니다. Notion 데스크톱 앱, 공개 `notion.site`, 레거시 도메인은 지원하지 않습니다.
- Moa의 밝고 어두운 배경은 Notion 사이드바의 현재 색상을 따릅니다. 사이드바를 좁히면 상단 Moa는 책갈피 아이콘으로 표시됩니다.
- **현재 Notion 사이드바 DOM에 렌더된 Favorites만 선택 후보**입니다. Notion이 일부 Favorite만 표시하면 Library 설정에서 사이드바 표시 수를 늘려야 합니다.
- `+ 즐겨찾기`에서 체크하고 목적지를 선택한 뒤 `선택한 N개 추가`를 실행한 항목만 Moa에 들어옵니다. 원본 목록에서 보이지 않는다는 이유만으로 삭제·숨김 처리하지 않습니다. Moa에서 더 이상 필요 없는 항목은 행 메뉴의 `Moa에서 제거`를 사용합니다.
- `목록 갱신`은 관리 항목의 상태만 갱신합니다. 새로 발견한 Favorite를 자동으로 추가하지 않습니다.
- 관리 중인 즐겨찾기는 마지막으로 확인한 제목·이모지 아이콘을 로컬에 보관합니다. 원본 목록이 접히거나 화면에서 사라져도 이름과 페이지 이동 링크를 유지하며, 다시 확인한 이름으로 갱신합니다. 저장된 제목은 마지막 관찰값이며 현재 접근 권한이나 즐겨찾기 상태를 보증하지 않습니다.
- 현재 페이지와 하위 트리는 현재 워크스페이스의 렌더된 사이드바에서 확인한 관계만 사용합니다. 페이지 본문이나 비공개 API로 전체 계층을 수집하지 않으며, 즐겨찾기로 직접 추가하지 않은 페이지의 제목·하위 계층은 저장하지 않습니다. 접힌 원본 목록, 아직 로드되지 않은 페이지, 계층을 안전하게 확인할 수 없는 구조는 표시 범위에 포함되지 않습니다.
- 트리 맨 아래 `초기화`는 Moa 로컬 데이터만 비웁니다. 현재 화면의 Favorites를 자동 재수입하지 않습니다.
- 숨겨진 전체 목록을 얻기 위해 비공개 Notion API, 세션 쿠키, 로그인 토큰을 사용하지 않습니다.
- Notion의 상단 탐색 DOM이 바뀌어 안전한 위치를 확인하지 못하면 `Moa` 버튼을 주입하지 않는 **fail-open** 방식으로 동작합니다.
- Favorites 탐지가 실패해도 원본은 항상 그대로 보이며, 저장된 Moa를 열 수 있는 경우 선택 추가와 목록 갱신만 비활성화됩니다.
- Notion이 소유한 원본 DOM 노드는 이동·감싸기·숨김 처리하지 않으며 부모·자식 구조, 접근성 속성, 선택 상태, 인라인 스타일을 변경하지 않습니다. 확장 소유 trigger host와 Moa view host만 안전하게 형제로 추가했다가 제거합니다.
- 이 정리 구조는 로컬 전용이며 다른 사용자나 기기로 공유·동기화하지 않습니다.

## 문제가 생겼을 때

- **Moa가 안 보여요:** `app.notion.com`인지 확인하고 사이드바를 펼치세요. 확장 관리 화면에서 켜져 있는지 확인한 뒤 Notion 탭을 새로고침합니다. Notion 화면 구조가 호환되지 않으면 원본 화면을 보호하기 위해 Moa가 나타나지 않을 수 있습니다.
- **추가할 즐겨찾기가 없어요:** Moa를 닫고 원본 즐겨찾기를 펼친 뒤 다시 열어 보세요. Notion이 목록 일부만 표시하는 경우 표시 범위를 늘려야 합니다.
- **제목 대신 페이지 ID가 나와요:** 0.1.8까지는 제목을 저장하지 않았습니다. 업데이트 후 Moa를 닫고 원본 즐겨찾기를 펼친 다음 다시 열거나 `목록 갱신`을 한 번 실행하세요. 원본에서 확인한 제목을 복구해 보관합니다. 제목을 아직 확인하지 못한 항목도 유효한 페이지 ID가 있으면 클릭해서 열 수 있습니다. 그룹·섹션을 초기화할 필요는 없습니다.
- **하위 페이지가 안 보여요:** 원본 Notion 사이드바에서 부모 페이지를 먼저 펼치고 Moa를 다시 열어 보세요. 하위 트리는 로드된 계층만 사용하므로, 표시되지 않는다는 이유만으로 하위 페이지가 없는 것은 아닙니다.
- **변경 내용을 저장할 수 없다고 나와요:** 다른 탭에서 같은 트리를 수정했는지 확인하세요. 새로 표시된 내용에서 다시 작업하면 됩니다. 문제를 해결하려고 초기화할 필요는 없습니다.
- **다른 브라우저에서는 트리가 없어요:** Moa는 브라우저별 로컬 저장을 사용합니다. 다른 Chrome 프로필·기기에는 자동으로 복사되지 않습니다.

## 개인정보와 권한

매니페스트의 명시적 권한은 `storage` 하나뿐입니다. 저장하는 정보는 다음으로 제한됩니다.

- 그룹·섹션의 이름, 색상/이모지, 순서, 접힘 상태
- 정규화된 Notion page ID와 섹션 내 순서, dormant 상태와 갱신 시각
- 명시적으로 관리 중인 즐겨찾기의 마지막 확인 제목(최대 300자)과 이모지 아이콘. 기존 트리와 분리된 워크스페이스별 표시 캐시에 보관하며, 항목 제거·초기화 시 해당 저장 캐시도 정리합니다.

페이지 URL·본문, 쿠키, 인증 토큰은 저장하지 않습니다. 링크는 확인한 페이지 ID로 재구성할 수 있습니다. 외부 서버, 네트워크 요청, 분석 SDK, 광고, 원격 코드, 외부 라이브러리가 없습니다. content script가 저장소를 직접 사용하지 못하도록 `chrome.storage.local` 접근 수준을 `TRUSTED_CONTEXTS`로 제한하고, 검증된 service worker 메시지를 통해서만 읽고 씁니다. 표시 캐시에 실패해도 기존 그룹·섹션 저장 데이터는 유지합니다.

## Moa 로고 자산

청록색 책갈피와 두 페이지를 작은 화면에서도 읽히는 벡터 심벌로 정리했습니다. 아래 자산과 생성 코드가 이 저장소에 포함됩니다.

- `src/moa-brand.js`: 메뉴 SVG와 배포 아이콘이 함께 쓰는 도형·색상 원본
- `icons/moa-mark.svg`: 팝업용 심벌
- `icons/moa-{16,32,48,128}.png`: Chrome 아이콘. 밝거나 어두운 툴바에서 읽히도록 아이보리 배경 포함
- Notion 다크 테마에서는 메뉴 심벌의 바깥색이 밝은 민트로 전환됩니다.

아이콘은 배포에 포함되어 있으므로 사용자는 생성 도구를 설치할 필요가 없습니다. 개발 중 다시 만들 때만 `sharp` 0.35.4를 준비한 뒤 저장소 루트에서 `npm run build:extension-icons`를 실행합니다. 이미 설치된 모듈을 이용하려면 `MOA_SHARP_MODULE`에 해당 `sharp` 디렉터리의 절대 경로를 지정할 수 있습니다. `npm test`는 생성된 SVG의 원본 일치와 PNG 실제 크기를 검사합니다.

상표·도메인·스토어 이름 가용성은 검증하지 않았으며 웹스토어 등록도 진행하지 않았습니다.

## 저장소 메시지 계약

content script는 다음 형태로 service worker에 요청합니다.

```js
chrome.runtime.sendMessage({
  type: "NFS_STORAGE_SET", // 읽기는 NFS_STORAGE_GET
  payload: {
    workspaceKey: "stable-workspace-key",
    workspace: { schemaVersion: 1, groups: [] },
    expectedRevision: 3
  }
});
```

`GET`은 `{ ok: true, workspace?, revision }`을 반환합니다. `SET`은 마지막으로 읽은 `revision`을 `expectedRevision`으로 보내며, 성공 시 `{ ok: true, workspace, revision }`을 반환합니다. 다른 탭이 먼저 저장했다면 `{ ok: false, error, conflict: true, workspace?, revision }`을 반환합니다. 화면은 최신 상태를 보여주며 사용자가 변경을 다시 실행할 수 있습니다. 초기화도 확인 화면을 열었을 때의 revision과 빈 트리를 `SET`으로 저장하므로, 확인 이후 추가된 다른 탭의 변경을 지우지 않습니다. 되돌리기도 동일한 CAS 검증을 거치며 이전 snapshot은 현재 탭의 메모리에만 보관합니다.

service worker는 워크스페이스별 Promise queue 안에서 revision 확인과 저장을 직렬화하므로 동시 `SET` 두 개가 같은 revision을 통과할 수 없습니다. 저장 값은 `{ revision, workspace }` envelope이며, 이전 버전의 raw workspace는 최초 `GET`에서 revision 0 envelope로 자동 이관합니다. 성공한 변경은 trusted port를 통해 workspace와 새 revision을 다른 Notion 탭에 알립니다. 이전 프로필 카탈로그는 기존 트리를 찾기 위한 읽기 호환 계층으로만 남겨 둡니다.

요청자, 메시지 필드, revision, 스키마, 중복 Favorite ID, 크기 상한을 service worker 경계에서 검증합니다.

표시 캐시는 `NFS_METADATA_GET {workspaceKey}`와 `NFS_METADATA_MERGE {workspaceKey, entries:[{pageId,title,icon}]}`로 읽고 갱신하며 `{ok:true,metadata:[...]}`를 반환합니다. `nfs:metadata:` 키에 별도 저장하고 현재 관리 ID만 허용합니다. 캐시 갱신은 트리 revision이나 되돌리기 기록을 변경하지 않으며, 저장 시 같은 워크스페이스 큐에서 제거·초기화와의 경쟁을 방지합니다. 캐시의 제목이나 링크는 원본 목록의 선택 추가 권한이나 하위 계층을 증명하지 않습니다.

## 테스트

저장소 메시지와 데이터 검증 계약만 빠르게 실행하려면:

```sh
node --test extension/notion-favorite-sections/test/background-contract.test.mjs
```

저장소 루트의 전체 테스트를 실행하려면:

```sh
npm test
```

브라우저 통합 검사는 로컬 서버(`npm start`)에서 `test/browser-suite.html`을 열고 **전체 검사 실행**으로 8개 시나리오를 실행합니다. `npm test`는 Node 검사이며 브라우저 검사는 별도로 실행해야 합니다.

- `test/browser-smoke-fixture.html`: 저장소 연결 실패 시 선택 추가·초기화 비활성화, 불투명 내부 화면의 원본 차폐와 닫은 뒤 원본 복원
- `test/browser-interaction-fixture.html`: 워크스페이스 자동 로드, Moa 내부 화면 열기, content surface 전체 차폐·복원, Favorite 명시 추가, 그룹·섹션 생성, Favorite 이동, 2단계 접기, 활성 페이지 경로 펼치기, Moa 초기화
- `test/browser-live-demo.html`: 실제 view·adapter·model로 수신함 옆 Moa, 불투명 내부 화면, 검색·복수 선택·목적지 일괄 추가, 관리 항목 목록 갱신, 현재 페이지와 하위 트리 탐색을 시연하는 로컬 화면. 이 데모에서만 링크를 누르면 외부 이동 대신 모의 현재 페이지가 바뀝니다.
- `test/browser-view-usability-fixture.html`: 실제 DOM의 초점, 접기, 입력/확인, 저장 중 조작, 키보드 이동, 메뉴 위치와 복구 검사
- `test/browser-layout-fixture.html`: 220·240px, 긴 한국어 이름, 40개 항목, 200% 크기와 다크 화면의 선택기·트리·마지막 행 메뉴 검사
- `test/browser-icon-fixture.html`: 실제 Notion의 접근성 설명과 이모지 구조를 재현해 설명 문구 유출·아이콘 중복·복합 이모지·잘못된 이미지 경로와 화살표 대체 표시 검사
- `test/browser-page-navigation-fixture.html`: 현재 페이지 카드, 즐겨찾기 아래 다단계 링크, 활성 경로 펼치기, 수동 접힘 유지, 저장 데이터 불변, 안전하지 않은 링크 차단, 워크스페이스 전환과 현재 페이지 스크롤 우선순위 검사
- `test/browser-title-cache-fixture.html`: 실제 content→view에서 원본 목록 숨김, 새 컨트롤러의 제목 복원, 이름 변경 반영, 캐시 링크 이동과 그룹 배치 보존 검사

수동 확인 시에는 확장 관리 화면에 매니페스트 오류가 없는지, 수신함 옆에 Moa가 한 번만 나타나는지, 내부 Moa 화면이 sidebar content surface 전체를 불투명하게 채우는지, 화면을 닫으면 원래 Notion tabpanel과 Favorites가 즉시 다시 조작되는지 확인합니다. 닫았다 열어도 그룹/섹션 접힘 상태가 유지되고, 모든 과정에서 Notion 소유 DOM 노드의 구조와 속성이 그대로인지도 함께 확인합니다.
