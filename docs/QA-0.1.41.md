# FAVMOA 0.1.41 · 가져오기 창에서 새 그룹에 담기

검증일: 2026-09-25 KST. [개선 큐](USABILITY-IMPROVEMENT-QUEUE.md) 7번을 구현·검증해 **등록된 후보 1~7을 마무리**했다. 다단계 Undo·휴지통·개별 후보 검토 페이지네이션을 별도로 확장하거나 실제 사용자 성공률을 주장하지 않는다.

## 재현과 설계

실제 sidepanel 소스의 모의 DOM 핸들러에서 선택·검색을 유지하며 새 그룹 이름을 입력할 버튼이 없어 RED가 발생했다. UI 초안을 추가한 뒤 기존 그룹 추가 명령으로 실행되는 RED를 확인하고 원자적 모델 명령으로 연결했다. 모델도 지원하지 않는 명령의 RED부터 구현했고 누락된 부모를 루트로 대체하지 않도록 별도 RED→GREEN을 수행했다. 삭제된 부모를 최신 선택기에 무효 상태로 반영하는 회귀도 먼저 재현했다. TDD 스킬에 따라 작은 계약부터 순서대로 확장하고 별도 에이전트가 경계를 검토했다.

그룹 생성과 링크 담기를 두 번 저장하면 가져오기를 취소하거나 실패했을 때 빈 그룹이 남고 Undo도 나뉠 수 있다. 따라서 창 안의 이름·위치는 **아직 저장하지 않은 초안**이며 마지막 ‘새 그룹에 N개 담기’에서 함께 저장한다.

## 구현 계약

- 탭·북마크 공용 창의 ‘새 그룹에 담기’로 이름/위치 초안을 연다. 기존 그룹 모드로 돌아갔다가 다시 열어도 이름·위치를 유지하며 후보 검색·숨은 선택·전체 결과 선택을 보존한다. 전체 창 취소에는 저장이 없다.
- 이름은 1~80자, 제어 문자 금지. 최상위 또는 깊이31 이하 부모를 전체 경로로 선택해 새 그룹이32단계를 넘지 않게 한다. 같은 이름의 그룹은 ID로 구별한다. 저장 예정 경로와 그룹·링크가 함께 저장된다는 설명을 표시한다.
- `addLinksToNewGroup`은 루트에 명시적 null, 부모에 유효 ID를 요구한다. 모델이 새 ID를 생성하고 기존 일괄 링크 검증·중복 방지·1,000개·catalog 10,000링크/20,000노드/5MiB 검증을 재사용한다. 저장 키·schema·서비스 프로토콜·권한을 변경하지 않는다.
- 그룹·선택 링크·상위 자동 펼침은 단일 서비스 쓰기/revision/Undo다. 성공하면 검색을 해제하고 생성된 실제 ID의 그룹을 표시한다. 한 번 Undo로 생성 그룹·링크·자동 펼침을 함께 복구하며 이후 명시적 접힘 보호 계약을 유지한다.
- 충돌 뒤 명시적 최신 검토는 이름/검색/남은 선택을 유지한다. 최신 전체 부모 경로를 갱신하고 삭제·깊이 초과 부모는 무효 선택으로 남긴다. 다른 보관함을 고르면 동일 그룹 ID가 있거나 이전 위치가 최상위였어도 새 위치를 직접 고른다. 자동으로 루트/미분류를 선택하지 않는다.
- 검토만으로 쓰지 않고 저장 실패 시 초안을 보존한다. 로딩·검토·저장 중 조작과 취소/대체된 이전 버튼의 늦은 동작을 방어한다. 숨겨진 새 그룹 필드는 disabled/required 상태를 함께 바꿔 기존 그룹 저장을 방해하지 않는다.
