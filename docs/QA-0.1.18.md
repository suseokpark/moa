# FAVMOA 0.1.18 — Notion 원본 주소 보존과 공통 URL 검증

검증일: 2026-09-23 KST · 다음 패치: 0.1.19

## 수정 내용

0.1.17의 현재 페이지 카드 수정에 이어, 기존 즐겨찾기와 하위 탐색 트리의 주소 손실을 수정했다.

- `notion-url.js`에서 Notion URL 파싱·동일 페이지 검증·관측 URL 선택을 공통 처리한다. 어댑터, 화면, 저장 계약에서 같은 규칙을 사용한다.
- 워크스페이스 경로, 밑줄 제목 구분자, 인코딩된 제목/ID, UUID, 쿼리·해시를 보존한다.
- 실제 현재 주소는 짧은 원본 행 주소보다 우선한다. 중복 탐색 노드와 즐겨찾기 병합에서도 알려진 전체 경로를 잃지 않는다. 계층과 제목 병합 규칙은 유지한다.
- 워크스페이스별 메타데이터에 선택적 `href`를 저장한다. 기존 `{pageId,title,icon}` 레코드도 읽으며, 필드가 없는 갱신으로 알려진 주소를 지우지 않는다.
- 저장 URL은 최대 4,096자, HTTPS `app.notion.com`, 동일 페이지 ID로 한정한다. 잘못된 포트·출처·인증정보·인코딩된 경로 구분자·위험한 프로토콜을 거부한다.
- 주소가 전혀 없는 과거 항목은 ID만으로 링크를 생성하지 않고 **주소 확인 필요**로 표시한다. 이동·삭제 등 정리 기능과 원래 참조는 유지한다.
- Notion에서 해당 페이지를 열거나 원본 즐겨찾기 목록을 펼친 뒤 목록 갱신하면, 확인된 URL을 기록해 이후에도 사용한다. 다른 페이지의 워크스페이스 이름으로 주소를 추측하지 않는다.

트리 스키마, 저장 키, 그룹·섹션·배치, 확장 ID와 권한은 유지한다. 메타데이터만 선택적 URL 필드를 확장했다.
Google 연결은 계속 보류하며, 범용 사이드 패널의 탭 재사용 로직과 과거 데이터의 일괄 URL 추측/변환은 이번 범위가 아니다.

- 중복 관측 URL/탐색 트리가 먼저 들어온 짧은 주소를 고집하는 사례도 2개 실패 테스트로 재현한 뒤 수정했다.
- 메타데이터 URL 저장 거부, 누락 갱신, 재시작 주소 손실, 현재 페이지와 오래된 원본 행의 충돌을 재현한 뒤 저장·복원 경계를 수정했다.
- 최종 전체 Node 검사 **385/385**. 이전 0.1.17의 371개에 회귀 검사 14개를 추가했다.
- 서로 다른 워크스페이스 이름·한글·밑줄·인코딩·UUID·쿼리·해시 **84개 조합**에서 어댑터와 화면 정규화가 전체 주소를 동일하게 보존했다. 이는 합성 코드 검사이며 84개 실제 페이지 접속 검사가 아니다.
- 메타데이터/콘텐츠 컨트롤러 검사 **47/47**: 워크스페이스 및 관리 대상 격리, 기존 레코드 호환, 삭제/초기화 정리, 트리 revision 불변 포함.
- localhost 페이지 탐색 검사 **15/15**, 제목·주소 캐시 검사 **5/5**.
- localhost 전체 브라우저 검사 **8/8**. 최초 실행은 주소 미확인 항목에도 생성한 링크가 있어야 한다는 구형 테스트 때문에 **7/8**이었다. 새 정책인 비활성 표시·복구 안내·정리 기능 유지로 기대값을 수정한 후 전체를 다시 실행했다. 이를 0.1.16의 과거 메뉴 간헐 실패 해결로 간주하지 않는다.
- 임시 디버그 코드 없음. `git diff --check`, 관련 소스 구문 검사와 패키지 검사 통과.

## 확인 범위와 사용 안내

실제 확인은 열린 다른 워크스페이스의 현재 페이지 링크에 한정된다. 사용자의 저장된 모든 링크, 계정별 권한, 모든 Notion 호스트에서의 동작을 보장하는 결과는 아니다. 저장·접기·재시작·특수 주소 복원은 합성 테스트로 검증했다.

업데이트 후 다른 Notion 탭도 새로고침해야 새 콘텐츠 스크립트를 사용한다. **주소 확인 필요**가 표시되면 원본 페이지를 한 번 열거나 원본 즐겨찾기 목록을 펼쳐 갱신한다. 목록 초기화나 확장 재설치는 필요하지 않다.
