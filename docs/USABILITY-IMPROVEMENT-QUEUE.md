# FAVMOA 사용성 개선 작업 큐

기준: [0.1.28 합성 페르소나 감사](PERSONA-AUDIT-2026-09-24.md). 실제 사용자 테스트가 아닌 합성 시나리오와 별도 예시 화면에서 나온 개선 후보다. 2026-09-26 09:00 KST까지 우선순위대로 진행하며, 그 시각 이후 새 변경은 시작하지 않는다. 후보를 다 처리하면 불필요한 변경을 추가하지 않는다.

## 전달 규칙

- AGENTS.md를 따르고 기존 사용자 변경을 보존한다. 완료한 작은 단위마다 회귀 테스트 → 전체 테스트 → 패키지 검사 → 관련 파일 커밋 → 원격 푸시 → 원격 HEAD 확인을 수행한다.
- 릴리스마다 patch 버전을 올리고 ZIP을 생성·검증한다. 사용자 데이터, 서명 키, 생성된 로컬 산출물은 공개 저장소에 올리지 않는다.
- 데이터는 합성 fixture/별도 localhost 예시만 사용한다. 브라우저 설치 확인과 실제 확장 데이터 동작 검증을 혼동하지 않는다.
- OAuth, 권한 추가, 클라우드 동기화, Notion 내부 UI, 웹스토어 게시는 범위 밖이다.
- 0.1.28 원본 감사 기록은 보존한다. 수정된 계약의 회귀 결과는 새 경로·버전으로 기록한다. 300/300 계약 통과를 실제 사용자 성공률로 부르지 않는다.
- 2026-09-25 Chrome 확장 관리 URL의 자동 접근이 브라우저 보안 정책으로 차단됐다. 다른 표면/CDP로 우회하지 않는다. 패키지·기존 설치 폴더 업데이트와 실제 Chrome 새로고침 확인을 구분하며, 새로고침은 사용자에게 안내한다.

## 다음 실행에 필요한 설계 메모

### 2. 충돌 복구

**공용 가져오기 창은 0.1.30에서 완료됐다. 반복 구현하지 않는다.** `sidepanel.js`의 `requireResult`는 충돌의 최신 catalog를 채택하지만 초기 대화상자 revision은 그대로였으며, 모의 DOM에서 `[7, 7]` 요청과 화면 state 8을 재현했다. 서비스 충돌 차단은 정상이고 picker의 복구 경로를 추가했다.

`chooseCandidateLinks`는 충돌 후 저장을 잠그고 **선택 유지하고 최신 목록 검토**를 제공한다. 검토는 `platform.load()`만 호출한다. 자동 저장·자동 revision 대체·후보 재조회·권한 재요청은 하지 않는다. 사용자가 최신 대상과 변경된 선택을 확인한 뒤 별도 저장을 눌러야 한다.

- 최초 보관함 ID를 고정한다. 삭제된 보관함/그룹을 첫 항목이나 미분류로 몰래 대체하지 않는다.
- 최신 이름/경로를 표시하고, 이미 저장된 URL만 선택에서 제외하며 제외/유지 개수를 알린다. 새 항목은 자동 선택하지 않는다.
- `needsReview`를 실제 submit 함수에서도 검사한다. `setDialogBusy(false)`의 이전 disabled 복원 이후에도 잠금 상태를 다시 계산한다.
- 체크박스 변경이 충돌 안내를 지우지 않게 한다. 검토 응답은 대화상자 세대 및 revision을 검사하여 취소 후 도착하거나 더 오래된 응답을 무시한다.
- 검토 후 또 바뀌면 다시 충돌 안내로 돌아간다. 일반 저장 실패는 기존 선택을 보존하고 재시도할 수 있다.
- `test-support/candidate-picker-fixture.mjs`의 load seam과 `sidepanel-candidate-conflict.test.mjs` 38개 회귀로 읽기/저장 횟수, 선택·검색 유지, 삭제 대상, 중복 제거, 재충돌, 취소, 읽기 실패를 검증했다.
- `qa/persona-audit/capture.mjs` variant 9는 새 명시적 검토 흐름을 실행한다. 해결된 `conflict-reopen` 기록만 제거했다.

**수동 링크 입력·수정·단일 링크 이동도 0.1.31에서 완료됐다.** `linkDialog`가 세 모드를 처리하며 `moveDialog`는 move 모드 진입점이다. 원래 보관함 ID를 고정하고 최신 이름·주소·전체 경로를 비교한다. 변경된 기존 링크는 명시적 확인 체크 후 별도 저장, 삭제된 기존 링크는 재생성/대체하지 않는다. 수동 추가의 삭제된 보관함/그룹만 직접 재선택할 수 있다. 같은 이름의 상위 그룹 사이 이동도 전체 경로 ID로 판별한다. 공용 form의 `afterSubmit` 후처리가 busy 복원 이후에도 잠금을 유지한다. 당시 남겨둔 검색 해제/결과 펼침은 3번 과제로 0.1.37에서 완료했다.

**이름·색상도 0.1.32에서 완료됐다.** `nameDialog`와 `groupColorDialog`는 `metadataDialog`를 사용한다. 원래 대상 고정, 최신 이름·색상·전체 경로 비교, 명시적 확인 후 별도 저장, 삭제된 대상/상위 그룹과 최대 깊이 보호가 포함된다. 전역 작업인 새 보관함 추가는 원래 보관함이 없어져도 검토 후 진행할 수 있다. 색상 검증 오류 초점도 재활성화 후 HEX 입력으로 돌아온다. 공용 full-source fixture의 실제 색상 편집기를 사용한 68개 회귀로 검증했다.

**그룹·일괄 링크 이동도 0.1.33에서 완료됐다.** `moveGroupDialog`/`bulkMoveDialog`는 공용 `treeMoveDialog`를 사용한다. 원래 보관함·그룹·선택 링크 ID를 고정하고 최신 하위 내용/제목/주소/전체 경로와 목적지를 비교한다. 변경됐다면 확인 체크 후 별도로 이동하며, 삭제된 출발지를 다른 ID로 대체하거나 남은 일부만 이동하지 않는다. 삭제/자손 순환/최대 깊이로 무효가 된 목적지는 선택값을 보존한 채 차단하고 직접 재선택한다. 최신 이동 수와 같은 위치의 no-op를 확인한다. 목록 인덱스는 검토한 catalog마다 한 번 계산한다. 신규 40개 회귀로 읽기/쓰기 분리와 비동기·성능 경계를 검증했다.

**링크 제거·그룹 제거·보관함 초기화는 0.1.34에서 완료됐다.** `destructiveDialog`가 원래 보관함/대상 ID를 고정한다. 최신 링크 제목·주소·경로, 그룹 제거 후 보존 위치와 하위 내용, 초기화할 그룹·링크 수와 전체 내용을 읽어 표시한다. 충돌 후에는 변경 유무와 무관하게 명시적 확인 체크 후 별도로 실행해야 한다. 삭제된 원래 대상/보관함은 대체하지 않으며 긴 영향 목록은 native details로 펼쳐 확인한다. 신규 54개 회귀로 동작/비동기/취소/초점/최신 범위만 적용을 검증했다.

**JSON 복원·복원 전 안전 사본 복구는 0.1.35에서 완료됐다.** `restoreDialog`가 두 경로를 처리한다. JSON 파일 내용은 창을 연 뒤 고정하고 충돌 시 최신 현재 목록·교체될 안전 사본을 읽어 확인한다. 복원 전 목록 복구는 최초 실행부터 실제 안전 사본 미리보기와 확인 체크를 요구한다. 검토마다 체크를 해제하며 사본이 없거나 손상되면 현재 목록/다른 목록으로 대체하지 않는다.

- `platform.previewBackup()` / `FAVMOA_PREVIEW_BACKUP`이 신뢰된 sidepanel에 현재 revision·catalog와 실제 `restoreCatalog` 또는 null을 같은 서비스 큐에서 읽기 전용 반환한다. GET/CONFLICT는 기존 compact 응답을 유지한다. 데모 미리보기는 변경 알림도 보내지 않는다.
- 기존 안전 사본의 교체/소비는 revision을 올린다. 검토한 revision으로 별도 실행하고 재충돌은 다시 잠근다. 최초 JSON 확인창은 기존 명시적 전체 교체 계약을 유지하며, 선택적으로 최신 미리보기를 할 수 있다. 충돌 후에는 미리보기·체크를 건너뛸 수 없다.
- 신규 59개 회귀(서비스/플랫폼 23 + UI 기능 12 + 독립 비동기 경계 24)로 데이터 변경 없는 미리보기, 고정 파일, 최신 대상, 사본 교체/소비, null/손상, 늦은 응답, 취소, 재시도를 검증했다.

**기존 Moa 가져오기도 0.1.36에서 완료됐다.** `legacyImportDialog`가 마지막 `confirmDialog` 호출을 대체한다. 충돌 뒤 반복 실행을 막고 `platform.load()`로 최신 **대상 catalog**만 검토한다. 원본을 읽거나 쓰지 않는 검토 뒤 확인 체크와 별도 가져오기를 요구하며, 재검토/재충돌마다 체크를 해제한다. 초기 명시적 가져오기는 기존 동작을 유지한다.

- 원본 nfs 목록은 실제 가져오기 실행 때 읽는다. 대상 검토는 원본 내용·가져올 개수의 미리보기가 아니라는 문구를 표시한다. 원본 변경은 catalog revision과 별개이며 UI가 원본 스냅샷을 확인했다고 주장하지 않는다.
- 현재 catalog에 이전 기록이 남은 워크스페이스를 중복 복사하거나 자동 동기화하지 않는다. Undo/JSON 복원으로 이전 이력이 달라질 수 있어 영구적인 중복 방지라고 표현하지 않는다. 성공/취소/저장 실패에서 원본과 기존 보관함을 보존한다.
- 0개 가져오기 + warnings를 빈 목록으로 오안내하던 경로도 수정했다. 결과를 확인 필요로 표시하되 원본별 내부 경고 문자열을 그대로 출력하지 않는다. 신규 30개(실제 서비스 연결 기능 11 + 독립 비동기/실패 경계 19)로 검증했다.
- 이 완료는 큐에서 지정한 대화상자들의 복구 계약이며 모든 종류의 외부 충돌이나 실제 Chrome 사용 검증을 뜻하지 않는다. 서비스/모델/권한은 바꾸지 않았다.

### 3. 수동 추가·이동 결과 표시 — 0.1.37 완료

- 수동 추가·단일 링크 이동·그룹 메뉴 이동·드래그 콜백의 검색/접힘 숨김을 RED 재현했다. 모델 `addLink`/`moveLink`/`moveGroup`에 선택적 `revealTarget`을 추가해 내용 변경과 목적지 조상 펼침을 단일 저장·revision·Undo로 처리한다. 그룹 자체/하위의 접힘은 유지한다.
- `revealTreeResult`는 성공한 실제 결과를 찾아 검색과 화면상 접힘 억제를 해제한다. 대화상자 종료와 보류 렌더를 고려한 결과 초점·스크롤을 처리한다. 이후 다른 보관함/새 대화상자(열었다 취소한 경우 포함)/열린 테마의 초점을 빼앗지 않는다.
- 드래그 저장 전 보관함·대화상자 세대를 캡처해 응답 대기 중 사용자가 새 맥락을 선택한 경우 결과 표시만 생략한다. 완료된 이동은 보존한다. 동일 위치 이동·실패·취소·충돌 검토에서 불필요한 검색 해제/자동 펼침이 없다.
- 신규 58개(모델/서비스28 + UI 기능8 + 독립 경계22)로 한 번 저장·Undo·후속 명시 폴딩 보존·실패/취소/no-op·비동기 초점 보호를 검증했다. 드래그 콜백 시험은 실제 네이티브 포인터 검증을 뜻하지 않는다. 기존 일괄 담기/이동과 일반 링크 수정 계약은 유지한다.

### 4. 보관함 전환 시 검색 정리 — 0.1.38 완료

- 실제 선택기 핸들러의 검색 잔존을 RED 재현했다. 다른 유효 보관함을 선택하면 검색·임시 보기 상태를 비우고 다중 선택을 즉시 종료한다. 같은 보관함이나 없는/빈/삭제된 값은 현재 맥락과 정상 예약 작업을 보존한다.
- 보기 전환에 저장·revision·Undo 변경이 없다. 보류 렌더 중에도 이전 선택을 종료하고 보류된 결과 초점을 취소한다. 드래그 저장 전 보기 세대를 캡처해 A→B→A 왕복 뒤 늦은 결과 표시가 새 검색/초점을 덮지 않도록 한다. 이동 저장 자체는 보존한다.
- 신규16개(기본 정책·실제 서비스8 + 독립 비동기8)와 기존 회귀를 통과했다. 명시적 사용자 전환만 수정하고 프로그램 내부 보관함 변경·저장된 접힘·기존 충돌 복구 계약은 유지한다. 감사 variant5를 회귀 기대값으로 전환했고 기존 감사 원장은 그대로 보존한다.

### 5. 순서 독립 다중 키워드 검색 — 다음 실행

- `sidepanel.js`의 `projectGroup`은 현재 연속 부분 문자열을 제목/주소/그룹 이름별로 검사한다. 감사 `find-organize.mjs` variant1의 역순 단어 조합이 결과 0개인 사례를 먼저 RED 재현한다. 원본 감사 기록은 수정하지 않는다.
- 우선 메인 보관함 트리 검색을 대상으로, 단어 순서·공백·대소문자·한글과 제목/주소/상위 그룹 경로에 흩어진 단어를 시험한다. 모든 단어 일치의 범위를 명시하고 형제 그룹 간 단어가 섞여 잘못 매칭되지 않게 한다. 후보 선택창 검색 확대는 별도 재현 없이 묶지 않는다.
- 기존 그룹 이름으로 하위 링크 찾기·결과 상위 경로 표시·검색 중 폴딩 비활성화·빈 검색·일괄 선택·보관함 전환 계약을 유지한다. 경로/문자열을 링크마다 불필요하게 반복 계산하지 않는지 대량 합성 데이터로 확인한다. 검증된 작은 범위로 결정하고 6번 대량 후보 선택 반복 줄이기로 이어간다.
