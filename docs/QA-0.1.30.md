# FAVMOA 0.1.30 · 선택을 보존하는 가져오기 충돌 복구

검증일: 2026-09-25 KST. [개선 큐](USABILITY-IMPROVEMENT-QUEUE.md) 2번의 첫 단위로 열린 탭·북마크 공용 가져오기 창만 개선한다. 일반 이름 변경·링크 수정·이동·백업 확인창은 이번 완료 범위가 아니다.

## 재현과 원인

배포되는 `sidepanel.js`를 합성 DOM과 저장소 fixture에서 실행했다. revision 7에 연 가져오기 창에서 링크를 선택하고 revision 8 충돌 응답을 받았다. 화면은 8을 채택했지만 재제출 요청은 `[7, 7]`이었다. 선택은 유지됐으나 같은 창에서 복구할 수 없었다.

원인은 대화상자 closure의 초기 revision이 고정되고 최신 목록을 명시적으로 검토하는 경로가 없다는 점이다. 또한 공용 form의 busy 해제가 저장 직전 disabled 플래그를 복원하므로 충돌 시점에만 저장 버튼을 비활성화하면 다시 풀릴 수 있었다. 첫 회귀 4개가 실패하는 RED를 먼저 확보했다.

## 수정한 계약

- 충돌 후 저장을 잠그고 **선택 유지하고 최신 목록 검토**를 제공한다. 실제 submit 함수에서도 차단하므로 직접 form submit으로 우회할 수 없다.
- 검토는 `platform.load()`만 호출한다. 원본 탭·북마크 재조회, 권한 재요청, 자동 저장은 하지 않는다. 이후 별도 담기 클릭이 필요하다.
- 검증한 동일 스냅샷의 revision·보관함·그룹 경로·중복 여부를 함께 갱신한다. 검색어와 유효한 목적지 ID, 아직 저장되지 않은 선택을 유지한다.
- 원본 후보 스냅샷을 다시 비교해 이미 저장된 선택만 제외하고 제외·유지 개수를 알린다. 새로 선택 가능한 후보도 자동 선택하지 않는다.
- 삭제된 그룹은 빈 목적지를 표시한다. 삭제된 보관함은 보관함과 그룹을 각각 직접 고르게 하며, 배경 화면이 선택한 다른 보관함이나 같은 ID의 미분류 그룹으로 몰래 대체하지 않는다.
- 검토 중 중복 읽기·저장은 차단하되 취소는 가능하다. 닫힌/교체된 창의 늦은 응답, 이전 revision, 잘못된 catalog는 반영하지 않는다. 읽기 실패 때 선택을 보존하고 내부 진단 원문은 노출하지 않는다.
- 재충돌은 다시 검토하도록 차단한다. 충돌이 아닌 일반 저장 실패는 기존 재시도를 유지한다. 명시적으로 다른 보관함에 저장한 경우 그 보관함으로 결과를 보여준다.
- busy 해제 이후 picker의 상태를 다시 계산한다. 다른 대화상자의 저장 계약은 바꾸지 않는다.

## 브라우저와 설치 전달의 한계

사용자 데이터와 분리된 localhost:4130 예시 서버를 띄웠으나 내부 브라우저가 webview 연결 대기에서 두 번 실패했다. 생성된 탭 목록도 비어 있었다. 따라서 이번 실행의 실제 화면·포인터·키보드·시각 배치 검증은 **미실행**이며 합성 테스트 통과로 대신 주장하지 않는다. 0.1.29에서 남은 일부 자동 클릭 문제의 원인도 이번에 분리 확인하지 못했다. 임시 서버는 종료했다.

기존 설치용 `artifacts/favmoa-v0.1.13` 폴더가 0.1.29 압축 해제본과 일치함을 확인하고 `artifacts/favmoa-before-0.1.30-20260925`에 백업한 뒤 0.1.30 배포 파일만 교체했다. 소스·ZIP 압축 해제본·기존 설치 경로의 **39개 파일이 바이트 단위로 일치**한다. 폴더명은 기존 Chrome 설치 경로를 유지하기 위한 것이다. 확장 저장 데이터·Chrome 설정은 변경하지 않았다.

Chrome 관리 화면은 이전 실행에서 자동 접근이 보안 정책으로 차단됐다. 우회하거나 다시 시도하지 않았으며, 이번에도 Chrome 런타임의 실제 새 버전 반영은 확인하지 못했다. 사용자가 확장 카드의 새로고침을 눌러야 한다. ZIP·설치 사본·합성 원장은 로컬 산출물로 Git에 올리지 않는다.

다음 단위는 일반 편집·이동 창에서 입력과 의도를 보존하는 충돌 검토다. 최신 데이터에 과거 편집이나 삭제를 자동 재적용하지 않는 범위로 나눈다.
