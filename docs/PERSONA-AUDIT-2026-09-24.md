# FAVMOA 0.1.28 · 관심사 기반 합성 페르소나 점검

## 방법과 근거 범위

100개 합성 페르소나 × 3개 과업 = 300개 시나리오를 실제 배포 소스의 모의 DOM 이벤트 처리와 저장 서비스/모델에 실행한다. 실사용자 100명, 실제 브라우저 300세션, 통계적 사용자 성공률을 뜻하지 않는다. 관심사별 콘텐츠와 규모·깊이·검색·실패 조건을 바꾼 목적 표집이며 행동 특성은 검증을 위한 가정이다. 30개 시나리오 유형을 반복·변형한다. 수행 시간은 기계 실행시간이며 사람의 작업시간으로 해석하지 않는다.

실제 화면은 별도 localhost 예시 저장소에서 대표 흐름만 직접 조작한다. 사용자 Chrome 데이터나 원본 북마크는 읽거나 수정하지 않는다. 제품 런타임은 이번 요청에서 수정하지 않는다.

## 대표 화면 직접 점검

1. **진입 — 양호, 발견성 추가 검증 필요.** 380×820에서 현재 페이지 담기, 열린 탭 담기, 링크 추가, 빈 상태의 북마크 가져오기를 확인했다. 로컬 예시와 실제 데이터의 구분이 명시적이다. `01-start.png`를 저장 후 재열람했다. 북마크를 처음 담는 진입점은 보이나, 링크가 쌓인 뒤에도 찾기 쉬운지는 추가 확인 대상이다. 실사용자 발견 시간이나 스크린리더 경험은 확인하지 않았다.
2. **수동 링크 저장 — 개선 필요, 화면 재현.** 여행 계획 그룹을 접고 `없는 검색어`를 입력한 상태에서 `철도 여행 일정`을 그 그룹에 저장했다. 성공 메시지는 있지만 `검색 결과 0개 / 전체 1개`와 빈 결과 화면이 남는다. `02-manual-save-hidden.png`를 저장·재열람했다. 데이터 손실이 아니라 저장 결과 가시성 문제다. 검색 지우기라는 복구 경로는 제공한다. 실제 사용자의 혼동 빈도는 측정하지 않았다.
   검색을 지운 뒤에도 대상 그룹은 접혀 있었고, 직접 펼친 다음에야 링크가 보였다(`03-reveal-by-hand.png`). 링크 주소·이름은 정상 유지됐다. 수동 저장도 일괄 담기와 같은 결과 표시 정책을 적용할 여지가 있다.
3. **되돌리기 — 개선 필요, 화면 재현.** 위 링크 저장 후 대상 그룹을 펼치고 되돌리기를 한 번 누르자 그룹만 다시 접혔다. 링크는 1개로 남고 되돌리기 버튼이 비활성화됐다(`04-undo-only-fold.png`). 구현은 직전 변경을 되돌렸지만, 방금 추가한 링크를 취소하려던 목표는 달성하지 못한다. 접힘 상태와 데이터 편집의 복구 이력을 분리하는 것을 우선 권고한다. 직접 삭제하는 대안은 있으나 이번 검증에서 임의 삭제하지 않았다.
4. **관심사 보관함 전환 — 개선 필요, 화면 재현.** 별도 과학 자료 보관함에 천문 관측 안내를 담고 내 링크에서 `철도` 검색 후 과학 자료로 전환했다. 이전 검색어가 남아 `검색 결과 0개 / 전체 1개`가 표시됐다(`05-library-search-carryover.png`). 카탈로그는 정상이나 다른 관심사로 이동한 뒤의 탐색 맥락이 이어지는 문제다. 검색 초기화 또는 보관함별 검색 상태를 명시적으로 관리하는 방향을 검토한다. 검색어 지우기 대안은 제공된다.
   검색을 지우자 천문 관측 안내가 다시 보였다(`06-library-search-recovered.png`). 이번 대표 흐름의 콘솔 warning/error는 0건이었다. 합성 예시 저장소에만 여행·과학 자료를 만들었으며 실제 사용자 데이터는 건드리지 않았다.

스크린샷과 실행 결과는 `artifacts/persona-audit-202609241338/`에 보관한다. 이전 턴의 스크린샷은 이번 감사 근거로 재사용하지 않는다.

## 권장 개선 순서

1. 보기 상태의 접기·펼치기를 내용 편집의 되돌리기 기록과 분리한다. 한 단계 복구 정책도 UI에 분명히 알린다.
2. 충돌 후 동일 창 재시도 대신 최신 목록 재검토 또는 창 다시 열기라는 실제 복구 경로를 안내한다. 사용자 확인 없이 최신 데이터에 덮어쓰는 방식은 피한다.
3. 수동 저장 결과와 일괄 담기 결과 표시 정책을 통일한다.
4. 보관함 전환 시 검색 초기화/보관함별 검색 상태 중 일관된 정책을 정한다.
5. 단어 순서에 덜 민감한 검색, 대량 선택과 새 목적지 생성은 별도 사용성 실험 후 우선순위를 정한다.
