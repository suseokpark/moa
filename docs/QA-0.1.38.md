검증일: 2026-09-25 KST. [개선 큐](USABILITY-IMPROVEMENT-QUEUE.md) 4번 완료. 다음은 5번 순서 독립 다중 키워드 검색의 재현·범위 검토다. 이번 검증은 합성 DOM·메모리 저장소이며 실제 Chrome 화면이나 실사용자 연구와 구분한다.

## 재현과 원인

실제 sidepanel 소스에서 첫 보관함의 `Saved` 검색 후 천문 자료 1개를 가진 다른 보관함을 선택했다. 검색어가 그대로 남아 새 보관함의 자료를 숨겼다. 동기적인 선택기 핸들러가 `libraryId`와 임시 펼침 억제 상태만 바꾸고 검색어를 정리하지 않는 것이 원인이다. 즉시 재현되므로 늦은 응답이나 원본 데이터 손실이 원인은 아니었다.

diagnose·TDD로 기능별 실패 테스트→최소 수정→회귀를 진행했다. 동일 보관함 재선택 때 임시 보기 상태가 사라지는 경계와 잘못된/삭제된 선택값의 렌더 오류도 재현했다. 독립 검토에서는 지연 렌더 중 이전 다중 선택이 남는 경우, 보류된 저장 위치 표시가 A→B→A 뒤 초점을 가져가는 경우, 늦은 드래그 저장 응답이 왕복 후 새 검색을 지우는 경우를 RED로 확인하고 각각 수정했다.

## 구현 계약

- 보관함 선택기에서 **유효한 다른 보관함**을 고르면 검색을 비우고 선택 모드를 즉시 종료한다. 임시 보기 상태(`suppressedFolds`, 현재 페이지 자동 펼침 억제)를 정리하지만 catalog에 저장된 그룹 접힘은 바꾸지 않는다.
- 같은 보관함 재선택은 no-op이다. 검색·선택·임시 보기·정상적으로 예약된 결과 표시를 보존한다. 없는/빈/삭제된 보관함 값은 이전 선택으로 돌리고 상태를 변경하지 않는다. 지연 렌더로 예전 옵션이 화면에 남아 있더라도 최신 catalog로 검증한다.
- 전환은 저장 명령 없이 처리한다. catalog·revision·Undo·안전 사본에 쓰지 않으며 초점은 선택기에 남는다. 새 보관함은 기존 검색의 0개 결과가 아니라 해당 보관함의 평상시 목록 또는 빈 보관함 안내를 표시한다. 저장된 접힘과 기존 현재 페이지 표시 규칙은 유지한다.
- 유효한 전환마다 보기 세대를 증가시키고 보류된 결과 초점을 취소한다. 드래그 저장 전에 캡처한 세대와 비교하여 A→B→A 왕복도 새 탐색 의도로 처리한다. 늦은 이동은 정상 저장되지만 이전 결과 표시로 새 검색·초점을 덮지 않는다.
- 새 보관함 생성·추가/이동 성공·저장 위치 보기 등 프로그램 내부의 보관함 변경을 일괄 교체하지 않았다. 서비스/모델/스키마/저장 키/권한/확장 ID와 기존 충돌·Undo 계약은 유지한다.
