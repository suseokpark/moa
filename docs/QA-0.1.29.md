# FAVMOA 0.1.29 · 접기·펼치기와 편집 복구 분리

검증일: 2026-09-25 KST. [0.1.28 감사](PERSONA-AUDIT-2026-09-24.md)의 첫 개선 후보만 다룬다. 마지막 내용 편집 1회 정책을 유지하며 다단계 Undo는 도입하지 않는다.

## 재현과 원인

실제 저장 서비스와 메모리 저장소에서 링크 삭제 → 그룹 접기 → 되돌리기를 실행했다. 삭제 직후 복구본에는 링크가 있었으나 접기 직후 복구본에는 링크가 없었다. revision은 일치하고 Undo도 성공했지만 링크는 복구되지 않았다. 화면이나 충돌 검사가 아니라 모든 액션이 같은 복구 슬롯을 교체하는 것이 원인이었다. `fold-undo.test.mjs`에 기대하는 링크 복구를 먼저 작성하여 실패를 확인했다.

## 수정 정책

- `toggleGroup`은 현재 유효한 편집 복구본을 유지하고 해당 보관함·그룹의 명시적 접힘 상태만 반영한다. 새 revision과 함께 원자적으로 저장한다.
- 다른 보관함에서 같은 그룹 ID를 사용해도 그 접힘 상태는 바꾸지 않는다. 새 그룹이 복구본에 없으면 편집 Undo로 새 그룹 자체를 취소할 수 있다.
- 명시적 접기와 달리 일괄 추가/이동의 자동 펼침은 해당 내용 편집을 취소할 때 종전처럼 복구된다.
- Undo가 없거나 손상/버전 불일치 상태면 접기만으로 Undo를 만들거나 부활시키지 않는다.
- 저장 실패, 충돌, v1 원본 보관, JSON 복원 전 안전 사본 정책을 유지한다. 그룹 보기 변경 자체를 되돌리는 이력은 제공하지 않는다.
- 독립 검토에서 `collapsed: true → false`의 1바이트 증가가 정확히 5 MiB인 Undo 스냅샷을 무효화하는 경계를 재현했다. 수정한 복구본도 저장 전에 검증하며, 초과하면 접기·펼치기 저장을 거절하고 기존 목록·Undo를 그대로 보존한다. 정확히 한도에 도달하는 경우에는 저장·재시작·복구가 가능하다.
- 버튼 설명과 사용 안내에 마지막 내용 편집 1회 정책을 명시한다. 업데이트 전에 이미 소모된 편집 이력을 재구성하거나 복구하는 기능은 아니다.

## 실제 화면 점검

별도 localhost:4177 예시 저장소에서 새 `여행 회귀 점검` 그룹을 만들고 `https://example.com/project/specification` 예시 링크를 담았다. 그룹의 링크 수 1과 펼침 상태를 확인한 뒤 접고, 되돌리기를 눌렀다. 링크 수는 0, 그룹은 접힌 상태, Undo는 비활성으로 바뀌었다. 새로고침 후에도 이 상태가 유지됐다. 화면과 접근성 트리로 확인했고 수집된 콘솔 warning/error는 0건이었다.

이는 내부 브라우저의 합성 예시 화면 검증이다. 사용자 Chrome 링크·북마크·탭이나 실제 확장 저장 데이터는 검증에 사용하지 않았다. 스크린리더 음성, Chrome 저장소 할당량, 사용자 체감 성과를 증명하지 않는다.

최종 소스로 다시 연 화면에서 편집 없이 그룹을 펼쳐도 Undo가 비활성인 것을 접근성 `Expand` 동작으로 확인했다. 이 후속 점검 중 일부 자동 클릭·Enter가 화면에 반영되지 않았으나 콘솔 오류는 없었다. 입력 도구와 제품 이벤트 경로의 원인을 분리하지 못했으므로 이 후속 동작을 일반 포인터·키보드 전체 흐름 통과로 집계하지 않는다.
