# FAVMOA 0.1.27 QA — 열린 탭을 골라 한 번에 담기

검증일: 2026-09-23 KST. 0.1.26 → 0.1.27, 다음 패치 0.1.28.

## 사용 방법과 범위

1. 현재 페이지 카드의 **열린 탭 담기…**를 누른다.
2. 현재 Chrome 프로필의 모든 창에서 새로 담을 웹 탭을 조회한다. 처음에는 아무것도 선택하지 않는다.
3. 탭 이름·주소로 검색하고 필요한 항목을 체크한다. **보이는 탭 모두 선택**은 현재 표시된 결과에만 적용한다.
4. 저장할 그룹을 지정하고 **선택한 N개 담기**를 누른다. 추가 전체는 **되돌리기** 한 번으로 취소한다.

현재 보관함에 이미 저장한 페이지, 같은 페이지를 중복으로 연 탭, HTTP(S)가 아닌 주소와 시크릿 탭은 제외한다. 기존 링크 식별 규칙을 사용하므로 동일 Notion 페이지의 서로 다른 보기 주소도 중복으로 취급하며 첫 후보의 전체 URL을 유지한다. 제목은 제어문자·공백을 정리하고 최대 300자로 제한한다. 원본 탭은 닫거나 이동하지 않는다.

검색으로 숨겨진 선택은 개수로 알린다. 200개씩 표시하고 더 보기로 추가 표시하며, 선택은 최대 1,000개다. 전체 catalog 용량·항목 제한도 적용한다. 탭 목록은 창을 열 때의 스냅샷이며 새 탭을 반영하려면 닫았다 다시 연다. 조회 실패는 오류와 다시 불러오기 버튼을 표시한다. 취소된 조회가 늦게 끝나도 다른 대화상자를 덮어쓰지 않는다.

## 저장과 접근성

- 보관함·revision을 조회 전에 고정하고 선택한 제목·URL만 `addLinks` 한 번으로 전달한다. 브라우저 탭 ID·창 ID·전체 조회 목록은 저장하지 않는다.
- `revealTarget: true`일 때 목적지와 상위 그룹을 같은 변경 안에서 펼친다. 기존 북마크 가져오기 동작은 바꾸지 않는다.
- 중복·잘못된 주소·삭제된 목적지·저장 실패·revision 충돌은 부분 추가하지 않는다. 실패 시 체크·검색·목적지를 유지하며, revision 충돌은 최신 목록을 확인하고 대화상자를 다시 열어야 한다.
- 일반 링크 클릭과 다중 이동 기능은 그대로 유지한다. 저장 성공 후 검색/이동 선택 모드를 해제하고 목적지에 포커스를 준다. 지연 렌더 이후에도 포커스를 복구한다.
- 네이티브 checkbox와 label, Space 선택, 상태 안내, Escape 취소를 사용한다. 저장 중 중복 제출을 차단한다.
- 새 권한·로그인·클라우드 연결 없이 기존 `tabs` 권한을 사용한다. schema 2·저장 키·공개키·고정 확장 ID는 불변이다. Notion 전용 UI는 복구하지 않는다.

브라우저 검증은 명시적으로 표시한 예시 데이터로 진행했다. Chrome 탭 API·저장 실패·충돌은 모의 실행이며 실제 사용자 데이터에서의 성공으로 확대하지 않는다. 실제 스크린리더 음성 출력·전체 WCAG 준수는 검증하지 않았다. 로컬 페이지의 수집된 오류/경고는 0개였다.

독립 코드 검토에서 발견한 지연 렌더 뒤 목적지 포커스 누락을 수정하고 회귀 테스트를 추가했다. 테스트용으로 담은 두 합성 링크는 되돌리기로 정리했고 원래 예시 문서를 보존했다. 임시 브라우저 탭과 뷰포트 설정을 정리했다.
