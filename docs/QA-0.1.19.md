# FAVMOA 0.1.19 QA — Notion 전용 화면 종료

기록일: 2026-09-23 KST. 코드·합성 검증과 실제 설치 확인은 구분한다.

## 변경 범위

- Chrome 사이드 패널만 현행 UI로 제공한다. Notion 안의 메뉴·내부 트리·DOM 수집은 종료한다.
- 기존 `nfs:` 데이터는 삭제하거나 자동 이전하지 않는다. 수동 **기존 Moa 목록 가져오기**는 남겨 두며, 실행 시 원본을 보존한 복사본을 만든다.
- 일반 Notion URL의 저장·열기는 범용 링크와 같은 경로로 지원한다.
- 기존 범용 catalog·재귀 그룹·JSON 백업, 확장 공개키·ID와 로컬 우선 정책을 유지한다. Google 연결은 재개하지 않는다.
- 도움말·가져오기 확인문·설치 문서에 종료와 보존의 차이를 명시한다. Notion 탭을 새로고침해야 이미 주입된 이전 UI가 없어짐을 안내한다.
- 구형 `NFS_*` 요청은 종료 응답만 반환하고 저장소에 접근하지 않는다. 기존 동기화 포트도 종료한다. 역사적 저장 계약 검증용 worker는 `test-support/`에만 두며 배포에서 제외한다.
- 수동 가져오기에서 검증된 기존 `href`가 있으면 워크스페이스 경로·쿼리·해시를 보존한다. 주소가 없는 과거 항목은 기존 ID 기반 `www.notion.so` 호환 주소를 유지한다. 실제 모든 과거 링크가 열리는지는 별도 확인이 필요하다.

## 확인할 수용 기준

- manifest에서 웹사이트 콘텐츠 스크립트를 등록하지 않는다. 종료된 Notion UI 파일은 현재 배포에서 제외한다.
- 확장 업데이트만으로 기존 저장 데이터를 삭제·자동 이전하지 않는다.
- Chrome 도구 모음에서 범용 사이드 패널을 열 수 있다.
- 업데이트 후 새로고침한 Notion 탭에는 내부 FAVMOA 메뉴나 화면이 없다.
- 일반 Notion URL의 저장·기존 탭 이동·새 탭 열기에서 워크스페이스 경로가 불필요하게 제거되지 않는다.
- 수동 이전은 사용자 실행 시에만 수행하고 원본 저장 데이터는 보존한다. 취소는 데이터 변경이 아니다.

## 한계

- 이전 Notion 합성 fixture는 역사적 회귀 자료이며, 통과 여부를 현행 Notion 내부 화면 제공의 근거로 사용하지 않는다.
- localhost 미리보기와 Node 검사는 실제 Chrome 사용자 데이터·보호된 확장 페이지·모든 Notion 워크스페이스의 정상 동작을 증명하지 않는다.
- 자동 이전·삭제·Google 로그인·Drive 동기화는 이번 범위가 아니다. 사용자 원본 문서에 쓰기 작업을 하지 않는다.
