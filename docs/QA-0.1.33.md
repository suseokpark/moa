# FAVMOA 0.1.33 · 그룹·일괄 링크 이동 충돌 검토

검증일: 2026-09-25 KST. [개선 큐](USABILITY-IMPROVEMENT-QUEUE.md) 2번의 네 번째 단위다. 삭제·초기화·백업 확인창은 다음 범위이며 이번 완료에 포함하지 않는다.

## 재현과 구현

실제 sidepanel 소스와 모델을 합성 DOM/저장소에서 실행했다. 두 이동창 모두 revision 7로 열고 revision 8 충돌을 받은 뒤 다시 제출하자 요청은 `[7, 7]`이고 버튼은 활성 상태였다. 그룹 이동은 원래 보관함이 사라지면 재시도 libraryId가 다른 보관함으로 바뀌기도 했다. 일괄 이동은 ID를 고정하고 있었지만 이동 수와 목적지는 처음 목록으로 계산했다. 서비스의 충돌/원자적 이동 보호는 유지되고 있었으며, 이를 우회하지 않고 화면의 명시적 복구 경로를 추가했다.

- 공용 `treeMoveDialog`에서 원래 보관함·출발 그룹·선택 링크 ID를 고정한다.
- 충돌 후 **선택 유지하고 최신 목록 검토**는 `platform.load()`만 실행한다. 최신 revision을 검토한 뒤 별도로 이동해야 하며 원본 탭/북마크 재조회·자동 이동·권한 요청은 없다.
- 최신 하위 그룹·링크의 이름/주소/전체 경로 ID와 이름/순서, 목적지 경로를 처음 상태와 비교한다. 그룹색도 비교한다. 바뀌었다면 내용을 표시하고 확인 체크 후에만 이동한다. 아이콘/접힘만 바뀐 경우는 이동 범위를 바꾸지 않으므로 추가 동의를 요구하지 않고 최신 값을 유지한다.
- 보관함·출발 그룹·선택 링크가 삭제되면 전체 이동을 차단한다. 선택 상태가 최신 목록에서 정리되어도 대화상자의 원래 ID 목록을 축소하지 않는다. 다른 보관함의 같은 ID로 대체하거나 일부 링크만 이동하지 않는다.
- 목적지가 삭제되거나 자손으로 이동했거나 이동할 하위 트리를 포함한 깊이가 32단계를 넘으면 이전 선택을 사용 불가로 남긴다. 사용자가 다른 위치를 직접 선택해야 한다. 정확히 32단계는 허용하며 자기 자신/자손과 no-op 이동은 차단한다.
- 최신 링크 위치에 맞춰 실제 이동 수와 이미 목적지에 있는 수를 다시 계산한다. 목적지 변경/새 검토/재충돌 시 이전 확인을 취소한다.
- 실패한 읽기, 오래되거나 잘못된 스냅샷, 중복 검토, 창 취소·교체 뒤 늦은 응답은 이동을 허용하지 않는다. 일반 저장 실패는 선택을 유지하고 기존 재시도를 제공한다. 저장 성공 시 원래 보관함으로 돌아간다.

## 재현 우선 및 독립 검토

작은 실패 테스트를 추가하고 실패를 확인한 뒤 구현하는 순서로 진행했다. 그룹/일괄 충돌, 삭제 보관함, 누락된 선택 링크, 변경된 하위 내용, 삭제/변경 목적지, 자손 순환, 깊이 초과, no-op, 오래된 메뉴의 삭제 그룹 접근을 각각 재현했다.

독립 검토가 개발 중인 구현의 반복 계산을 발견했다. 목적지마다 전체 트리를 다시 순회하고, 일괄 이동 개수를 세며 목적지 DOM 값을 그룹마다 다시 읽었다. 검토한 catalog 단위 인덱스/그룹 ID 조회/하위 트리 높이 캐시와 목적지 값 1회 읽기로 변경했다. 결정적 회귀는 1,003그룹의 트리 방문 약 101만 회와 목적지 읽기 1,004회에서 RED를 확인하고 각각 선형 방문/10회 미만 읽기로 GREEN을 확인한다.

독립 합성 VM 계측에서 10,003그룹은 **개발 중간 구현**의 그룹창 약 8,540ms → 14ms, 일괄 이동창 약 652~850ms → 94ms였다. 최종 두 흐름은 각 2회 트리 순회/20,006노드 방문이었다. 이 수치는 0.1.32 대비 출시 성능 향상이나 실제 Chrome 체감시간이 아니다.

## 전달과 한계

실제 사용자 저장 데이터·북마크·탭을 사용하지 않았다. 최근 내부 브라우저 webview 연결 실패를 반복하지 않았으며, 이번 실제 화면 점검은 미실행이다. 네이티브 포인터/키보드/스크린리더/긴 비교 목록 가독성은 별도 확인이 필요하다. 합성 DOM 테스트를 실제 Chrome 검증으로 주장하지 않는다.

기존 설치 경로 `artifacts/favmoa-v0.1.13`의 파일이 0.1.32와 일치함을 확인하고 `artifacts/favmoa-before-0.1.33-20260925`에 백업한 뒤 배포 파일만 교체했다. 소스·ZIP 압축 해제본·설치 경로의 **39파일이 바이트 단위로 일치**한다. Chrome 설정/저장 데이터는 변경하지 않았으며 확장 카드 새로고침은 사용자 확인이 필요하다. 이전에 차단된 확장 관리 URL을 다른 경로로 우회하지 않았다.

ZIP·설치 백업·합성 원장은 로컬 산출물로 공개 저장소에 올리지 않는다. 다음은 삭제/초기화/백업 확인창의 최신 영향 범위 재검토다.
