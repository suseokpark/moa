### 현재 출시 범위: 0.1.37 — 추가·이동한 항목의 목적지를 바로 표시

**수동 링크 추가**, **단일 링크 이동**, **그룹 메뉴 이동**, **드래그 이동**이 실제로 성공하면 목적지와 조상 그룹을 펼쳐 결과가 보이게 한다. 새 링크와 이동한 링크는 그 링크를, 이동한 그룹은 그룹 제목을 표시한다. 그룹 이동은 옮긴 그룹 자체의 접힘 상태를 강제로 풀지 않는다. 최상위 그룹 이동도 옮긴 그룹 제목을 결과로 삼는다. 목적지 자동 펼침은 편집 명령과 같은 원자적 저장에 포함하며 성공 뒤 별도 `toggleGroup` 저장을 하지 않는다.

성공하면 검색을 비우고 실제 결과가 있는 보관함으로 돌아온다. 대화상자 종료·보류 렌더링을 고려해 결과 항목에 포커스와 스크롤을 맞춘다. 새 대화상자를 열었거나 열었다가 취소한 경우, 보관함이 바뀐 경우에는 이전의 보류된 포커스 이동을 취소하며 열린 테마 설정의 포커스도 빼앗지 않는다. 취소·저장 실패·충돌과 최신 목록 검토만으로 검색·접힘·결과 표시를 바꾸지 않는다. 같은 위치 이동은 데이터·접힘·기존 되돌리기를 바꾸지 않는 no-op이며 불필요한 저장을 만들지 않는다. 일반 링크 내용 수정과 기존 일괄 추가·일괄 이동 계약은 이번 변경으로 확대하지 않는다.

마지막 내용 편집 1회 되돌리기는 편집과 그 편집에서 자동으로 펼친 경로를 함께 취소한다. 이후 사용자가 명시적으로 접거나 펼친 상태는 기존 보호 계약에 따라 유지한다. 충돌 revision 검사·원자적 실패·순환/깊이/시스템 그룹 보호, schema 2·저장 키·권한·확장 ID와 원본 서비스 불변을 유지한다.

감사 우선순위 3의 지정된 추가·이동 경로 구현을 마무리하며 다음은 우선순위 4인 보관함 전환 시 검색 맥락 정리다. 검증 범위와 한계는 [0.1.37 QA](QA-0.1.37.md)에 구분한다. 실제 Chrome 화면·키보드·스크롤 검증은 별도이며 합성 테스트를 실사용자 검증으로 해석하지 않는다.

### 역사 기록: 0.1.36 — 기존 Moa 가져오기 충돌 뒤 최신 저장 목록 검토

**기존 Moa 목록 가져오기** 확인창에서 revision 충돌이 나면 오래된 실행 반복을 차단한다. **최신 대상 목록 검토**는 현재 대상 catalog와 revision만 읽으며 저장·undo·안전 사본을 변경하지 않는다. 원본 `nfs:` 자료를 조회·미리보기·고정하지 않고 가져올 수량이나 내용을 확정해서 보여준다고 주장하지 않는다. 실제 원본은 사용자가 별도 가져오기를 실행할 때 읽으므로 검토 이후 달라질 수 있다는 한계를 안내한다.

최신 현재 보관함을 검토하고 명시적으로 확인한 뒤 별도 가져오기 버튼을 눌렀을 때만 검토한 revision으로 기존 일회성 복사를 실행한다. 검토만으로 가져오거나 변경을 자동 재적용하지 않는다. 다시 충돌하면 확인을 취소하고 최신 목록을 다시 검토해야 한다. 읽기 실패·오래된 revision·잘못된 catalog는 실행을 허용하지 않고 읽는 중 취소·창 교체 뒤 응답은 새 작업에 반영하지 않는다. 일반 저장 실패의 명시적 재시도와 원자적 저장·마지막 내용 편집 1회 되돌리기를 유지한다.

현재 catalog에 남아 있는 `migratedLegacyKeys`로 같은 원본 키의 중복 이전을 막는다. 이전 기록이 없는 다른 catalog로 복원한 경우까지 영구적인 중복 방지를 보장하지 않는다. 성공 응답의 가져온 보관함이 0개라도 경고가 있으면 목록이 없다고 단정하지 않고 확인이 필요한 결과를 안내한다. 원본 트리·제목 캐시·호환 스냅샷 보존, 자동 이전·원본 동기화 없음, schema 2·저장 키·공개키·확장 ID·권한과 클라우드 보류 정책을 유지한다.

0.1.36은 감사 우선순위 2의 지정된 후보 선택·수동 링크·메타데이터·그룹/일괄 이동·삭제/초기화·JSON/안전 사본·기존 Moa 가져오기 대화상자의 복구 경로 구현을 마무리했다. 모든 명령·네트워크·실제 Chrome 환경의 충돌이 해결됐다는 뜻은 아니다. 당시 다음 항목은 우선순위 3인 수동 링크 추가·이동 후 목적지 펼침/검색 해제/결과 표시, 이어 우선순위 4인 보관함 전환 시 검색 맥락 정리였다. 당시 검증 범위와 한계는 [0.1.36 QA](QA-0.1.36.md)에 구분한다. 실제 Chrome 화면 검증은 별도이며 합성 테스트를 실사용자 검증으로 해석하지 않는다.

### 역사 기록: 0.1.35 — 실제 백업 사본을 미리 보고 최신 교체 영향 재검토

**JSON 백업 불러오기**와 **복원 전 목록 복구**는 현재 목록뿐 아니라 실제 저장된 복원 전 안전 사본을 읽는 미리보기 경로를 사용한다. 미리보기는 읽기만 하며 catalog·revision·undo·안전 사본을 변경하지 않는다. 현재 목록과 적용할 목록을 비교하고 기존 사본이 교체되거나 사용 완료되는 영향을 보여준다. 읽기 실패·오래된 응답·잘못된 데이터는 실행을 허용하지 않고, 읽는 중 취소·창 교체 뒤 응답은 새 작업에 반영하지 않는다.

JSON 복원은 사용자가 선택해 검증한 파일 내용을 고정한다. 다른 패널의 변경과 충돌해도 파일을 다시 고르거나 원본 파일을 다시 읽게 하지 않으며, 최신 현재 목록과 기존 안전 사본에 미치는 영향을 다시 검토한다. 명시적으로 확인한 뒤 별도 실행 버튼을 눌렀을 때 검토한 revision으로 원자적으로 적용한다. 기존 안전 사본을 대체하는 경우 그 영향을 알리고, 같은 목록인 no-op은 기존 사본을 유지한다. 검토 사이 다시 충돌하면 다시 검토하고 확인해야 한다.

복원 전 목록 복구는 사본이 있다는 불리언만으로 실행하지 않는다. 실제 사본 내용을 읽어 미리 보고 명시적으로 확인한 뒤 별도로 복구한다. 사본이 없거나 손상되면 실행을 차단한다. 최신 미리보기 이후 목록 또는 사본이 바뀌면 revision 검사로 중단하고 새 미리보기·확인을 요구한다. 사본 사용 완료, 원자적 쓰기, 일반 저장 오류 재시도와 마지막 내용 편집 1회 되돌리기 계약은 유지한다.

당시 **기존 Moa 가져오기 확인창의 충돌 복구는 후속 범위로 남겼다.** 당시 전체 충돌 복구 후보의 완료를 뜻하지 않았다. schema 2·저장 키·공개키·확장 ID·권한과 클라우드 보류 정책을 유지했다. 당시 검증 범위와 한계는 [0.1.35 QA](QA-0.1.35.md)에 보존하며, 합성 검증을 실제 Chrome 화면·사용자 저장소·원본 서비스 검증으로 해석하지 않는다.

### 역사 기록: 0.1.34 — 삭제·초기화 전 최신 영향 범위 재확인

**링크 삭제**, **그룹 삭제**, **현재 보관함 초기화** 확인창에서 revision 충돌이 나면 원래 보관함과 대상 ID를 유지하고 최신 목록을 명시적으로 검토하게 한다. 오래된 확인을 반복하지 않으며 검토 버튼은 최신 저장 목록을 읽기만 하고 저장·undo를 만들지 않는다. 읽기 실패·오래된 응답은 실행을 허용하지 않고 취소·창 교체 뒤의 응답은 새 작업에 반영하지 않는다.

삭제할 링크는 최신 이름·URL·위치를, 그룹 삭제는 최신 그룹과 하위 내용의 범위 및 내용이 보존될 위치를, 초기화는 원래 보관함의 최신 관리 범위를 보여준다. 그룹 삭제는 그룹 껍데기만 없애고 직접 링크·하위 그룹을 부모로, 최상위 그룹의 내용은 미분류 그룹으로 옮기는 기존 계약을 유지한다. 최신 위치가 바뀌었다면 그에 따른 보존 위치를 검토해야 한다. 원래 보관함·대상 링크·그룹이 사라졌다면 실행을 막으며 다른 보관함의 같은 ID나 첫 보관함으로 대체하지 않는다.

충돌 뒤 검토에서는 영향이 처음과 같더라도 반드시 명시적 확인을 받은 뒤 별도 삭제·초기화를 허용한다. 검토한 revision과 고정한 원래 대상으로만 실행하며 그 사이 다시 충돌하면 다시 검토하고 확인받는다. 일반 저장 오류의 재시도, 미분류 그룹 보호, 그룹 삭제의 내용 보존, 원자적 저장·마지막 내용 편집 1회 되돌리기 및 원본 웹페이지·브라우저 탭·북마크 불변을 유지한다. schema 2·저장 키·공개키·확장 ID·권한과 클라우드 보류 정책은 바꾸지 않는다.

당시 범위는 세 로컬 관리 확인창이었다. 기존 Moa 가져오기·JSON 복원·복원 전 안전 사본 적용의 충돌 복구는 당시 포함하지 않았다. 당시 검증 범위와 한계는 [0.1.34 QA](QA-0.1.34.md)에 보존하며 합성 검증을 실제 사용자 저장소나 원본 서비스 검증으로 해석하지 않는다.

**북마크 선택 가져오기**와 **열린 탭 담기**에 같은 후보 선택 흐름을 사용한다. 사용자 클릭 즉시 읽기 상태와 취소를 제공하고, 시작 시점의 보관함·revision을 고정한다. 취소하거나 다른 작업창으로 바뀐 뒤 도착한 이전 결과는 무시한다. 읽기 실패는 안내와 명시적 다시 불러오기를 제공하며 늦은 응답이 다른 대화상자의 입력을 덮지 않아야 한다. 북마크 읽기 권한은 사용자가 가져오기 버튼을 직접 누를 때만 기존 선택 권한으로 요청하고 원본 북마크 쓰기는 하지 않는다.

북마크 제목·URL·원래 폴더 경로로 검색한다. 현재 보관함에 이미 저장한 주소와 중복·지원하지 않는 주소는 가져오기 대상에서 제외한다. 처음 200개를 표시하고 **더 보기**로 200개씩 늘린다. **보이는 북마크 모두 선택** 또는 **보이는 탭 모두 선택**은 현재 실제 표시한 항목만 선택·해제한다. 검색·표시 한도 밖의 선택을 유지하고 전체 수와 화면 밖 개수를 함께 안내한다. 두 창의 **선택 해제**는 검색어를 유지하며 숨겨진 항목을 포함한 선택 전체를 해제한다. 선택 0개이면 제출을 비활성화하고 최대 1,000개 한도를 선택 단계에서 안내한다. 제목의 제어문자·공백을 정리하고 300자로 제한하되 전체 URL은 보존한다. 북마크 폴더 경로는 검색·출처 안내에만 사용하며 폴더 구조를 자동 복사하지 않는다.

확정은 고정한 보관함·revision과 선택한 목적지로 하나의 `addLinks` 명령을 보낸다. `revealTarget`으로 목적지 조상 경로를 같은 변경에서 펼치고 성공 뒤 트리 검색을 비워 저장 그룹으로 포커스를 옮긴다. 성공한 추가 전체를 한 번의 되돌리기로 취소한다. 선택·목적지 오류, 충돌, 저장 실패는 부분 추가하지 않는다. 충돌을 자동으로 최신 revision에 재적용하지 않으며 닫고 다시 열어 최신 목록을 확인하도록 안내한다. 취소와 선택 해제는 원본·보관함을 변경하지 않는다. 조회 후보와 임시 선택은 영속 저장·JSON 백업 대상이 아니다.

schema 2·기존 저장 키·공개키·확장 ID와 권한 범위는 유지한다. Google 연결·클라우드 동기화·Notion 전용 화면을 재개하지 않는다. 자동 회귀·합성 브라우저·패키지·실제 Chrome 확인의 범위와 한계는 [0.1.28 QA](QA-0.1.28.md)에 구분한다. 데모의 합성 북마크·탭 및 모의 저장 결과는 실제 Chrome 권한 승인·개인 북마크 조회·사용자 저장소 검증의 증거가 아니다.

### 역사 기록: 0.1.27 — 열린 탭을 선택해 그룹에 한 번에 담기

**열린 탭 담기**는 사용자가 명시적으로 실행하는 복사 기능이다. 현재 Chrome 프로필의 모든 일반 창에서 HTTP(S) 웹 탭을 조회하고, 제목·URL 검색과 체크박스로 필요한 항목만 고른 뒤 현재 보관함의 목적지 그룹에 저장한다. 시크릿 탭과 Chrome 설정·확장 화면 등 비웹 주소는 제외한다. 탭을 닫거나 이동·새로 열지 않고 원본 페이지를 변경하지 않는다. 목록은 대화상자를 열 때 조회한 스냅샷이며 탭 변화가 실시간 반영되는 목록이 아니다. 탭을 열거나 주소를 바꿨다면 대화상자를 닫고 다시 열어 새로 조회한다.

처음에는 선택이 없으며 **보이는 탭 모두 선택**은 현재 검색 결과의 추가 가능한 항목만 선택·해제한다. 검색으로 숨겨진 선택은 유지하고 전체 선택 수와 함께 표시한다. 기존에 현재 보관함에 저장한 링크와 중복 탭은 기존 링크 식별 규칙에 따라 제외한다. 다른 보관함의 링크를 임의로 옮기거나 합치지 않는다. 이름의 제어 문자·공백을 정리하고 길이를 제한하되 전체 URL은 보존한다. 한 번에 최대 1,000개를 추가하며 전체 catalog 용량·항목 수 제한도 별도로 적용한다.

확정은 하나의 `addLinks` 명령으로 검증·저장하고 성공한 추가 전체를 한 번의 되돌리기로 취소할 수 있다. 잘못된 목적지·선택·오래된 revision·저장 실패는 부분 추가하지 않으며, 취소도 목록을 바꾸지 않는다. 조회한 탭 목록과 임시 선택은 저장소·JSON 백업·클라우드에 넣지 않는다. 선택하여 저장한 일반 링크만 기존 로컬 보관함과 사용자가 실행한 JSON 백업에 포함된다. 페이지 본문·쿠키·브라우저 세션을 수집하거나 다른 기기의 열린 탭을 복원하는 기능은 아니다.

기존 `tabs` 권한을 사용하며 새 권한·로그인·클라우드 연결은 추가하지 않는다. schema 2·저장 키·공개키·확장 ID와 Notion 전용 화면 종료 경계를 유지한다. 이전의 일괄 이동·클릭 보호·테마·백업을 유지한다. 자동 회귀, 합성 브라우저, 패키지와 실제 Chrome의 확인 범위는 [0.1.27 QA](QA-0.1.27.md)에 구분하며, 합성 탭 목록을 실제 사용자의 Chrome 탭 조회·저장 증거로 보고하지 않는다.

### 역사 기록: 0.1.26 — 여러 링크 선택 후 한 번에 이동

목록의 **선택** 버튼으로 명시적 선택 모드에 들어간다. 이때 체크박스와 링크 제목은 선택·해제를 수행하고 링크를 열지 않는다. 모드 밖의 일반 클릭은 기존 탐색 동작을 유지한다. 선택 중 링크·그룹 드래그를 비활성화하여 선택과 이동 제스처가 충돌하지 않게 하며, 그룹 자체를 일괄 선택하는 기능은 추가하지 않는다.

**보이는 링크 모두 선택**은 현재 검색과 그룹 접힘 상태에서 실제 표시된 링크 ID만 대상으로 한다. 일부만 선택했으면 보이는 항목을 모두 선택하고, 모두 선택했으면 보이는 항목만 해제한다. 검색·접힘으로 숨겨진 선택은 유지하며 전체 개수와 화면 밖 개수를 안내한다. 선택은 현재 보관함의 패널 메모리에만 유지하고 저장소·백업에 넣지 않는다. 같은 보관함의 화면·탭 갱신에는 유지하되 제거된 링크를 정리하며, 보관함 전환·선택 종료 시 모두 비운다.

**선택 이동…** 대화상자는 전체 선택 수와 숨겨진 항목 수를 명시한다. 대화상자를 열 때 보관함·선택 IDs·revision을 고정하고 하나의 `moveLinks` 명령으로 검증·저장한다. 목적지에 이미 있는 링크의 순서는 바꾸지 않으며, 다른 그룹에서 들어오는 링크는 원래 트리 순서대로 목적지 뒤에 붙이고 목적지 경로를 펼친다. 모두 같은 목적지에 있으면 이동 버튼을 비활성화하며 모델·서비스의 no-op도 저장·undo를 만들지 않는다. 성공한 일괄 이동 전체는 한 번의 되돌리기로 복구한다. 취소·잘못된 대상·오래된 revision·저장 실패는 부분 이동을 하지 않는다. 오류 후 유효한 선택을 유지해 재시도할 수 있게 하며, 최신 목록에서 없어진 링크만 제외한다.

이전 버전의 클릭 보호·조용한 이동 피드백·새 보관함 선택·입력 오류 포커스·저장 중 편집 보호를 유지한다. schema 2·저장 키·권한·공개키·확장 ID와 클라우드 보류 경계는 변경하지 않는다. 자동 회귀, 합성 브라우저와 실제 Chrome의 확인 범위는 [0.1.26 QA](QA-0.1.26.md)에 구분한다. 합성 데이터와 모의 저장 검증을 실제 사용자 목록이나 원본 서비스 변경의 증거로 보고하지 않는다.

### 역사 기록: 0.1.25 — 조용한 링크 이동과 명확한 편집 흐름

링크 클릭 직후 임시 **여는 중** 문구를 삽입·제거하거나 **현재·열림** 배지를 바꾸지 않는다. 제목·행의 자식 요소와 폭을 유지하면서 `aria-busy`를 즉시 갱신한다. 정상 이동은 독립된 화면 밖의 polite live region으로 안내하고, 열기 실패만 보이는 오류로 표시한다. 이동 안내가 기존 저장·되돌리기 메시지를 덮어쓰지 않으며 오류 후 다시 열기를 시도할 수 있다. 빈 live region도 첫 안내 전부터 접근성 트리에 유지한다.

새 보관함을 만들면 생성한 보관함을 즉시 선택하고 기존 검색어를 비워 빈 새 공간을 명확히 보여 준다. 입력 검증 실패는 해당 칸에 `aria-invalid`와 오류 설명을 연결하고 포커스를 옮겨 바로 고칠 수 있게 한다. 저장 중에는 대화상자의 입력·선택·버튼을 잠가 제출 내용과 화면 값이 달라지지 않게 하고, 실패하면 입력값과 이전의 비활성 상태를 보존한 채 편집 가능한 상태로 복구한다.

첫 클릭 보호·드래그앤드롭·중복 열기 방지·명시적 새 탭·URL 보존·되돌리기를 유지한다. schema 2·저장 키·권한·확장 ID와 네트워크 경계는 변경하지 않는다. 자동 회귀, 합성 브라우저, 실제 Chrome 확인 범위와 남은 개선 제안은 [0.1.25 QA](QA-0.1.25.md)에 구분한다. 합성 화면의 결과를 실제 설치 데이터나 원본 사이트 로딩의 검증으로 보고하지 않는다.

### 역사 기록: 0.1.24 — 첫 클릭 보존

탭·포커스 갱신이 링크를 누르는 동안 목록 DOM을 교체하여 첫 클릭을 잃는 경합을 수정한다. 화면에 영향을 주는 탭 상태가 같으면 트리를 다시 그리지 않는다. 실제 탭 상태나 보관함 내용이 달라져도 포인터를 누르는 중에는 표시 갱신을 보류하고, 포인터를 놓은 뒤 이어지는 클릭 처리가 끝나면 최신 상태를 반영한다. 변경을 버리는 것이 아니라 눌린 항목을 보존하도록 반영 시점을 조정한다.

드래그가 끝난 뒤 300ms 동안 발생하는 후행 클릭 차단은 유지하지만, 새로운 `pointerdown`은 사용자의 다음 의도적인 누르기로 보고 차단을 해제한다. 드래그 후 새로 클릭한 링크나 그룹이 첫 조작을 잃지 않게 한다. 기존 중복 열기 방지·명시적 새 탭·URL 보존·이동 보호와 되돌리기는 유지한다.

schema 2·저장 키·권한·확장 ID는 변경하지 않는다. [0.1.24 QA](QA-0.1.24.md)에 제어된 브라우저 재현, 회귀 검사, 실제 Chrome 확장의 확인·미확인 범위를 구분한다. 합성 화면의 클릭 성공은 보호된 실제 확장 화면이나 사용자 사이트의 로딩 완료를 대신하지 않는다.

### 역사 기록: 0.1.23 — 드래그 이동과 빠른 조작 피드백

링크를 다른 그룹에 드래그앤드롭하여 소속을 바꾸고, 사용자 그룹은 내용물 전체와 함께 다른 그룹 안이나 최상위로 옮긴다. 드롭 가능 위치를 표시하되 자기 자신·자손 안으로의 이동, 미분류 그룹 이동, 깊이 상한 위반은 허용하지 않는다. 기존 이동 명령·revision 검사·되돌리기를 사용하며 외부 페이지나 다른 보관함에서 넘어온 드래그를 목록 추가로 해석하지 않는다. 키보드용 이동 메뉴는 유지하고 드래그를 필수 조작으로 만들지 않는다.

일반 링크 클릭은 즉시 **여는 중**을 표시한다. 현재 창과 전체 탭 조회를 병렬 처리하고, 처리 중인 같은 목적지의 일반 클릭은 하나의 열기 요청으로 합친다. 현재 창의 일치 탭을 우선하는 기존 재사용 규칙과 명시적 새 탭 열기·URL 보존은 유지한다. 개선 대상은 확장의 탭 열기 준비와 사용자 피드백이며 원본 사이트의 네트워크·문서 로딩 속도 자체를 보장하지 않는다.

`+ 그룹`은 테마 강조색을 사용하는 보조 버튼으로 바꾸어 주요 **링크 추가** 버튼과 위계를 나누되 회색 안내처럼 보이지 않게 한다. 그룹색·배경·전체 테마·저장 형식·권한·확장 ID는 유지한다. 당시 검증 결과는 [0.1.23 QA](QA-0.1.23.md)에 보존하며 모의 Chrome API 측정·localhost 화면·실제 확장 실행 결과를 서로 구분한다.

### 역사 기록: 0.1.22 — 그룹의 연한 배경

색을 지정한 그룹은 제목과 직접 속한 링크를 같은 연한 배경으로 감싼다. 사용자 지정 테마의 기본 배경에 그룹색을 최대 8% 섞어 불투명한 색으로 계산하고, 글자·상태·포커스 대비를 유지하기 위해 필요하면 농도를 줄인다. 중첩 그룹도 기본 테마 배경을 기준으로 각각 계산하므로 상위 색이 누적되지 않는다. 색을 지정하지 않은 하위 그룹은 중성 기본 배경을 사용한다.

접힘·펼침·검색에서 그룹 구분을 유지하며 현재 페이지 강조·포커스·메뉴를 가리지 않는다. schema 2·색상 저장 방식·테마 설정·권한·확장 ID는 변경하지 않고 표시만 개선한다. 당시 검증 결과와 미검증 범위는 [0.1.22 QA](QA-0.1.22.md)에 보존한다.

### 역사 기록: 0.1.21 — 그룹 색상과 테마 팔레트 아이콘

상단 **테마** 버튼은 기존 텍스트 이름과 함께 팔레트 아이콘을 표시한다. 각 그룹의 **더보기 → 그룹 색상**에서 색상 선택기·HEX 입력으로 색을 고른다. **저장**으로 확정하고 취소·닫기는 기존 색을 유지한다. **기본 색상**은 편집 중인 색 지정만 해제하며 저장해야 확정된다. 색은 이름 옆 표식과 해당 그룹의 트리 연결선에 표시하고 이름·폴딩 표시를 함께 유지한다. 상위·하위 그룹은 독립적으로 색을 가지며, 색을 지정하지 않은 하위 그룹이 상위 색을 자동으로 물려받지 않는다. 미분류 그룹의 색은 변경 가능하지만 이름 변경·이동·삭제 보호는 유지한다.

그룹 색상은 schema 2 Group의 선택적 `color` 필드에 `#rrggbb`로 저장한다. 색이 없는 기존 그룹에는 필드를 추가하지 않는다. 그룹 이름·링크·위치·하위 구조를 바꾸지 않고, 보관함 이동·되돌리기·JSON 백업·복원으로 색을 보존한다. 기존 색상 없는 schema 1·2 백업은 읽을 수 있다. **색상 필드가 있는 백업은 0.1.20 이하의 엄격한 검증에서 거부되므로 0.1.21 이상에서 복원해야 한다.** 색을 지정한 저장소 위에 구버전을 덮어씌우는 다운그레이드는 지원하지 않으며 업데이트 전 백업 보관을 안내한다.

프로필 전체 테마는 기존 별도 저장 계약을 유지하며 그룹 색상과 합치지 않는다. 추가 권한·로그인·네트워크 요청 없이 구현하고, 공개키·확장 ID와 Notion 전용 기능의 종료 상태를 유지한다. 당시 검증 결과와 한계는 [0.1.21 QA](QA-0.1.21.md)에 보존한다. 후속 제안은 **고정·최근 링크 빠른 접근**과 **키보드 위치 이동 개선**이며 이번 구현 범위가 아니다.

### 역사 기록: 0.1.20 — 사용자 지정 테마

사이드 패널 상단 **테마**에서 **시스템 설정·밝게·어둡게** 모드, 여섯 가지 색상 조합, 사용자 지정 강조색·밝은 배경·어두운 배경을 제공한다. 색상 선택기와 HEX 입력을 함께 제공하고 잘못된 색은 저장하지 않는다. 편집 중인 색을 패널에 미리 적용하며 **저장**만 영구 설정을 바꾼다. 취소·닫기는 저장 전 설정으로 돌아간다. **기본 테마로** 역시 편집 미리보기만 기본값으로 바꾸며 저장해야 확정된다.

글자·버튼·포커스의 색은 배경과의 대비를 계산해 정한다. 선택·현재 위치·오류는 색상 외 텍스트·테두리·표시 상태를 함께 사용한다. 시스템 모드에서만 운영체제 밝기 변경을 따른다. 설정은 이 Chrome 프로필의 모든 FAVMOA 보관함에 공통으로 적용하며 catalog·undo·복원 사본·기존 `nfs:` 데이터와 분리한다. 링크 JSON에는 테마를 넣지 않으며 목록 복원·목록 초기화도 테마를 바꾸지 않는다. 테마 변경을 위해 로그인·네트워크 요청·추가 권한을 도입하지 않는다.

재귀 그룹·일반 링크·로컬 저장·JSON 백업, 확장 공개키·ID·권한을 유지한다. Notion 전용 화면과 DOM 수집은 종료 상태이며 Google 로그인·Drive 동기화는 계속 보류한다. 당시 검증 결과와 미검증 범위는 [0.1.20 QA](QA-0.1.20.md)에 보존하며 현행 버전의 검증 결과로 재사용하지 않는다.

### 역사 기록: 0.1.19 — Notion 전용 화면 종료

Notion 안의 FAVMOA 메뉴·내부 화면·즐겨찾기 및 하위 계층의 DOM 수집을 제거한다. 기본 진입점은 Chrome 도구 모음의 확장 아이콘으로 여는 범용 사이드 패널 하나다. Notion 페이지는 일반 HTTP(S) 링크로 저장하고 원본에서 열며, 다른 서비스 링크와 같은 규칙으로 열린 탭을 재사용한다.

기존 `nfs:` 트리·제목 캐시·저장 키를 지우지 않는다. 사용자가 **기존 Moa 목록 가져오기**를 실행할 때만 새 보관함으로 복사하며 자동 이전·양방향 동기화하지 않는다. 범용 schema 2·확장 공개키·ID·로컬 저장·JSON 백업·Google 보류 정책은 유지한다. 업데이트 뒤 확장을 다시 로드하고 기존 Notion 탭을 새로고침하면 이전 버전이 넣은 UI가 사라진다. 검증 결과와 한계는 [0.1.19 QA](QA-0.1.19.md)에 기록하고, 과거 테스트 숫자를 이번 검증으로 재사용하지 않는다.

### 역사 기록: 0.1.18 — 확인한 Notion 주소 보존·미확인 주소 열기 방지

공유 URL 처리기로 어댑터·표시 화면·메타데이터의 Notion 주소 판정을 일치시킨다. 현재 페이지의 실제 주소를 우선하고, 관찰한 같은 page ID의 안전한 Notion URL을 최대 4,096자의 선택적 `href`로 표시 캐시에 보존한다. 주소 없는 기존 캐시와 하위 호환되며, 새 정보가 ID만 있는 주소이거나 주소를 생략해도 이미 아는 전체 경로는 유지한다. 알려진 주소가 전혀 없으면 링크 열기를 비활성화하고 원본 Notion 페이지나 즐겨찾기를 열어 주소를 확인하도록 안내한다. 워크스페이스 경로를 추측하거나 page ID만으로 주소를 만들지 않는다. 하위 페이지 관계는 화면에서 관찰한 범위만 사용한다.

범용 schema 2·관리 트리·저장 키·확장 공개키·ID·권한과 로컬 저장·JSON 백업·Google 보류 정책은 유지한다. 이번 검증 결과와 한계는 [0.1.18 QA](QA-0.1.18.md)에 별도로 기록하며, 아래 과거 버전의 통과 숫자를 재사용하지 않는다.

### 과거 0.1.17 변경 — 현재 Notion 페이지의 전체 경로 보존

현재 Notion 페이지의 주소를 ID만으로 재구성하면서 원래 경로를 잃는 동작을 수정한다. 관찰한 현재 페이지의 전체 경로를 유지하며 기존 사용자 데이터·schema 2·저장 키·확장 공개키·ID·권한은 바꾸지 않는다. 재귀 그룹과 로컬 저장·JSON 백업, Google 연결 보류 정책은 0.1.16과 동일하다. 이번 검증 결과와 한계는 [0.1.17 QA](QA-0.1.17.md)에 별도로 기록하며 아래 과거 버전의 통과 숫자를 재사용하지 않는다.

### 과거 0.1.16 변경 — 그룹 안에 그룹과 링크

범용 링크 보관함의 사용자 분류를 **재귀 그룹**으로 통일한다. 각 Group은 `groups`와 `links`를 함께 가지며 링크를 직접 담을 수 있다. 별도 Section 모델은 없앤다. 이 절과 4.1절의 schema 2 결정이 과거 버전의 두 단계 모델 설명보다 우선한다. [재귀 그룹 전환](RECURSIVE-GROUPS-0.1.16.md)과 [0.1.16 QA](QA-0.1.16.md)에 구현·검증 범위를 기록했다. 새 전체 Node 검사 367/367과 localhost 합성 흐름·ZIP 검증은 통과했지만, 실제 설치 데이터·실계정·파일 선택 업로드는 미검증이다. 구형 브라우저 suite는 최초 7/8, 개별 검사 19/19, 전체 재실행 8/8이었으며 최초 간헐 실패의 원인은 미확정이다.

- 그룹·하위 그룹 생성, 독립 접기, 링크 직접 추가·이동, 내용물 전체를 보존하는 그룹 이동을 제공한다. 자기 자신·자손 안으로 이동하는 순환 구조는 허용하지 않는다.
- 보호된 최상위 미분류 그룹은 이름 변경·삭제·이동을 금지하되 링크·하위 그룹은 담을 수 있다. 사용자 그룹을 삭제하면 링크·하위 그룹을 부모로 올리고, 최상위 사용자 그룹의 내용은 미분류 그룹으로 옮긴다.
- schema 1의 사용자 섹션은 하위 그룹으로 변환한다. 시스템 ID로 식별한 자동 미분류 섹션의 링크는 부모 그룹에 직접 둔다. 이름이 같다는 이유만으로 사용자 섹션을 합치지 않는다.
- GET은 새 모델로 읽기만 하고 원본을 다시 쓰지 않는다. 첫 실제 변경의 성공적인 저장 때 구형 catalog·undo·복원 사본을 `favmoa:schema-v1-backup:v1`에 보존하고 schema 2를 저장한다. no-op·실패는 이전 완료가 아니다. 일반 undo·복원 사본도 schema 2로 정규화한다.
- 구형 JSON 백업은 가져올 수 있지만 새 schema 2 백업은 0.1.15 이하에서 읽을 수 없다. 자동 다운그레이드는 지원하지 않으므로 업데이트 전 JSON을 별도로 보관하도록 안내한다. 새 버전 이후 편집은 이전 백업에 포함되지 않는다.
- 0.1.15의 디자인, 확장 공개키·고정 ID·권한·기존 저장 키를 유지한다. 구형 Notion 내부 화면은 별도 그룹·섹션 호환 화면으로 남기고 원본 저장소는 바꾸지 않는다. 명시적 가져오기만 새 모델의 복사본을 만든다.
- Google 로그인·Drive 동기화와 Drive 하위 API 탐색은 계속 보류한다. 실제 계정 연결을 재개하지 않는다.

### 과거 0.1.14 변경 — 로컬 우선·입력 단순화·복원 안전성

사용자가 Google 연결을 보류하기로 결정했다. 아래 클라우드 동기화·Drive 하위 탐색 요구는 **장기 목표로 보류**하며 0.1.14 출시 조건이 아니다. Google 설정·로그인을 다시 진행하지 않는다. 이 절이 과거 버전 설명보다 우선한다.

- 로그인 UI와 실행 경로를 제외하고 로컬 저장·JSON 백업을 기본 흐름으로 통일한다. Google 인증·API 권한을 배포 manifest에서 제거한다. 공개 설정과 구현은 소스에만 보존하며 ZIP에서 제외한다.
- 링크 추가는 주소 우선, 이름 선택, 저장 위치 접기로 단순화한다. 도메인 입력은 HTTPS로 정규화하며 안전하지 않은 주소는 기존 검증 기준으로 차단한다.
- 백업 화면을 상단 버튼에서 바로 연다. 가져오기는 전체 교체임을 알리고 현재/가져올 링크 수를 비교하며 취소와 사전 JSON 내보내기를 제공한다.
- 실제 교체 전 목록 1개를 전용 안전 사본으로 저장한다. 일반 편집·접기·되돌리기는 이를 지우지 않는다. 새 교체는 사본을 갱신하고 동일 목록 가져오기는 보존한다. 명시적 복구는 사본을 소비하며 복구 자체는 다음 변경 전까지 일반 되돌리기로 취소할 수 있다.
- 기존 확장 ID·저장 키·사용자 분류는 유지한다. 현재 catalog, 일반 undo, 복원 사본으로 저장 용량이 늘 수 있으며 저장 실패 시 기존 데이터를 유지한다.

근거·사용자 스토리·검증 범위는 [사용성 점검](UX-AUDIT-0.1.14.md)과 [0.1.14 QA](QA-0.1.14.md)에 기록한다. 실사용자 연구, 실제 설치 갱신·권한·열린 탭 동작은 로컬 미리보기와 구분한다.

실제 Chrome에서 Google 동의 창 없이 인증이 실패하는 흐름을 재현했으며, 0.1.13에서도 `AUTH_FAILED` / `authorization`으로 실패가 계속됩니다. 원본 오류와 Google Cloud 설정은 확인하지 못했으므로 원인을 확정하거나 인증이 고쳐졌다고 주장하지 않습니다. 로컬 또는 모의 응답 검증은 실제 인증·Drive 접근을 대신하지 않습니다. 공개키·고정 확장 ID·OAuth 클라이언트·권한 범위·저장 키는 유지하며 자동 동기화·Drive 하위 폴더 탐색은 이번 범위가 아닙니다.

### 0.1.12 변경 — OAuth 클라이언트 설정 반영

사용자가 새로 제공한 공개 클라이언트 ID `24454578838-6nqb1s33u6djs6inpn2jud1nfq0ojevn.apps.googleusercontent.com`을 manifest에 반영합니다. 고정 확장 ID **ebbgmhdbonpillbfjapebljagnbjembj**와 공개키는 0.1.11과 동일하며, 0.1.11 사용자는 같은 설치 폴더에서 업데이트하고 새로고침합니다. OAuth 범위는 `openid`, `email`, `https://www.googleapis.com/auth/drive.appdata`로 제한하고 client secret은 포함하지 않습니다.

이는 **설정 반영이지 실연동 완료가 아닙니다.** Google Cloud 콘솔의 실제 Chrome Extension 유형·Item ID 연결, Drive API 활성화, OAuth 동의 화면·테스트 사용자, 조직 정책은 직접 확인하지 않았습니다. 실제 Chrome 확장에서 사용자 동의를 거친 로그인과 수동 Drive 백업·목록·복원, 다른 PC 복원도 미검증입니다. localhost 데모로 실인증을 검증하지 않습니다. 연결만으로 보관함을 업로드하지 않으며 계정을 확인한 뒤 별도의 수동 백업을 실행합니다. 자동 동기화·Drive 하위 폴더 탐색은 계속 미구현이고, Google 연결은 Notion 로그인이나 원본 접근 권한을 대신하지 않습니다.

### 0.1.11 변경 — 개발용 확장 ID 고정

manifest 공개키로 **ebbgmhdbonpillbfjapebljagnbjembj**를 고정합니다. 빌드 시 승인된 ID·공개키 SHA-256을 대조하고, 키 누락·변경은 배포를 차단합니다. 이 값은 OAuth 클라이언트 ID가 아니며 웹스토어 ID 확보나 Google 인증 완료를 뜻하지 않습니다. 공개키만 배포하고 서명 개인키는 로컬 비공개·Git 제외 경로에 보관합니다.

키 없는 0.1.10 이하와 ID가 달라지므로 첫 전환은 **구형 설치에서 JSON 내보내기 → 0.1.11 별도 설치 → JSON 가져오기**입니다. 0.1.9는 원래 설치 경로에서 키 없는 0.1.10으로 먼저 업데이트하여 기존 Moa 트리를 범용 보관함으로 복사한 뒤 내보냅니다. 기존 확장은 삭제·초기화하지 않습니다. ID가 같아져도 다른 PC의 로컬 데이터는 자동 동기화되지 않습니다. 상세 절차와 웹스토어 전환 주의 사항은 [ID 고정 안내](EXTENSION-IDENTITY.md)에 있습니다. 아래 0.1.10 기능 범위와 미구현 사항은 그대로 유지됩니다.

### 0.1.10부터의 구현 범위 — 전체 PRD 완료 아님

0.1.10은 FAVMOA 이름, 범용 사이드 패널, 로컬 그룹·섹션·링크 보관함, 현재 페이지와 열린 탭 연결, 선택 북마크 가져오기, 기존 Moa 트리의 비파괴 복사, 로컬 백업·복원과 되돌리기를 도입했습니다. 기존 Notion 내부 화면은 호환 유지합니다. Google 기능 코드는 선택 연결 후 **Drive 앱 데이터 수동 스냅샷 백업·목록·복원**으로 제한합니다. 0.1.10·0.1.11 배포본은 OAuth 미설정이었고, 0.1.12에서 설정을 추가했으나 실연동은 미검증입니다. 자동 기기 간 동기화나 원격 동시 수정 병합도 제공하지 않습니다.

처음 사용자 제공 OAuth 클라이언트는 웹 애플리케이션용으로 확인되어 0.1.10·0.1.11 manifest에 포함하지 않았습니다. 새 클라이언트를 반영한 0.1.12도 Google Cloud의 **Chrome Extension 유형**, 실제 등록 확장 ID·테스트 사용자 설정이 맞는지 검증해야 합니다. 클라이언트 secret은 포함하지 않습니다. 코드·로컬 테스트만으로 실계정 인증과 실제 Drive 데이터 접근을 검증했다고 처리하지 않습니다. 일반 Drive 파일 조회 scope는 요청하지 않으며 **Drive 하위 폴더 API 탐색, 자동 동기화·삭제 전파·계정 간 병합은 아직 미구현**입니다. 기존 트리를 가져온 뒤 Notion 내부 화면과 범용 보관함은 독립적으로 수정되며 양방향 동기화하지 않습니다. 아래 동기화와 서비스 탐색 관련 사용자 스토리·수용 기준은 계속 목표로 남습니다.

0.1.10의 로컬 catalog 한도는 간결한 UTF-8 JSON 기준 5MiB, 백업 파일 가져오기는 포장 정보를 포함한 파일 기준 6MiB이며 파싱 후 catalog 검증을 다시 적용합니다. Drive 수동 스냅샷 백업·읽기는 별도의 4MiB 한도를 둡니다. 1MiB는 1,048,576바이트입니다. 복원은 전체 보관함 교체이고 자동 병합이 아닙니다. 한도 초과·검증 실패 시 현재 로컬 목록을 유지해야 하며, 로컬에서 유효하지만 Drive 한도를 초과하는 데이터는 JSON으로 보관할 수 있어야 합니다. 코드/모의 응답 테스트와 로컬 데모 결과를 실제 Chrome 확장 설치·Google 인증·다른 PC 복원 완료로 취급하지 않습니다.

> 저장한 주소를 다시 찾는 데서 끝나지 않고, 지금 하는 일의 관련 링크와 서비스 내부 구조를 같은 트리에서 탐색한다.

## 1. Problem Statement — 문제 정의

### 1.1 사용자 문제

하나의 업무에 필요한 자료가 Notion, Google Drive, Slack, GitHub 등 여러 서비스에 흩어져 있다. 사용자는 주소를 기억하는 것뿐 아니라, 현재 문서가 어느 업무에 속하는지 확인하고 다음 자료로 이동하며 이미 열어 둔 탭을 다시 찾는 일을 반복한다.

기본 북마크의 폴더 정리만으로도 단순 링크 보관은 해결된다. Chrome은 북마크 검색·탐색 패널·기기 간 이용을 제공하고, 탭 그룹도 지원한다. 따라서 중첩 폴딩이나 프로젝트별 분류 자체를 독점적 차별점으로 주장하지 않는다. [Chrome 북마크](https://support.google.com/chrome/answer/188842?hl=ko), [Chrome 탭 관리](https://support.google.com/chrome/answer/2391819?hl=ko)

Moa의 출발점은 Notion 즐겨찾기 정리였지만, 이를 Notion 안에서만 사용하면 다른 서비스로 이동했을 때 같은 탐색 체계를 이어갈 수 없다. 현재 로컬 전용 저장은 다른 PC에서 구조를 다시 만드는 문제도 남긴다.

### 1.2 대상과 사용 상황

- 여러 웹 서비스를 오가며 프로젝트·고객·개인 업무를 수행하는 개인 사용자.
- 회사 PC와 개인 PC 등 둘 이상의 Chrome 환경에서 자신의 정리 구조를 이어서 쓰려는 사용자.
- 원본 서비스의 폴더·페이지 위치나 팀 공유 권한은 변경하지 않고 개인용 탐색 구조만 만들려는 사용자.
- 단순 링크 몇 개만 저장하는 사용자에게는 기본 북마크가 충분할 수 있다. 이들을 위해 기능을 과도하게 늘리지 않는다.

### 1.3 해결해야 할 핵심 질문

1. 지금 보고 있는 페이지가 내 트리의 어디에 있는가?
2. 같은 업무의 다른 서비스 링크로 얼마나 쉽게 이동할 수 있는가?
3. 저장한 폴더·페이지 아래에 무엇이 있으며, 그 원본으로 바로 이동할 수 있는가?
4. 다른 PC에서도 같은 링크와 분류를 안전하게 복원할 수 있는가?

## 2. Solution — 제품 방향과 범위

### 2.1 제안

Chrome 사이드 패널에 `그룹 → 하위 그룹 → …`를 두고 각 그룹에 링크를 직접 담는다. 현재 페이지를 강조하고, 이미 열려 있는 링크는 기존 탭으로 이동한다. Drive 폴더의 실제 하위 조회는 보류한 장기 목표다. Notion 전용 내부 화면과 DOM 기반 하위 탐색은 종료하고 일반 링크 저장·열기만 제공한다.

장기 목표는 Google 연결을 선택한 사용자의 관리 트리를 자신의 Google Drive 앱 데이터 영역에 동기화하는 것이다. **현재 0.1.37은 로컬 저장과 JSON 백업만 제공한다.** Google 로그인만으로 자동 동기화되는 것이 아니라 저장·조회·충돌 처리와 실연동 검증이 필요하다.

### 2.2 현재와 목표 구분

| 영역 | 확인한 Moa 0.1.9 | 이 PRD의 목표 |
|---|---|---|
| 기본 화면 | Notion 수신함 옆 내부 화면 | 사이트와 무관한 Chrome 사이드 패널 |
| 관리 대상 | Notion page ID 기반 즐겨찾기 | HTTP(S) 링크, 서비스별 식별 정보 |
| 사용자 분류 | 그룹·섹션·즐겨찾기, 독립 폴딩 | 재귀 그룹·직접 링크, 기존 섹션의 하위 그룹 변환 |
| 현재 위치 | 현재 Notion 페이지와 관찰한 경로 | 현재 브라우저 페이지와 저장 위치 |
| 열린 탭 연결 | 범용 탭 매칭 없음 | 열린 상태 표시, 기존 탭으로 전환 |
| 하위 탐색 | 현재 렌더된 Notion 계층 | Notion 전용 탐색 종료, Drive 폴더 조회는 보류 |
| 저장 | 워크스페이스별 브라우저 로컬 | 로컬 우선 + 선택적 Drive 동기화 |
| 별도 인증 | 없음 | 동기화용 Google 연결, 별도 탐색 권한 |

위 표의 **Moa 0.1.9 기준선**은 명시적 권한이 `storage`였고 Google OAuth 설정이 없었다. 현재 FAVMOA 0.1.37은 `storage`, `sidePanel`, `tabs`, 선택 `bookmarks`를 유지하고 사이트 콘텐츠 스크립트는 없다. `identity`, Google API 호스트 접근, OAuth 설정은 0.1.14부터 배포에서 제외한다. 현재 설치 범위는 문서 상단의 버전별 변경 및 README를 따른다. 기존 로컬 탭 간 revision 검사는 여러 PC 사이의 충돌 해결을 증명하지 않는다.

### 2.3 전체 제품 목표 — 클라우드 항목은 보류

- 로그인 없이 사용 가능한 링크 등록·정리·검색, 중첩 그룹의 독립 접기와 하위 트리 이동.
- 현재 페이지 카드, 저장 위치 강조, 열린 탭 표시와 기존 탭 전환.
- Google 연결, Drive 앱 데이터 동기화, 다른 PC에서 복원, 오프라인·재시도·충돌 표시.
- 선택한 Drive 폴더를 시작점으로 하위 폴더·파일 읽기 전용 탐색. **조회 권한과 검증이 준비되지 않으면 연결 완료로 표시하지 않는다.**
- 종료된 Notion 화면의 로컬 저장 데이터는 보존하고 명시적 가져오기로만 복사. 새 DOM 수집·전용 탐색은 제공하지 않음.
- Moa 0.1.9 데이터의 비파괴 이전과 백업·복원 경로.

개발은 단계적으로 배포할 수 있지만, Drive 탐색 없이 배포한 중간 버전을 이 PRD 전체 완료로 처리하지 않는다.

### 2.4 대표 사용자 흐름

**처음 사용:** 확장 설치 → 패널 열기 → 그룹 또는 하위 그룹 선택 → 현재 페이지 추가. 현재 버전은 로그인 절차 없이 로컬로 시작한다.

**업무 중 이동:** 프로젝트 기획서 열기 → 패널에서 해당 링크와 조상 그룹 경로 강조 → 같은 그룹의 Slack 링크 선택 → 이미 열려 있으면 해당 탭으로 이동. 연관성은 사용자가 정한 분류에 근거하며 AI가 임의로 추정하지 않는다.

**Drive 폴더 탐색 — 보류한 목표:** 폴더 URL 추가 → 펼침 클릭 → 필요한 탐색 권한 안내·승인 → 하위 항목 조회 → 하위 폴더 펼침 또는 파일 이름을 클릭해 원본 열기. 자식 항목은 즐겨찾기에 자동 추가되지 않는다.

**다른 PC에서 복원 — 현재:** 원래 PC에서 JSON 백업 저장 → 다른 PC에 같은 또는 호환되는 최신 버전 설치 → 백업 내용 확인 후 전체 목록 교체 → 링크 열기. 비공개 원본은 해당 서비스 로그인과 접근 권한이 필요하다. Google 계정 기반 원격 복원은 보류한 목표이며 원본 로그인 상태는 복사하지 않는다.

### 2.5 성공 기준 — 목표이며 아직 측정하지 않음

- 처음 사용하는 테스트 참여자가 안내 후 3분 안에 그룹·하위 그룹 생성과 링크 3개 등록을 완료한다.
- 등록된 업무 링크 사이 이동에서 중복 탭 생성 없이 기존 탭으로 전환할 수 있다.
- 장기 동기화 목표: 서로 다른 PC의 두 Chrome 프로필에서 정상 동기화 후 재귀 그룹·링크의 논리적 데이터가 일치한다. 현재는 JSON 이전 경로를 검증한다.
- 오프라인·동시 수정·재시도·계정 전환 검사에서 확인 없이 관리 데이터가 유실되거나 다른 계정에 업로드되지 않는다.
- 성능 제안 목표: 1,000개 저장 링크에서 로컬 패널 첫 유용 화면 500ms 이내, 로컬 검색 p95 100ms 이내. 출시 전 테스트 기기와 측정 조건을 고정해 검증한다.
- 정상 네트워크·유효한 인증·두 클라이언트 활성 상태에서 원격 변경 인지 목표 30초 이내. 브라우저 종료·OS 절전 중에는 보장하지 않는다.
- 기본 원격 분석 수집은 하지 않는다. 초기 사용성 수치는 동의한 테스트 세션에서 측정한다.

## 3. User Stories — 사용자 요구

형식은 ‘어떤 사용자로서, 어떤 이익을 얻을 수 있도록, 무엇을 하고 싶다’이다.

1. 처음 쓰는 사용자로서, 설치 직후 가치를 확인할 수 있도록 로그인 없이 링크를 저장하고 싶다.
2. 업무 사용자로서, 서비스가 바뀌어도 분류를 유지할 수 있도록 같은 사이드 패널을 계속 사용하고 싶다.
3. 사용자로서, 내 업무 방식으로 정리할 수 있도록 그룹 안에 하위 그룹과 링크를 함께 만들고 이름을 바꾸고 싶다.
4. 사용자로서, 지금 필요 없는 내용을 줄일 수 있도록 각 그룹을 독립적으로 접고 싶다.
5. 사용자로서, 준비 중인 분류를 보존할 수 있도록 빈 그룹과 하위 그룹도 유지하고 싶다.
6. 사용자로서, 복사·붙여넣기를 줄일 수 있도록 현재 페이지의 제목과 주소를 확인하고 저장하고 싶다.
7. 사용자로서, 아직 열지 않은 자료도 정리할 수 있도록 URL을 직접 입력하고 싶다.
8. 사용자로서, 기존 정리를 재사용할 수 있도록 Chrome 북마크를 선택해서 가져오고 싶다.
9. 기존 Moa 사용자로서, Notion 전용 화면이 종료되어도 저장된 그룹·섹션을 잃지 않고 원하는 때에 범용 그룹 구조로 복사하고 싶다.
10. 사용자로서, 중복 정리를 피할 수 있도록 이미 저장한 링크의 위치를 안내받고 싶다.
11. 사용자로서, 분류가 바뀌면 링크를 옮기거나 그룹과 그 하위 트리를 함께 이동하고 순서를 바꾸고 싶다.
12. 사용자로서, 긴 트리를 훑지 않도록 제목·주소·그룹 경로로 저장 항목을 검색하고 싶다.
13. 사용자로서, 현재 페이지의 업무 맥락을 알 수 있도록 트리에서 내 위치를 강조받고 싶다.
14. 사용자로서, 화면이 의도와 다르게 계속 펼쳐지지 않도록 내가 다시 접은 상태를 존중받고 싶다.
15. 여러 탭을 쓰는 사용자로서, 같은 페이지를 중복으로 열지 않도록 열린 링크를 구분하고 기존 탭으로 이동하고 싶다.
16. 사용자로서, 비교 작업이 필요할 때는 기존 탭이 있어도 명시적으로 새 탭에서 열고 싶다.
17. Drive 사용자로서, 저장한 폴더 안의 자료를 찾을 수 있도록 하위 폴더와 파일을 펼쳐 보고 싶다.
18. Drive 사용자로서, 탐색 속도를 유지할 수 있도록 펼친 폴더부터 단계적으로 조회하고 싶다.
19. Drive 사용자로서, 파일이 많은 폴더도 누락 없이 확인하도록 다음 항목을 추가로 불러오고 싶다.
20. 사용자로서, 자주 쓰는 하위 파일만 내 분류에 남길 수 있도록 탐색 항목을 명시적으로 링크에 추가하고 싶다.
21. Notion 사용자로서, 별도 전용 화면 없이 원본 페이지 주소를 저장하고 같은 Chrome 사이드 패널에서 열고 싶다.
22. 사용자로서, 목록이 비어 보이는 이유를 알 수 있도록 미조회·빈 폴더·부분 조회·권한 부족을 구분하고 싶다.
23. 여러 PC를 쓰는 사용자로서, 같은 Google 계정으로 연결하면 같은 보관함을 복원하고 싶다.
24. 사용자로서, 회사 자료가 어느 계정에 저장되는지 알 수 있도록 동기화 계정과 전송 항목을 확인하고 싶다.
25. 사용자로서, 계정 연결 전에 만든 로컬 목록을 잃지 않도록 원격 목록과의 합치기 또는 분리 선택을 하고 싶다.
26. 사용자로서, 인터넷이 끊겨도 링크를 편집하고 연결 복구 뒤 동기화하고 싶다.
27. 사용자로서, 저장이 완료됐는지 판단할 수 있도록 로컬 저장과 클라우드 동기화 상태를 별도로 보고 싶다.
28. 사용자로서, 두 PC에서 같은 링크를 수정했을 때 어느 변경도 몰래 사라지지 않도록 충돌을 확인하고 선택하고 싶다.
29. 사용자로서, 삭제한 항목이 오래된 PC에서 되살아나지 않도록 삭제도 안전하게 반영되기를 원한다.
30. 사용자로서, 개인·회사 계정이 섞이지 않도록 계정을 바꿀 때 로컬 캐시와 대기 중인 변경도 분리되기를 원한다.
31. 사용자로서, Drive 폴더 읽기에 동의하지 않아도 내 링크 목록의 동기화는 계속 사용하고 싶다.
32. 사용자로서, 민감한 세션 정보가 복사되지 않도록 비밀번호·쿠키·토큰·열린 탭 목록은 동기화에서 제외하고 싶다.
33. 사용자로서, 원본 문서를 잃을 걱정 없이 FAVMOA에 저장한 바로가기만 제거하고 싶다.
34. 사용자로서, 실수를 복구할 수 있도록 최근 정리 작업을 되돌리고 데이터를 내보내고 싶다.
35. 사용자로서, 로컬 캐시 비우기·연결 해제·클라우드 삭제의 차이를 확인하고 필요한 작업만 실행하고 싶다.
36. 기존 Moa 사용자로서, 업데이트 후 기존 섹션이 하위 그룹으로 바뀌어도 이름·내용·배치·제목·아이콘을 잃지 않고 싶다.
37. 키보드 사용자로서, 드래그 없이 추가·이동·폴딩·메뉴·충돌 해결을 모두 수행하고 싶다.
38. 사용자로서, 좁은 패널·다크 테마·확대 화면에서도 항목 이름과 주요 버튼을 읽고 조작하고 싶다.
39. 사용자로서, 연결 권한이 만료돼도 저장한 목록은 보존하고 재연결하거나 원본을 직접 열고 싶다.
40. 사용자로서, 현재 PC의 열림 상태나 화면 위치가 다른 PC의 작업을 방해하지 않도록 기기별 작업 상태는 독립적으로 유지하고 싶다.
41. 사용자로서, 테마 설정을 빠르게 찾을 수 있도록 텍스트 옆에 알아보기 쉬운 팔레트 아이콘을 보고 싶다.
42. 사용자로서, 업무 묶음을 쉽게 구분하도록 그룹과 하위 그룹에 각각 색을 지정하고 이름과 함께 표시하고 싶다.
43. 사용자로서, 색 변경을 취소·되돌리거나 기본 표시로 복구해도 기존 링크와 분류는 유지하고, 백업을 옮길 때 그룹 색도 함께 보존하고 싶다.
44. 사용자로서, 같은 그룹에 속한 제목과 링크를 연한 배경으로 한눈에 구분하고, 중첩 그룹이나 어두운 테마에서도 글자를 편하게 읽고 싶다.
45. 사용자로서, 링크와 그룹을 다른 그룹으로 끌어 옮기고 잘못 옮겼으면 되돌리되, 키보드로도 같은 이동을 수행하고 싶다.
46. 사용자로서, 링크를 누른 직후 처리 중임을 알고 기다리는 동안 다시 눌러도 같은 탭이 중복으로 열리지 않기를 원한다.
47. 사용자로서, 그룹 추가가 비활성 안내처럼 보이지 않고 선택한 테마와 어울리는 조작 버튼으로 보이기를 원한다.
48. 사용자로서, 패널로 돌아와 링크를 처음 누르거나 드래그 후 다른 항목을 새로 눌러도 화면 갱신 때문에 클릭을 다시 하지 않기를 원한다.
49. 사용자로서, 링크를 누를 때 잠깐 나타나는 문구 때문에 제목이 줄거나 목록이 흔들리지 않고, 실패한 경우에만 분명한 안내를 보고 다시 시도하고 싶다.
50. 사용자로서, 새 보관함을 만든 직후 그 보관함이 선택되고 이전 검색어가 없어져 어디에 링크를 담을지 분명히 알고 싶다.
51. 키보드·스크린리더 사용자로서, 입력 오류가 생기면 잘못된 칸으로 바로 이동하고 오류 설명을 확인한 뒤 수정하고 싶다.
52. 사용자로서, 저장 중 바꾼 값이 저장됐다고 오해하지 않도록 입력과 버튼이 잠기고, 실패하면 작성한 내용을 잃지 않고 다시 편집하고 싶다.
53. 사용자로서, 여러 그룹의 링크를 명시적으로 선택해 한 번에 다른 그룹으로 옮기고, 실수하면 한 번에 되돌리고 싶다.
54. 사용자로서, 검색하거나 그룹을 접어도 선택한 링크를 잃지 않고 화면 밖 선택까지 확인한 뒤 이동하고 싶다.
55. 사용자로서, 선택 모드에서 제목을 눌렀을 때 새 탭이 열리거나 드래그가 시작되지 않고, 취소·오류·보관함 변경을 안전하게 처리하고 싶다.
56. 사용자로서, 여러 Chrome 창에 열어 둔 웹페이지 중 필요한 것만 골라 현재 보관함의 한 그룹에 한 번에 담고 원래 탭은 그대로 두고 싶다.
57. 사용자로서, 열린 탭의 제목·주소를 검색하고 보이는 결과만 전체 선택하되 숨겨진 선택과 이미 저장한 링크·중복 탭을 알아보고 싶다.
58. 사용자로서, 여러 탭을 담다가 오류가 나면 일부만 저장되지 않고, 성공한 추가 전체를 한 번의 되돌리기로 취소하고 싶다.
59. 사용자로서, 북마크를 제목·주소·폴더 경로로 찾고 표시된 항목을 한 번에 고르며 300개 이후 항목도 검색어를 추측하지 않고 더 보고 싶다.
60. 사용자로서, 북마크와 열린 탭을 고르는 동안 검색 밖 선택 수를 확인하고 검색어는 유지한 채 선택 전체를 한 번에 비우고 싶다.
61. 사용자로서, 북마크를 읽는 중 취소하거나 다른 작업을 시작해도 늦게 도착한 결과가 작성하던 내용을 덮지 않으며 처음 선택한 보관함에만 저장하고 싶다.
62. 사용자로서, 긴 북마크 제목이나 너무 많은 선택 때문에 마지막 단계에서 전체 작업이 실패하지 않도록 제목 정리와 선택 한도를 미리 적용받고, 저장 후 목적지 그룹을 바로 확인하고 싶다.
63. 사용자로서, 링크를 추가하거나 이동한 뒤 그룹을 접고 펼쳐 확인해도 마지막 내용 편집은 취소할 수 있고 내가 직접 바꾼 접힘 상태는 유지하고 싶다.
64. 사용자로서, 탭이나 북마크를 고른 뒤 다른 패널의 변경과 충돌해도 선택·검색어를 잃지 않고 최신 저장 목록을 읽어 검토한 뒤 직접 다시 저장하고 싶다.
65. 사용자로서, 충돌 확인 중 이미 저장된 선택의 제외 개수를 알고 삭제된 저장 위치는 직접 다시 고르며, 확인만으로 원본을 다시 읽거나 자동 저장하지 않기를 원한다.
66. 사용자로서, 링크를 추가·수정하거나 하나를 옮기다 충돌해도 입력을 잃지 않고 최신 저장 목록을 검토한 뒤 별도로 저장하고 싶다.
67. 사용자로서, 수정·이동하려던 링크의 내용이나 위치가 다른 창에서 바뀌었다면 최신 값을 명확히 보고 확인하며, 삭제된 링크가 몰래 다시 생기지 않기를 원한다.
68. 사용자로서, 링크·그룹 삭제나 보관함 초기화 중 다른 창의 변경과 충돌하면 최신 영향 범위를 확인한 뒤 직접 다시 실행하고 싶다.
69. 사용자로서, 그룹 삭제 뒤 내용이 보존될 위치를 확인하고, 원래 삭제 대상이나 보관함이 사라지면 다른 대상이 대신 처리되지 않기를 원한다.
70. 사용자로서, JSON 복원이 충돌해도 고른 파일을 유지하고 최신 현재 목록과 기존 안전 사본에 미치는 영향을 검토한 뒤 직접 다시 실행하고 싶다.
71. 사용자로서, 복원 전 목록 복구를 실행하기 전에 실제 안전 사본을 미리 보고, 사본이 없거나 손상되면 현재 목록을 그대로 유지하고 싶다.
72. 사용자로서, 기존 Moa 가져오기가 충돌하면 최신 현재 보관함을 검토하고 원본은 실행 시 읽는다는 한계를 확인한 뒤 직접 다시 가져오고 싶다.
73. 사용자로서, 가져온 보관함이 0개여도 처리 경고가 있다면 단순히 목록이 없다는 안내 대신 확인이 필요한 이유를 알고 싶다.

## 4. Implementation Decisions — 구현 결정과 제안

### 4.1 화면과 데이터 모델의 용어 일치

| 화면 명칭 | 도메인 모델 | 의미·소속 | 저장·동기화 |
|---|---|---|---|
| 보관함 | Library | 링크 트리의 논리적 저장 단위. 계정은 소유·동기화 경계이며 분류 단계가 아님 | 트리와 함께 저장 |
| 그룹·하위 그룹 | Group | 최상위는 Library, 하위는 정확히 한 Group에 속함. 직접 링크와 자식 그룹을 함께 소유 | 현재 이름·순서·접힘·내용·선택적 색상을 로컬 저장/JSON 보관 |
| 링크 | Link | 정확히 한 Group에 직접 속하는 명시적 저장 항목 | URL·제목·서비스 식별 정보·순서를 로컬 저장/JSON 보관 |
| 하위 항목 | SourceNode | Drive/Notion에서 조회한 실제 자식. 사용자 그룹이 아님 | 기본은 계정·서비스별 로컬 캐시 |
| 열린 탭 | OpenTab | 현재 Chrome 프로필의 실행 상태 | 메모리/기기 로컬, 동기화 제외 |

`보관함`은 데이터 이전을 구분하는 컨테이너이며 화면에서는 선택기로 다룬다. `하위 그룹`은 별도 엔티티가 아니라 자식 위치의 동일한 Group이다. canonical catalog는 `schemaVersion: 2`, `library.groups`, Group `{id, name, collapsed, groups: [], links: [], color?}`를 사용한다. 0.1.21에서 추가한 선택적 `color`는 엄격히 검증한 `#rrggbb`이며, 기본 색상은 이 필드를 제거해 표현한다. 별도 Section과 `sectionId`는 구형 이전·호환 경계에서만 허용한다. 일반 링크를 Favorite나 Notion pageId로 부르지 않는다.

**중요한 구분:** 사용자 그룹은 반복해서 중첩할 수 있지만 안전 상한은 최상위부터 32단계다. 이는 권장 탐색 깊이가 아니다. 원본 폴더 링크 아래 실제 하위 폴더는 별도 읽기 전용 SourceNode 탐색이며 사용자 Group을 생성하는 동작이 아니다. 시스템 미분류 그룹은 최상위에 보호하고, 이동 대상에서 자기 자신과 모든 자손을 제외한다. 사용자 그룹 삭제는 하위 그룹·링크를 부모 또는 최상위 미분류 그룹으로 올려 보존한다.

### 4.2 관리 데이터와 원본 정보

- Link는 안정적인 자체 ID, 목적지 URL, 표시 제목, 선택적 사용자 별칭, 서비스 유형, 선택적 원본 리소스 ID와 서비스 맥락, 그룹 내 링크 순서를 가진다.
- 사용자가 지정한 별칭은 원본 제목 갱신으로 덮어쓰지 않는다. 원본 제목·아이콘·관찰 시각은 별도 메타데이터다.
- 사용자 관리 구조, 원본 탐색 캐시, 기기 화면 상태, 인증 상태, 동기화 상태를 분리한다.
- SourceNode 조회는 트리 revision이나 저장 링크 수를 변경하지 않는다. ‘링크에 추가’를 실행해야 Link가 생긴다.
- UI에는 이모지/아이콘을 한 번만 표시한다. 아이콘 부재·이미지 로딩 실패 시 크기가 고정된 안전한 대체 아이콘을 사용한다.
- 기본 중복 정책 제안: 한 보관함에서 동일한 목적지 식별자는 관리 링크 하나만 갖는다. 재추가 시 기존 위치로 이동하거나 기존 링크를 옮기도록 안내한다. 여러 프로젝트에 같은 링크를 복제하는 기능은 후속 검토다.
- 목적지 식별자는 서비스 유형·원본 리소스·필요한 계정/워크스페이스 맥락을 고려한다. 알 수 없는 일반 URL의 쿼리·해시를 일괄 삭제해 서로 다른 페이지를 합치지 않는다.
- HTTP(S)만 기본 허용한다. 실행 스킴, URL 내 사용자명·비밀번호, 잘못된 URL은 거부한다. 인식 가능한 인증 콜백과 access/refresh token 등 자격 정보가 포함된 URL도 차단한다. 임의 URL에 숨은 모든 비밀정보를 검출한다고 보장하지 않으며, 인증용·일회성 링크의 위험을 안내하고 저장·최초 업로드 전에 제목과 URL을 확인할 수 있게 한다.

### 4.3 패널·링크·열린 탭 UX

- 기본 진입점은 확장 아이콘으로 여는 Chrome 사이드 패널 하나다. Notion에 메뉴·화면을 주입하지 않는다. 종료된 전용 화면의 데이터는 보존하며 명시적 가져오기만 새 범용 트리에 복사한다. 자동 이전·양방향 동기화하지 않는다.
- 현재 패널 상단에는 현재 페이지, 검색, 링크 추가와 백업·테마 바로가기를 둔다. 클라우드 동기화 UI와 Notion 전용 목록 새로고침은 제공하지 않는다.
- 테마는 시스템/밝게/어둡게 모드와 색상 조합·사용자 지정 색을 제공한다. 편집 미리보기는 저장 전까지 임시 상태이며 취소 시 원래 설정으로 돌아간다. 테마 초기값 복원도 링크 초기화와 분리하고 저장으로 확정한다.
- 테마 버튼은 팔레트 아이콘과 텍스트를 함께 제공한다. 그룹 더보기의 **그룹 색상**은 하위 그룹·미분류 그룹에서도 사용할 수 있으며 이름 옆 표식·연결선·제목과 링크의 연한 배경에 분류 색을 표시한다. 각 배경은 기본 테마 배경에서 독립적으로 계산하여 중첩 시 농도가 누적되지 않고, 글자 대비가 필요한 경우 농도를 줄인다. 색이 없는 그룹은 기본 배경을 사용한다. 그룹 색은 독립적인 catalog 값이며 테마와 달리 JSON 백업·되돌리기에 포함된다.
- ‘현재 페이지 추가’는 제목·URL·대상 그룹 경로를 확인한 뒤 저장한다. 현재 페이지 카드에 보인다는 이유로 자동 저장하지 않는다.
- 그룹 제목은 폴딩, 링크 이름은 목적지 열기로 역할을 분리한다. 원본 하위 탐색이 제공되는 경우 그 펼침 조작과 분리한다.
- 링크·사용자 그룹의 드래그앤드롭은 같은 보관함의 그룹 안으로 이동하는 명령이다. 그룹은 최상위로도 이동한다. 드롭 대상의 표시와 기존 이동 메뉴를 함께 제공하며 순환·보호·깊이·오래된 revision 검사는 드래그에도 적용한다. 드래그 조작이 링크 열기로 이어지지 않도록 구분한다.
- 등록된 현재 링크의 조상 그룹 경로를 펼치고 강조한다. 조회된 자식의 부모 관계가 확인되면 그 경로도 표시한다. 확인하지 못한 부모를 추측하지 않는다.
- 자동 펼침은 페이지 식별자가 바뀔 때 적용한다. 같은 페이지에서 사용자가 다시 접으면 그 선택을 유지한다. 닫힌 패널을 탐색 때마다 강제로 열지 않는다.
- 같은 목적지가 열려 있으면 현재 창의 일치 탭을 우선하고, 없으면 같은 프로필 내 다른 창의 일치 탭으로 이동한다. 여러 후보의 선택 규칙은 결정적이어야 한다.
- 클릭 즉시 **여는 중** 상태를 표시하고, 같은 목적지의 일반 클릭이 처리 중이면 기존 요청에 합류한다. 탭 탐색의 독립 조회는 병렬로 실행하며 실패 뒤 재시도를 막지 않는다. 원본 사이트 로딩 시간과 확장 내부 준비 시간을 별도로 판단한다.
- 탭 갱신 결과가 화면상 같으면 트리 DOM을 교체하지 않는다. 포인터 누름부터 클릭 처리까지 실제 탭·보관함 갱신의 표시를 보류하고 이후 최신 상태를 반영한다. 드래그 종료 직후의 후행 클릭은 차단하지만 새로운 포인터 누름과 그 클릭은 받는다.
- 다른 서비스 계정에서 열린 탭을 같은 업무 탭이라고 단정하지 않는다. 식별이 불확실하면 자동 재사용 대신 후보 또는 새 탭 열기를 제공한다.
- ‘새 탭에서 열기’와 Ctrl/Cmd 클릭은 기존 탭이 있어도 새 탭을 만든다. 열린 탭 목록은 Drive에 저장하지 않는다.
- 기본 북마크 가져오기는 선택·미리보기·대상 지정 후 일회성 복사다. 원본 북마크를 이동·삭제하지 않으며 양방향 동기화하지 않는다.
- Tab·Enter·Space·방향키·Escape의 역할과 포커스 복귀를 정의한다. 이동 메뉴를 제공해 드래그를 필수로 만들지 않는다.
- 불투명 배경, 일관된 아이콘 폭, 긴 이름 말줄임과 전체 이름 확인, 빈 상태·로딩·오류 메시지를 제공한다.

Chrome Side Panel은 MV3/Chrome 114 이상이며 사용자 조작으로 여는 API는 116 이상이다. 목표 최소 버전은 **Chrome 116 이상으로 상향 제안**하되, 실제 사용 API별 최소 버전을 출시 전에 검사한다. 패널의 좌우 위치는 Chrome 설정을 존중한다. [공식 API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)

### 4.4 인증·계정·권한 경계 — 보류한 클라우드 목표 포함

1. **동기화용 Google 연결:** 사용자에게 선택된 계정과 업로드할 제목·URL·분류 정보를 안내하고 동의 후 시작한다. 서비스 로그인 상태와 별개다.
2. **Drive 폴더 탐색:** 동기화용 앱 데이터 권한과 별도 권한이다. 사용자가 Drive 폴더를 펼칠 때 추가 설명 후 요청한다. 거절해도 로컬 기능·허용된 앱 데이터 동기화는 유지한다.
3. **Notion 브라우저 로그인:** 해당 브라우저에서 비공개 원본 링크를 열기 위한 상태다. FAVMOA는 로그인이나 계층 수집을 대신하지 않는다. Google 연결로 Notion에 자동 로그인하거나 권한을 부여하지 않는다.
4. **Notion 공식 API:** 현재 범위 밖이다. 재검토 시 브라우저 로그인과 별도의 인증·페이지 접근 권한이 필요하며 기존 DOM 수집을 자동으로 재개하지 않는다. [Notion 인증](https://developers.notion.com/guides/get-started/authorization)
5. 클라우드 소유자는 이메일 문자열이나 Notion 워크스페이스명으로 추정하지 않는다. OAuth로 확인된 안정적인 계정 식별자로 로컬 저장·대기 작업·캐시를 분리한다.
6. MVP의 동기화와 Drive 탐색은 같은 선택 Google 계정을 사용한다는 제안이다. 서로 다른 Google 계정의 자료를 한 연결처럼 취급하지 않는다. Notion 계정은 독립이다.
7. 계정 전환 시 이전 계정의 요청·큐·토큰을 새 계정에서 재사용하지 않는다. 늦게 도착한 응답은 요청 당시의 계정·세대와 일치할 때만 적용한다.
8. 계정 전환 화면에는 로컬 대기 변경이 있음을 알리고 동기화·보존·취소 경로를 제공한다. 전환이 자동 업로드·자동 이전을 의미하지 않는다.

권한 설계 제안은 필수 `storage`, `sidePanel`, 사용자 선택 기능에 따른 `identity`, 열린 탭 조회용 권한, 북마크 가져오기용 `bookmarks`, 명시된 Google API 호스트 접근이다. `activeTab`만으로 모든 열린 탭의 URL 조회를 보장하지 않는다. 세부 manifest는 기능별 최소 권한 검증 후 확정하며 광범위한 모든 사이트 주입은 기본값으로 두지 않는다. [Chrome 탭 권한](https://developer.chrome.com/docs/extensions/reference/api/tabs), [Chrome 인증 API](https://developer.chrome.com/docs/extensions/reference/api/identity)

### 4.5 Drive 저장과 동기화 계약 — 보류한 목표

**저장 위치 결정:** 동기화는 사용자의 Google Drive `appDataFolder`를 우선 사용한다. 일반 Drive 목록에 보이는 북마크 파일이 아니며, 해당 앱 전용 숨김 공간이다. 별도 내보내기로 사용자가 읽을 수 있는 백업을 제공한다. 앱 데이터 권한은 다른 Drive 폴더 조회 권한을 포함하지 않는다. [공식 저장 방식](https://developers.google.com/workspace/drive/api/guides/appdata)

사용자가 Drive에서 앱 데이터를 외부 삭제할 수도 있다. 이 공간을 영구 보존이 보장되는 백업으로 설명하지 않으며, 동기화와 독립적인 내보내기·복구 경로를 유지한다.

**저장 내용:** 보관함·재귀 그룹·명시적으로 저장한 링크와 표시 정보, 데이터 스키마 버전, 병합에 필요한 변경 식별·삭제 기록. 확장이 취급하는 인증 자격 정보(로그인 비밀번호·쿠키·OAuth 토큰), 브라우저 탭 ID/목록, 방문 기록, 문서 본문, 임시 검색어, 원본 하위 트리 전체는 제외한다. 사용자 입력 URL의 비밀정보 위험은 4.2절의 검증·확인 절차로 별도 다룬다.

**화면 상태 정책 제안:** 기기별 현재 선택·스크롤·자동 펼침·현재 페이지는 로컬 전용이다. 그룹의 수동 접힘도 최초 이전값은 보존하되 이후 기기 로컬로 유지한다. ‘동일하게 복원’은 링크·분류·순서의 일치이지 두 PC의 실시간 화면을 강제로 같게 만드는 의미가 아니다. 현재 로컬 JSON 백업에는 그룹의 저장된 접힘 상태가 포함된다.

**로컬 우선:** 사용자 변경은 먼저 검증 후 로컬에 영속 저장하고 업로드 대기 상태를 표시한다. 로컬 저장 실패를 클라우드 저장 성공처럼 표시하지 않는다. 패널 재오픈·브라우저 재시작·서비스 워커 재시작 후에도 대기 작업이 남아야 한다.

**상태:** 로컬 사용 / 연결 필요 / 처음 가져오는 중 / 업로드 대기 / 동기화 중 / 동기화 완료 / 오프라인 / 재연결 필요 / 충돌 확인 / 일시 실패. 완료는 해당 시점까지의 로컬 변경 업로드와 원격 변경 반영을 검증했음을 뜻하며 미래 변경까지 보장하지 않는다.

**동기화 계기:** 연결 완료, 패널 활성화, 로컬 변경 후 지연 배치, 사용자 ‘지금 동기화’, 온라인 복귀. 백그라운드 검사 주기는 Chrome 실행 제약에 맞추며 상시 실행이나 즉시 푸시를 보장하지 않는다.

**첫 연결:** 원격 유무를 먼저 확인한다. 원격과 로컬에 모두 자료가 있으면 항목 수·대상 계정을 보여주고 ‘가져와 합치기’ 또는 ‘별도 보관함 유지’를 선택하게 한다. 로그인 자체로 로컬 전체를 업로드하거나 원격 전체를 덮어쓰지 않는다.

**동시 변경의 필수 계약:**

- 동일 작업 재전송은 한 번만 적용한다. 작업 ID, 기기 ID, 기준 버전·계보를 기록하고 기기 시각만으로 승자를 정하지 않는다.
- 다른 항목에 대한 변경은 합칠 수 있어야 한다. 같은 필드 수정, 동일 링크의 다른 그룹 이동, 삭제 대 수정은 충돌로 보존하고 사용자에게 선택지를 제시한다.
- 두 PC가 같은 원격 JSON을 마지막 저장 순서로 통째 덮어쓰는 방식은 금지한다. 로컬 revision만으로 원격 동시 쓰기를 안전하다고 판정하지 않는다.
- 우선 검증할 구현안은 멱등적 작업 기록과 검증된 스냅샷을 분리하는 방식이다. 파일 검색·업로드·중복 생성·부분 실패·정리 과정을 포함한 두 기기 시험을 통과해야 확정한다. 이 문서는 Drive가 트랜잭션 DB처럼 동작한다고 가정하지 않는다.
- 삭제는 명시적 삭제 기록으로 전파한다. 오래된 오프라인 기기가 삭제 항목을 되살리지 않아야 한다. 삭제 기록 정리와 스냅샷 압축은 활성/오래된 기기 처리 규칙을 검증하기 전 수행하지 않는다.
- 전체 초기화는 데이터 세대 변경 등 동등한 안전장치를 사용한다. 이전 세대의 대기 작업은 자동 재적용하지 않고 별도 복구 후보로 남긴다.
- 원격 파일 미발견, 접근 거부, 잘못된 스키마, 일부 조회는 ‘빈 보관함’과 구분한다. 사용자의 초기화 의사로 해석하지 않는다.
- 스키마가 더 최신이면 읽기 제한·업데이트 안내를 제공하고 하위 버전이 데이터를 다시 써서 손상시키지 않는다.
- 백오프·재시도·속도 제한 처리를 제공한다. 업로드 실패 중에도 로컬 편집은 가능하며 사용자 선택을 잃지 않는다.
- 내보내기와 복구 스냅샷은 동기화와 별개다. 잘못된 삭제가 동기화되는 상황에 대비하되 보존 기간과 용량은 출시 전 명시한다.

### 4.6 서비스 내부 탐색 계약 — Drive 보류·Notion 전용 종료

**Drive:**

- 사용자가 추가한 폴더를 탐색 시작점으로 삼는다. 드라이브 전체를 자동 수집하거나 하위 파일을 관리 링크로 일괄 저장하지 않는다.
- 펼칠 때 직계 자식을 조회하고 페이지네이션을 제공한다. 폴더 이름은 원본 열기, 펼침 버튼은 자식 조회다. 부모별 요청 중복 제거·취소·캐시·갱신을 제공한다.
- 폴더/파일 유형·이름·원본 링크·식별 정보 등 필요한 메타데이터만 요청하며 본문 다운로드는 하지 않는다. [Drive 목록 조회](https://developers.google.com/workspace/drive/api/guides/search-files)
- 조회 상태를 `미조회`, `조회 중`, `부분 조회`, `완료·비어 있음`, `완료·항목 있음`, `권한 필요`, `실패`, `캐시`로 구분한다. 알려지지 않은 자식 수를 0으로 표시하지 않는다.
- 공유 드라이브·바로가기·순환 참조·접근 불가 대상은 별도 테스트한다. 지원하지 않는 경우 원본 열기를 유지하고 제한을 명시한다.
- 접근 권한 상실은 저장 링크 삭제가 아니다. 민감한 탐색 캐시는 숨기거나 만료시키되 사용자의 관리 항목은 유지한다.
- **권한 출시 게이트:** `drive.metadata.readonly`는 제한된 범위(Restricted scope)로 분류된다. 검증 요건을 검토해야 하며, 파일 단위 권한 `drive.file`로 폴더 하나를 선택했다고 모든 후손에 접근 가능하다고 가정하지 않는다. 실제 권한·조회 시험을 통과한 방식을 선택한다. UI에서 선택 폴더만 표시하는 것과 OAuth가 제한하는 데이터 범위는 동일하지 않을 수 있음을 고지한다. [공식 권한 분류](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)

**Notion:**

- 0.1.19부터 전용 메뉴·화면·DOM 기반 즐겨찾기 및 하위 계층 수집을 종료한다. 비공개 API·세션 쿠키 추출로 대체하지 않는다.
- Notion URL은 일반 링크처럼 저장·검색·열기를 지원한다. 원본 서비스의 로그인과 접근 권한은 별개다.
- 기존 저장 데이터는 삭제하거나 자동 이전하지 않는다. 사용자가 요청한 로컬 가져오기만 새 보관함으로 복사하며 원본을 보존한다.
- Notion 전용 탐색 재도입은 별도 사용자 결정 없이는 진행하지 않는다.

### 4.7 모듈과 외부 계약 — 초기 다섯 모듈에서 범위 조정

| 모듈 | 감추어야 할 복잡성 | 단순한 외부 계약 | 검증 책임 |
|---|---|---|---|
| 링크 트리 | ID·중복·이동·순서·삭제·스키마·되돌리기 | 보관함 읽기, 명시적 편집 명령, 검증된 변경 결과 | 분류 불변조건·URL 안전성·사용자 데이터 보존 |
| 브라우저·열린 탭 | 패널 생명주기·탭 이벤트·URL 매칭·권한 차이 | 현재 페이지 관찰, 열린 목적지 조회, 목적지 열기 | 중복 탭 방지·기기 상태 격리·접근성 |
| Google 로그인·Drive 동기화 | 인증 수명·계정 경계·원격 저장·오프라인 큐·병합 | 연결/해제, 상태 구독, 동기화 요청, 충돌 해결 | 멱등성·동시성·재시작·계정 누출 방지 |

인터페이스는 원본 서비스의 응답이나 DOM 형태를 뷰에 직접 노출하지 않는다. 자식 목록은 항목 외에 조회 범위·다음 페이지·관찰 시각·권한 상태를 함께 반환한다. 동기화 모듈은 원본 문서 편집 기능을 갖지 않는다.

기존 모델의 정리 규칙·엄격한 저장 계약·데이터 보존·키보드 상호작용을 재사용한다. 범용 링크는 서비스별 URL과 열린 탭을 식별하며 Notion 전용 화면의 렌더링은 사용하지 않는다. 사이드 패널의 신뢰된 확장 출처만 허용하고 임의 웹페이지가 저장·클라우드 요청을 실행하지 못하게 한다.

### 4.8 기존 데이터 이전과 이름 변경

- 이전 대상은 구형 워크스페이스 트리와 별도 제목·아이콘 캐시다. 실제 데이터를 읽은 뒤 이전 건수·누락/손상 항목·출처를 먼저 보고한다.
- 보관함별로 기존 그룹의 이름·순서·표시 정보·접힘을 보존하고 사용자 섹션은 하위 그룹으로 바꾼다. 자동 미분류 섹션의 링크는 부모에 직접 둔다. 그룹으로 변환되는 ID는 중복·예약 ID 충돌 없이 결정적으로 매핑한다. 유효한 page ID는 원본 링크로 복원하며 모르는 제목을 임의로 만들지 않는다.
- 서로 다른 Notion 워크스페이스 트리는 별도 보관함으로 유지하는 방식을 기본 제안으로 한다. 이름이 같다는 이유로 합치지 않는다. 사용자 확인 없이 Google 계정 소유로 배정하지 않는다.
- 구형 구조와 캐시의 검증 가능한 백업을 먼저 남긴다. 새 구조 검증·재열기·건수/배치 대조 후 이전 완료를 기록한다. 중간 종료와 재실행에도 중복 생성하지 않는다.
- 구형 네임스페이스는 이름 변경만을 이유로 삭제하지 않는다. 이전 실패 시 원본을 남기고 재시도/내보내기를 제공한다.
- 확장 ID와 기존 설치 경로의 연속성을 유지한다. 새 이름으로 재설치하면 기존 저장소가 자동으로 따라온다고 안내하지 않는다. 다른 확장 ID로 배포할 경우 구형 버전의 명시적 내보내기·신규 버전 가져오기 경로를 먼저 제공한다.
- 0.1.16 schema 변경은 승인된 구현 범위다. 로고·이름·GitHub 저장소 이름·원본 Notion 저장소 변경은 이에 포함되지 않는다. GET·no-op에서 쓰지 않고 최초 실제 저장에서 원형 백업과 새 catalog 저장을 함께 성공시켜야 한다. 이전 사본은 최대 3개 catalog를 추가 보관할 수 있어 저장소 여유를 별도로 고려한다.
- schema 1 JSON은 schema 2로 변환해서 복원하고 새 내보내기는 schema 2를 사용한다. 구형 버전은 새 백업을 읽을 수 없으므로 업데이트 전 JSON 보관을 안내한다. 일반 되돌리기는 새 형식 데이터의 최근 작업 복구이며 앱 버전 다운그레이드가 아니다.

### 4.9 제거·초기화·연결 해제

| 동작 | 영향 | 필수 보호 |
|---|---|---|

| 로컬 캐시 비우기 | 재생성 가능한 탐색 캐시만 제거 | 미업로드 편집·자격 정보·관리 트리를 건드리지 않음 |

초기화 버튼은 동기화 옆에 두지 않는다. 삭제 확인 중 데이터가 변경되면 확인을 다시 받는다. 연결 해제 후 데이터는 다른 계정에서 자동 노출하지 않으며, 기기 내 보존·삭제·별도 로컬 복사 선택을 명확히 한다. 이 기능들로 Notion 페이지나 Drive 원본 파일을 삭제·이동·공유하지 않는다.

### 4.10 개인정보·보안·운영 원칙

- 클라우드 동기화는 URL·제목·업무 분류가 선택한 Google 계정으로 전송되는 기능임을 온보딩에 명시한다. 로컬 전용의 기존 ‘외부 전송 없음’ 문구를 연결 상태에 그대로 재사용하지 않는다.
- 문서 본문과 확장이 취급하는 쿠키·비밀번호·인증 토큰을 북마크 데이터나 일반 로그에 저장하지 않는다. URL과 업무 제목도 민감할 수 있으므로 진단 로그는 기본 마스킹한다.
- 토큰 처리는 신뢰된 확장 인증/백그라운드 경계로 제한한다. 콘텐츠 스크립트나 동기화 파일에 자격 정보를 전달하지 않는다.
- 허용된 API로만 통신하고 원격 실행 코드는 금지한다. 제목·아이콘·원격 JSON은 신뢰하지 않고 크기·스키마·출처를 검사하며 텍스트로 렌더링한다.
- 서비스 연결이 실패해도 로컬 트리와 원본 서비스는 조작 가능해야 한다. 재연결 루프나 오류로 원본 DOM을 훼손하지 않는다.
- Google Cloud 프로젝트, Drive API 활성화, OAuth 동의 화면, 안정적인 확장 ID와 OAuth 클라이언트 구성이 실연동 전제다. 회사 관리 정책에 따른 차단 가능성도 안내한다.
- Google 앱 데이터는 사용자/앱에 묶인다. 다른 클라이언트·브라우저 배포에서도 같은 앱 데이터에 접근하는지 실제 시험 전에는 호환을 보장하지 않는다.

## 5. Testing Decisions — 테스트와 수용 기준

### 5.1 테스트 원칙과 기존 자산

초기 다섯 모듈 전체를 테스트한다는 결정과 이후의 범위 축소를 함께 반영한다. 현행 링크 트리·열린 탭·이전 기능은 동작을 검증하고, Google 보류·Notion 전용 종료는 실행·주입되지 않는 경계를 검증한다. 테스트는 내부 DOM 선택자보다 사용자 행동과 관찰 가능한 저장·탐색 결과를 중심으로 한다. 실제 계정 시험은 명시적으로 지정된 테스트 계정·합성 자료로 진행하며 운영 문서에 파괴 작업을 하지 않는다.

초안 작성 시 Moa 0.1.9 전용 저장소의 Node 회귀 테스트 **195/195 통과**를 기준선으로 확인했다. 이 숫자는 0.1.10의 현재 테스트 수나 검증 결과를 뜻하지 않으며 새 릴리스 검증 결과는 실제 실행 기록으로 별도 보고한다. 기존 그룹·섹션 모델, 중복, 엄격한 저장 스키마, 신뢰된 발신자, revision 충돌, 메타데이터 캐시, 워크스페이스 격리, 부분 DOM, 이전, 패키징 검사를 출발점으로 삼는다. 별도 브라우저 fixture suite도 회귀 대상으로 유지한다.

기존 ‘네트워크 요청 없음’ 계약은 클라우드 기능 도입 시 ‘로컬 모드 네트워크 없음 / 동의한 연결만 지정된 API로 통신’ 계약으로 대체 검증한다. 테스트를 삭제해 개인정보 경계를 없애지 않는다.

### 5.3 증거 수준과 완료 판정

- 단위/계약 테스트: 순수 트리 모델, URL 식별, 스키마, 병합, 이전, 권한 없는 경로.
- 통합 테스트: 가짜 Drive 응답으로 페이지네이션·오류·재시도·동시 변경·계정 전환·재시작.
- 브라우저 테스트: 실제 Chrome 확장 패널, 접근성, 탭 이동, 설치 업데이트와 Notion 내부 UI 미주입. 종료된 화면의 합성 회귀는 역사 기록이며 현행 런타임 검증을 대신하지 않는다.
- 실연동 테스트: 사용자 승인된 Google 테스트 계정으로 서로 다른 PC의 Chrome 프로필에서 신규 설치·복원, OAuth 동의·거절·취소, 앱 데이터 저장·복원, 테스트 Drive 하위 폴더 조회, 원본 불변 확인. 같은 PC의 두 프로필 시험은 빠른 사전 검증이며 다른 PC 시험을 대체하지 않는다.
- 합성 데모/가짜 API 통과를 실연동 완료로 표기하지 않는다. 일단 로컬 캐시에 보이는 것과 원격 저장 확인을 구분한다.
- 기능별 수용 기준, 데이터 이전, 계정 경계, 파괴 동작 보호, 두 기기 충돌 시험이 모두 통과해야 해당 기능을 완료로 표시한다.

## 6. Out of Scope — 이번 범위 밖

- 모든 브라우저·모바일·Notion 데스크톱 앱 지원 보장. 우선 서로 다른 PC/프로필의 Chrome을 검증한다.
- 탭 세션 전체 복원, 방문 기록 수집, 다른 PC의 현재 화면·스크롤·열린 탭 실시간 복제.
- 사용자 간 팀 공유·협업 편집·공유 링크 발행. Drive 앱 데이터 영역을 팀 공유 저장소로 사용하지 않는다.
- Notion/Drive 원본 생성·이동·삭제·권한 변경·본문 편집 또는 전체 문서 다운로드.

- Slack 채널 메시지·GitHub 이슈 내부 계층을 API로 수집하는 기능. 이 서비스들은 우선 일반 링크로 지원한다.
- AI 자동 분류·관련 문서 추천·본문 요약, 광고, 결제, 운영 서버 기반 사용자 분석.

## 7. Further Notes — 이름·단계·검토 사항

### 7.1 확정 이름: FAVMOA · 팹모아

사용자가 영문 **FAVMOA**, 한글 **팹모아**를 확정했다. Favorite의 FAV와 모은다는 뜻의 MOA를 연결하며, 특정 서비스에 제품 범위를 묶지 않는다. 화면 이름·확장 이름·설치 문서에는 이 표기를 사용한다. NEMOA · 네모아와 즐겨모아는 검토했던 과거 후보이며 출시 이름이 아니다.

사용자에 의한 이름 확정은 상표 등록·권리·도메인·Chrome 웹스토어 등록명 확보를 의미하지 않는다. 별도 검증과 등록 전까지 독점 사용 가능성을 주장하지 않는다. 0.1.10부터 배포 이름을 FAVMOA로 바꾸되 기존 저장 키·확장 소스 경로·GitHub 저장소는 유지하여 사용자 데이터의 연속성을 보호한다. 설치 폴더나 배포 키가 바뀌면 확장 ID가 달라질 수 있으므로 이름 변경만으로 ID 보존을 보장하지 않는다.

### 7.2 권장 개발 순서와 통과 조건

| 단계 | 산출물 | 다음 단계 조건 |
|---|---|---|
| A. 로컬 범용화 | 링크 도메인, 사이드 패널, 탭 연결, 기존 데이터 이전·백업 | 기존 회귀 + 범용 링크·설치 이전·탭 시험 통과 |
| B. 계정·동기화 | Google 선택 연결, 앱 데이터 저장, 상태 UI, 오프라인·충돌·계정 분리 | 다른 PC 두 프로필 실연동·재시작·동시 수정·삭제 전파 시험 통과 |
| C. 서비스 탐색 | Drive 권한 분리·폴더 트리. Notion 전용 탐색은 종료 | OAuth 검증 요건 확인, 페이지네이션·권한 거절·원본 불변 시험 통과 |
| D. 출시 검증 | 온보딩·성능·접근성·권한 고지·복구·패키지 | 전체 수용 기준과 출시 차단 항목 해결 |

현재 패치 버전은 0.1.37, 다음 패치 예정 번호는 0.1.38이다. 실제 릴리스마다 버전을 올리되 문서 버전을 확장 버전으로 사용하지 않는다. 단계 B·Drive 탐색은 현재 보류다. 수동 백업 기능·ID 고정·OAuth 설정 반영·연결 복구 안내만으로 자동 동기화 통과 조건을 충족했다고 하지 않는다.

### 7.3 출시 전 반드시 해결할 항목

1. 확정 이름 FAVMOA · 팹모아의 권리·스토어·도메인 사용 검토. 사용자 확정과 법적 가용성 검증은 분리한다.
2. Google Cloud/OAuth 설정, 앱 데이터 접근 및 필요한 추가 scope의 검증 요건. 설정·로그인 성공·실제 데이터 접근을 각각 확인한다.
3. 원격 동시 쓰기 프로토콜과 초기 파일 중복 생성, 삭제 기록 수명, 스냅샷 복구 정책. ‘나중에 충돌 처리’로 미루지 않는다.
4. 실제 Drive 하위 폴더 권한 범위, 공유 드라이브/바로가기 지원 범위. 구현 검증 전 전체 계층 보장을 하지 않는다.
5. 미업로드 변경이 있는 계정 전환·연결 해제·클라우드 삭제의 UX와 복구 경로.
6. 구형 설치의 데이터 이전 경로와 배포 확장 ID의 연속성.
7. 회사 자료의 제목·URL을 개인 Google 계정에 저장하는 상황에 대한 명확한 사용자 고지와 조직 정책 확인.
8. 이 PRD의 권장값인 보관함 단위 이전·단일 링크 소속·기기별 폴딩 상태·성능 목표는 구현 시작 시 설계 검토에서 확정한다. 초기 다섯 모듈의 전체 테스트 승인 이후 Google 기능은 보류하고 Notion 전용 화면은 종료했으므로 최신 범위를 기준으로 판정한다.

### 7.4 문서 관리

이 PRD는 Notion 전용 기획에서 범용 탐색기로 전환하는 제품 목표를 정의한다. Moa 0.1.9는 과거 구현 기준선이며 현재 설치·동작 범위는 FAVMOA 0.1.37 README와 문서 상단이 기준이다. 앞선 0.1.35는 JSON 복원과 복원 전 목록 복구에 실제 안전 사본 미리보기·최신 교체 영향 검토·명시적 확인 뒤 별도 실행을 추가한다. JSON 충돌 시 선택한 파일을 유지하며, 복구 사본이 없거나 손상되면 복구를 막는다. 검토한 revision으로만 실행하고 재충돌 시 다시 검토하며, 읽기만으로 저장·undo·사본을 바꾸지 않는다. 앞선 0.1.36은 기존 Moa 가져오기 충돌 뒤 대상 catalog만 검토하고 명시적 확인과 별도 실행으로 가져오게 한다. 원본은 실행 시 읽으며 미리 보거나 고정하지 않는다. 현재 catalog의 이전 기록으로 중복을 방지하고 추가 0개와 경고가 함께 있으면 확인 필요 결과로 구분한다. 감사 우선순위 2의 지정된 대화상자 복구 경로 구현을 마무리했으며 모든 명령·실제 Chrome 환경의 충돌 해결을 보장하지 않는다. 현재 0.1.37은 수동 링크 추가·단일 이동·그룹 메뉴 이동·드래그 이동의 성공과 목적지 조상 펼침을 같은 저장에 포함한다. 검색을 지우고 대화상자 종료·보류 렌더링을 고려해 저장한 링크 또는 옮긴 그룹 제목으로 포커스·스크롤을 맞추며, 옮긴 그룹 자체의 접힘은 보존한다. 취소·실패·검토는 맥락을 유지하고 같은 위치 no-op은 데이터·접힘·undo를 바꾸지 않는다. 한 번 undo로 편집과 자동 펼침을 복구하되 이후 명시적 접힘은 유지한다. 감사 우선순위 3의 지정 경로 구현을 마무리하며 일반 내용 수정과 기존 일괄 동작 계약은 유지한다. 다음은 보관함 전환 시 검색 맥락 정리다. 앞선 삭제·초기화의 고정 대상·영향 검토와 그룹 내용 보존도 유지한다. 앞선 그룹·일괄 이동·이름·그룹색·수동 링크 편집·단일 이동·가져오기 창의 입력·선택 보존도 유지한다. 그룹 접기·펼치기가 마지막 내용 편집 1회의 되돌리기를 소모하지 않도록 하고 직접 바꾼 접힘 상태를 유지하는 보호를 유지하며, 여러 단계 되돌리기는 제공하지 않는다. 북마크와 열린 웹 탭의 검색·보이는 항목 전체 선택·숨겨진 선택 안내·선택 해제·200개씩 더 보기·최대 1,000개 선택과 읽기 취소 보호를 유지한다. 긴 제목을 정리하되 전체 URL을 보존하며 원자적 일괄 추가 뒤 목적지 그룹을 보여준다. 원본 북마크·탭은 변경하지 않는다. 여러 저장 링크의 일괄 이동·조용한 링크 클릭·새 보관함 선택·입력 오류 안내·저장 중 편집 보호·첫 클릭 보호·드래그앤드롭 이동·그룹 추가 버튼·연한 그룹 배경·그룹별 색상·프로필별 테마·재귀 그룹·로컬 저장·JSON 이전과 기존 데이터의 명시적 가져오기를 유지한다. Notion 전용 화면은 종료 상태다. 목표 기능과 구현 범위를 혼동하지 않는다. 네트워크를 사용하는 보류 기능이나 Notion 전용 탐색을 다시 도입하려면 별도 사용자 결정·최소 권한·실연동 검증이 필요하다.

작성 과정에는 `to-prd` 스킬의 문제·해결·사용자 이야기·구현 결정·테스트·제외 범위 틀을 사용했다. 모듈과 전체 테스트 범위를 사용자에게 확인했고, 별도 코드 검토로 현재 기능과 이전 위험을 대조했다. 이슈 운영 설정과 외부 발행 요청은 없으므로 PRD 파일만 작성했으며 GitHub 이슈 생성·코드 푸시는 하지 않았다.
