# FAVMOA 0.1.17 — Notion 현재 페이지 링크 수정

검증일: 2026-09-23 KST · 다음 패치: 0.1.18

## 재현과 원인

Notion 내부 FAVMOA의 ‘현재 열린 페이지’ 카드가 `/p/<workspace>/<pageId>`에서
워크스페이스 경로를 지우고 `/<pageId>`로 이동했다. 사용자가 제공한 실제 주소를
`readPageNavigation()`에 입력한 회귀 검사에서 동일한 경로 손실을 재현했다.
원인은 사이드바에 현재 페이지가 없을 때 ID만으로 주소를 생성하는 fallback이었다.
화면의 URL 검증과 네이티브 앵커 자체는 전체 경로를 보존했다.

## 수정 범위

- 현재 페이지 ID와 일치하는 검증된 실제 문서 URL을 우선한다. 워크스페이스 이름을 하드코딩하지 않는다.
- 전체 경로, 쿼리, 해시를 보존한다. 기존 사이드바 행이 짧은 주소를 제공해도 현재 카드에는 실제 주소를 사용한다.
- 현재 문서와 ID가 다르면 그 URL을 사용하지 않는다. 저장된 동일 페이지의 유효한 URL이 있으면 이를 사용한다.
- 외부 호스트·인증정보 포함 URL·위험한 프로토콜은 계속 차단한다.
- 워크스페이스/계층을 확인할 수 없는 상태에서도 현재 페이지 링크만 보여주며 하위 관계를 추측하지 않는다.
- 스키마, 저장 키, 그룹/섹션/링크, 확장 ID, 권한은 변경하지 않는다.

다른 경로인 범용 Chrome 사이드 패널의 기존 탭 재사용 로직과,
저장된 즐겨찾기의 메타데이터 없는 ID-only fallback은 이번 수정 대상이 아니다.
원본 경로를 알 수 없는 페이지의 워크스페이스를 추측해서 일괄 변환하지 않는다.

## 실제 Notion 확인

사용자가 열어 둔 실제 Chrome의 Notion 탭을 새로고침하고 내부 FAVMOA
메뉴를 열었다. ‘현재 열린 페이지’ 카드의 링크가 원래 `/p/<workspace>/<pageId>`
경로를 가진 것을 네이티브 접근성 트리에서 확인했다. 해당 링크를 실제 클릭한 후에도
그 경로와 원래 페이지 제목·문서가 유지됐다. 공개 기록에서는 실제 워크스페이스 이름과
페이지 제목·ID를 생략했다. 이 확인은 합성 검사가 아닌 실제 Chrome 관찰이며, Chrome
사용자 저장소나 인증 토큰 접근, 문서 내용 편집, 즐겨찾기 추가/초기화가 없었다.

이 결과는 보고된 현재 페이지 카드 경로의 실제 확인이며, 모든 저장된 즐겨찾기나
다른 워크스페이스, 범용 사이드 패널의 탭 재사용을 검증했다는 의미는 아니다.
