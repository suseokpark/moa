# FAVMOA 0.1.37 · 추가·이동 결과 표시

검증일: 2026-09-25 KST. [개선 큐](USABILITY-IMPROVEMENT-QUEUE.md) 3번의 수동 링크 추가·단일 링크 이동·그룹 메뉴 이동·드래그 이동을 완료했다. 다음은 4번 보관함 전환 시 검색 정리다. 이번 증거는 합성 DOM·메모리 저장소 검증이며 실제 Chrome 화면 검증과 구분한다.

## 재현과 원인

실제 sidepanel 소스에 합성 catalog와 DOM을 연결해, 검색과 접힌 중첩 목적지를 가진 상태에서 추가/이동을 실행했다. 저장은 성공하지만 기존 검색어가 남아 새 링크·이동한 그룹이 보이지 않았다. 개별 추가·이동 모델에는 목적지 조상 펼침 옵션이 없고, 대화상자 종료는 원래 버튼으로 초점을 돌렸다. 드래그 콜백에서도 같은 숨김을 재현했다.

diagnose·TDD 절차로 각 경로의 실패 테스트를 먼저 고정했다. 독립 경계 점검에서 동일 위치 이동의 불필요한 검색 해제, 지연 렌더 뒤 새 대화상자의 초점 회수, 저장을 기다리는 중 보관함·대화상자를 바꿨을 때 이전 화면으로 돌아가는 경합도 RED로 확인한 뒤 수정했다.

## 구현 계약

- `addLink`, `moveLink`, `moveGroup`은 선택적인 boolean `revealTarget`을 받는다. 유효한 추가·실제 이동일 때만 목적지 경로를 같은 모델 변경 안에서 펼친다. UI에서 별도 `toggleGroup` 저장을 추가하지 않는다.
- 그룹 이동은 목적지 조상만 펼친다. 이동한 그룹 자체와 그 하위 트리의 접힘은 유지한다. 최상위 이동은 불필요하게 다른 그룹을 펼치지 않는다.
- 성공한 수동 추가·단일 이동·그룹 메뉴 이동·드래그 이동은 검색을 비우고 결과가 있는 보관함·경로를 표시한다. 새 링크는 실제 생성된 ID를 정규화 URL로 찾고, 이동은 고정된 원래 ID를 사용한다. 대화상자 종료와 보류된 트리 렌더를 고려해 결과 링크/그룹 제목에 초점과 스크롤을 맞춘다.
- 같은 위치 이동은 no-op이다. 데이터·접힘·revision·기존 Undo를 보존하고 검색을 지우거나 결과를 강제로 표시하지 않는다. 취소·일반 저장 실패·충돌·읽기 전용 검토도 미완료 결과를 표시하지 않는다.
- 내용 편집과 자동 펼침은 한 번의 저장·revision·Undo 단위다. Undo로 편집과 자동 펼침을 함께 취소하며 이후 사용자가 명시적으로 바꾼 접힘은 기존 보호 계약에 따라 유지한다. stale revision·용량 실패·무효 목적지·순환/깊이 보호도 유지한다.
- 보류 렌더 뒤 다른 보관함이나 더 새 대화상자를 선택했다면 이전 결과 초점을 적용하지 않는다. 새 창을 이미 열었다 취소한 경우에도 세대 번호로 차단한다. 열린 테마 설정의 초점도 보호한다.
- 드래그 저장 대기 중의 보관함·대화상자 변경도 저장 전에 캡처한 맥락과 비교한다. 저장 자체는 완료하되 사용자 새 맥락을 이전 결과 표시로 덮지 않는다. 완료 후 렌더 지연에는 별도 두 번째 초점 검사를 한다.
- 일반 링크 내용 수정과 기존 일괄 추가·일괄 이동 계약, schema 2·저장 키·권한·확장 ID·서비스의 원자적 저장 계약은 변경하지 않았다.
