# FAVMOA 0.1.14 검증 기록

검증일: 2026-09-23 KST. 범위는 로컬 우선 사용성, 링크 입력, JSON 복원 안전 사본, Google 보류 배포다. 기존 사용자 저장소·실계정·Notion 원본은 변경하지 않았다. [사용성 점검](UX-AUDIT-0.1.14.md)의 화면은 이번 점검 중 캡처하고 저장한 동일 파일을 열어 확인했다.

## 자동 검사

- `npm test`: **316/316 통과**, 실패·취소·건너뜀 0.
- 새 URL 준비 함수: 도메인 정규화, 선택 이름, 위험 URL/제어 문자/자격 증명 주소 차단.
- 전용 복원 사본: 편집·접기·일반 undo 이후 유지, 동일 파일 no-op 유지, 새 교체 시 갱신, 복구 소비와 복구 undo, 충돌·저장 실패·손상 사본 처리.
- UI 함수 계약: 실제 sidepanel 함수와 메모리 서비스를 실행해 동일 파일 안내, 교체 결과, 선택 이름 입력, 수정과 unsafe URL 차단, HTML ID 연결 확인.

- Google 보류: 오래된 메시지·클라이언트 요청이 `CLOUD_PAUSED`로 끝나며 토큰·네트워크·저장소를 사용하지 않음. 보존된 클라우드 코드의 모의 테스트는 실연동 증거가 아님.

## Chrome 로컬 미리보기

실제 Chrome에서 `http://127.0.0.1:4175/extension/notion-favorite-sections/sidepanel/sidepanel.html`을 사용했다. 현재 페이지·북마크는 합성값이고 데이터는 실제 확장과 분리된 미리보기 저장소다.

| 시나리오 | 확인 결과 |
|---|---|
| `example.com/usability`만 입력 | 이름 `example.com`, URL `https://example.com/usability`로 1개 저장 |
| 같은 주소 재입력 | 중복 경로 안내, 1개 유지, 입력값 보존 |
| `javascript:alert(1)` 입력 | 오류 안내, 저장 없음 |
| 일치하지 않는 검색 후 Escape | 0개 안내 후 전체 목록 복귀 |
| 그룹·섹션 생성과 목적지 선택 | `업무 자료 / 프로젝트`에 합성 현재 페이지 저장 |
| 그룹·섹션을 접은 뒤 저장 위치 보기 | 경로 펼침, 현재 링크 강조, 링크 초점 |
| Tab / Enter / Escape | 주소 → 선택 이름 → 저장 위치, Enter 펼침, Escape 취소 후 `+ 링크` 초점 |
| 320px 화면 | body scrollWidth 320 / viewport 320, dialog 폭 296 / 내부 폭 294, 가로 넘침 없음 |
| 새로고침 | 합성 링크 2개와 분류 유지 |
| 상단 백업 | 설정을 열어 JSON 영역으로 이동, 복원 사본 없을 때 복구 버튼 비활성 |
| JSON 내보내기 | 저장 요청 안내 확인. 자동화 다운로드 이벤트는 시간 초과하여 실제 저장 파일 내용은 미확인 |
| JSON 불러오기 | 합성 파일 선택 시 자동화 도구의 파일 URL 접근 권한 제한. 가져오기·확인·복구 종단 흐름은 미검증 |
| 콘솔 | 미리보기에서 수집된 error/warn 0건 |

임시 360×850·320×740 viewport override는 검증 후 해제했다. 실제 사용자의 확장 데이터는 읽거나 바꾸지 않았다.

## 미검증·다음 확인

실제 `chrome-extension://` 화면 자동 접근은 도구 보안 정책으로 제한되어 우회하지 않았다. 설치 갱신, 실제 탭 전환·북마크 권한, 실제 확장 저장소 및 JSON 파일 왕복은 별도 수동 확인이 필요하다. 스크린리더·전체 WCAG 적합성·1,000개 이상 성능·일반 사용자 연구도 이번에 주장하지 않는다. Google 실계정 인증은 사용자 결정대로 보류했다.

수동 확인은 **기존 목록을 JSON으로 저장 → 같은 설치 폴더에 0.1.14 적용 → 확장 카드 새로고침 → 기존 링크·분류 확인** 순서로 시작한다. 테스트용 목록에서 JSON을 바꿔 불러오고, 편집·접기 후 `복원 전 목록 복구…`가 원래 목록을 되돌리는지 확인한다. 기존 확장을 삭제하거나 초기화하지 않는다.
