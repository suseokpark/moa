# FAVMOA 0.1.13 — 사용성 개선과 실제 인증 실패 점검

검증일: 2026-09-23 KST. 관련 요구사항: [사용자 스토리 6개](USER-STORIES-0.1.13.md).

## 결론과 범위

로컬 링크 정리의 시작·검색·현재 위치 찾기와 Google 연결의 상태·오류·진단 안내를 개선했다. **Google 계정 연동은 해결 완료가 아니다.** 실제 Chrome 확장에서 0.1.12와 0.1.13 모두 Google 동의 창이 나타나기 전에 인증 실패가 재현됐다. 0.1.13에서는 `AUTH_FAILED` / `authorization`으로 실패 단계와 안전한 진단 정보를 확인할 수 있다.

이번 검증은 다음 세 환경을 구별한다.

- Node: 데이터·메시지·인증 상태 전이·모의 Google 응답·패키지 검사.
- 내장 브라우저 localhost: 합성 페이지·북마크를 사용하는 UI 흐름. 실제 Google 연결 불가.
- 사용자 Chrome에 설치한 확장: 실제 버전·ID·목록 보존·인증 시도와 오류 화면. Google 동의 승인·Drive 업로드는 하지 않았다.

## 흐름별 사용성 감사

이번 작업의 화면 캡처와 조작 결과를 기준으로 작성했다. 이전 `artifacts/qa/`의 0.1.10 이미지를 이번 버전의 증거로 재사용하지 않았다.

### 강점

- 처음부터 계정 연결을 요구하지 않으며 연결 실패 후에도 로컬 목록을 사용한다.
- 저장 여부·분류 경로·현재 페이지 강조를 이어서 보여준다. 찾기는 기존 링크를 변경하거나 중복 생성하지 않는다.
- 진단은 공개 설정과 안전한 오류 코드·단계만 제공한다. 계정 이메일·토큰·쿠키·링크 제목·URL·원본 OAuth 오류는 보고서에서 제외한다.
- 연결 기록을 실시간 인증 보장으로 표시하지 않고, 백업 때 인증을 확인하며 자동 동기화가 아님을 안내한다.

### 남은 위험과 후속 작업

- **P0:** 실제 Google 인증 실패. Cloud 클라이언트 유형·등록 Item ID·앱 대상/테스트 사용자·조직 정책과 원본 브라우저 오류를 확인해야 한다. `AUTH_FAILED`만으로 원인을 확정할 수 없다.
- **P1:** 현재 페이지가 여러 보관함에 있을 때 현재 보관함, 이후 첫 일치 항목 순으로 이동한다. 모든 위치를 고르는 선택기는 아직 없다.
- **검증 제한:** 320px에서 본문 `scrollWidth`가 viewport와 같은 320px로 가로 넘침이 없고, 진단 대화상자도 읽을 수 있음을 확인했다. 중복 URL을 다시 제출해도 링크 수 1개가 유지됐고 입력은 보존됐으며, 로컬 오류에 Google 오류 카드가 뜨지 않았다. Escape로 닫으면 링크 추가 버튼으로 초점이 복귀했다. 이 확인으로 전체 스크린리더·키보드 경로·모든 입력 오류·모든 브라우저 호환성을 검증했다고 하지는 않는다.
- 실제 Drive 수동 백업/목록/복원·다른 PC 복원은 미검증이다. 자동 동기화·원격 병합·Drive 하위 폴더 탐색은 미구현이다.

## 실제 Chrome 설치·인증 관찰

1. 기존 `artifacts/favmoa-v0.1.12` 설치의 버전과 고정 ID `ebbgmhdbonpillbfjapebljagnbjembj`를 확인했다.
2. **Google 계정 연결 → Google로 계속** 흐름에서 Google 동의 팝업 없이 일반 오류가 즉시 표시됐다. 이를 계정 선택·동의 거절·Drive API 오류로 단정하지 않았다.
3. 0.1.13 압축 해제 폴더 `artifacts/favmoa-v0.1.13`을 **압축해제된 확장 프로그램 로드**로 적용했다. 같은 ID와 0.1.13 버전 및 기존 링크 2개의 보존을 확인했다. 개인 링크의 제목·URL은 이 문서에 기록하지 않았다.
4. 다시 연결을 시도했으며 `AUTH_FAILED`, 단계 `authorization`으로 실패했다. Google 동의 팝업은 나타나지 않았다.
5. 진단에 실제 확장 ID, 공개 클라이언트 ID, 0.1.13 버전, 인증 API 사용 가능이 표시됨을 확인했다. 이는 로컬 설정 형식·API 존재의 증거이며 Google Cloud 등록·사용자 권한의 증거가 아니다.
6. Google 동의를 승인하지 않았고, 계정 연결 성공·Drive 업로드·백업 복원도 발생시키지 않았다.

진단 **복사 버튼 자체는 실제 Chrome에서 아직 누르지 않았다.** 원본 오류를 얻기 위한 DevTools UI 확인은 명령 입력을 완료하지 못해 결과를 얻지 못했다. 해당 작업으로 연 DevTools 두 개는 닫았고, 사용자 Chrome은 0.1.13 진단 화면을 열어 두었다. 서비스 워커의 원본 오류를 확보했다고 주장하지 않는다.

Chrome 공식 문서는 `getAuthToken`이 manifest의 OAuth 클라이언트·범위를 사용하며, 대화형 인증은 목적을 설명하는 사용자 동작으로 시작하도록 안내한다. 이번 구현도 설명 확인 뒤에만 인증을 요청한다. 이 문서가 특정 설치의 Cloud 설정을 검증해 주는 것은 아니다. [Chrome Identity API](https://developer.chrome.com/docs/extensions/reference/api/identity)

## 자동 검증과 수정한 회귀

- 전체 **300/300 Node 테스트 통과**.
- 그중 클라우드 서비스·클라이언트 **37/37**, 진단·현재 링크 위치 helper **5/5** 통과.
- 오류를 모두 취소로 뭉뚱그리지 않고 안전한 유형·단계로 구별한다. 계정 정보 조회 거절은 Drive 권한 오류와 분리한다.
- 인증 무응답 제한, 인증 중 상태 조회, 중복 동의 창 차단, 시간 초과 뒤 늦은 토큰 폐기와 뒤늦은 연결 방지, 대기 중 연결 해제를 모의 응답으로 검사했다.
- 원본 오류·계정·토큰·catalog와 보고서 필드 주입 문자열이 진단에 유출되지 않는지 검사했다.
- 현재 페이지의 다른 보관함 검색, 현재 보관함 우선, Notion 페이지 ID 정규화 기반 매칭을 검사했다.
- 최종 검토에서 시간 초과 후 재시도 버튼이 계속 비활성화될 수 있는 상태 갱신 문제, 로컬 오류가 Google 오류처럼 표시되는 문제, 다크 모드 CSS 회귀를 수정했다. 실제 Google 창의 시간 초과 경로까지 수동 재현한 것은 아니다.
- 기존 데이터 모델·저장 CAS·이전·되돌리기·메타데이터·권한 경계 검사도 전체 회귀에 포함한다. 기존 Notion 브라우저 fixture 전체를 이번에 새로 실행했다고 주장하지 않는다.
