# FAVMOA 0.1.25 — 클릭 깜빡임 수정과 사용성 점검

검증일: 2026-09-23 KST. 0.1.24 → 0.1.25, 다음 패치 0.1.26.

## 결론과 범위

링크 클릭 때 임시 텍스트가 삽입되었다 사라지는 문제를 수정했다. 새 보관함 선택, 입력 오류 복구, 저장 중 조작 보호도 함께 개선했다. 새 기능을 넓히기보다 기존의 열기·담기·정리 흐름을 안정화했다.

`diagnose`의 재현 → 실패 테스트 → 수정 → 회귀 확인 순서를 따랐다. 사용성 점검은 이번 실행에서 캡처한 **localhost 미리보기**에 한정한다. 실제 Chrome 확장 패널의 보호된 화면에는 우회 접근하지 않았다. 실제 Chrome에서는 설치 버전과 Reloaded만 확인했다. 화면 캡처·모의 API·실환경 검증을 서로 대체하지 않는다.

## 재현한 원인과 수정

1. `openSavedLink → setLinkOpening`이 API 호출 전에 링크 옆에 `여는 중`을 넣거나 기존 `현재/열림`을 바꾸고, 응답 직후 제거·복구했다. 빠른 API에서도 일어나는 DOM 텍스트 변경을 shipped 함수 테스트에서 재현했다. 이제 `aria-busy`와 기존 처리 중 커서/배경만 사용하고 제목·배지는 바꾸지 않는다.
2. 일반 클릭의 진행/성공 안내가 숨겨져 있던 상단 `status`를 펼쳤다. 수정 전 브라우저 캡처에서 목록이 아래로 밀렸다. 정상 이동은 별도의 화면 밖 polite live region으로 알리고, 실패만 눈에 보이게 남긴다. 저장·되돌리기 안내는 클릭으로 덮어쓰지 않는다. 오류는 다음 성공까지 유지하며 타이머로 지우지 않는다.
3. 보관함을 추가해도 기존 `libraryId`가 유효하여 이전 보관함이 선택된 채 남았다. 성공한 생성 결과에 신규 ID가 정확히 하나일 때만 새 보관함을 선택하고 검색을 비우며 선택기에 포커스를 돌린다. 실패·충돌·복수 신규 ID를 추측하여 선택하지 않는다.
4. 잘못된 링크 입력 뒤 제출 버튼에 포커스가 남고, 저장 중에는 제출 버튼만 잠겼다. 이제 주소/이름 오류를 해당 필드의 `aria-invalid`와 오류 설명에 연결하고 포커스를 옮긴다. 입력을 고치면 해당 검증 오류만 해제한다. 비동기 저장 중 입력·선택·버튼을 잠그고, 완료/실패 뒤 기존 disabled 상태와 포커스를 복구한다.

## 자동 검사와 설치

- 전체 `npm test`: **536/536 통과**. 기존 첫 클릭/드래그/데이터 보호 회귀 포함.
- 클릭 피드백: 신규 8개 + 기존 상호작용 7개. 수정 전 4개 실패로 임시 문구·배지 교체·상단 문구 재현.
- 보관함 생성 선택: 신규 9개. 수정 전 2개 실패 후 통과. 이름 변경·그룹 추가·실패·충돌은 기존 선택 유지.
- 대화상자: 신규 6개. 수정 전 3개 실패 후 통과. 오류 필드, 편집 시 오류 해제, 비동기 저장 잠금, 실패 시 포커스/값/disabled 복원.

## 다음 개선 후보 — 이번 버전 미구현

- **여러 링크 선택 후 한 번에 이동**: 현재 단계 5의 단건 메뉴 흐름은 명확하지만 여러 항목을 정리할 때 반복해야 한다. 다음 기능 중 우선 후보. 선택 범위·일괄 이동·한 번의 되돌리기를 함께 설계해야 한다.
- **긴 제목 표시 옵션**: 좁은 패널에서 한 줄 말줄임을 유지할지, 선택적으로 두 줄을 쓸지 실제 긴 제목 목록으로 비교 검증할 가치가 있다. 이번에는 밀도와 행 높이를 바꾸지 않았다.

재발 방지: 클릭 회귀는 API 완료 후 상태만 보지 않고 **호출 직후·대기 중·완료 후의 제목과 자식 노드 동일성**을 확인한다. 저장 회귀는 성공뿐 아니라 **처리 중 사용자 입력과 실패 후 포커스**를 함께 검사한다.
