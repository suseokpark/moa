# FAVMOA 0.1.24 QA — 첫 클릭 보존

검증일: 2026-09-23 KST. 0.1.23 → 0.1.24, 다음 패치 0.1.25.

## 재현한 원인

1. 포커스·가시성·탭 갱신마다 `refreshTabs()`가 트리 전체를 다시 그렸다. 누르기(pointerdown)와 떼기(pointerup) 사이에 갱신이 완료되면 누르던 anchor가 제거되어 네이티브 click이 링크에 전달되지 않을 수 있었다. 변경 없는 갱신, 탭 제목만 변경, 열린 URL 집합은 같지만 순서/중복 탭이 달라지는 경우에도 발생했다.
2. 드래그 종료 후 300ms의 잔여 클릭 차단이 **새 pointerdown으로 시작한 의도적인 클릭**까지 막았다. 기존 노드·재렌더링된 링크·메뉴·그룹 접기에서 재현했다.

`diagnose` 절차에 따라 수정 전에 회귀 테스트 실패를 확인했고, 포커스 갱신 문제는 배포 sidepanel을 iframe에 올린 로컬 브라우저 fixture에서도 실제 포인터 입력으로 재현했다. 실제 Chrome 확장의 보호된 화면은 우회 접근하지 않았다.

## 수정

- 트리를 다시 그릴 필요가 있는 현재 페이지 식별자와 열린 URL 집합을 비교한다. 동일 상태/제목 변경은 저장된 링크 DOM을 교체하지 않는다.
- 탭 갱신과 다른 화면에서 온 catalog 갱신은 pointerdown부터 pointerup 이후 click/auxclick 전달까지 DOM 변경을 보류한다. 다음 태스크에서 최신 상태만 적용한다.
- 네이티브 드래그 중 갱신도 계속 보류한다. 다중 포인터, 새 입력, pointercancel, 창 blur, 숨김 상태, 해제/destroy 경계를 테스트했다.
- 드래그 후 **새 pointerdown**은 이전 클릭 차단을 해제한다. 새 입력 없이 따라오는 드래그의 잔여 클릭은 계속 차단한다.
- 지연 렌더링 후 저장 위치 보기/이동 완료의 포커스·스크롤은 새 트리가 생성된 뒤 수행한다.
- 원래 링크 클릭/드래그 영역, URL, 저장 형식, 그룹 배치, 확장 ID와 권한은 변경하지 않았다.

로컬 미리보기의 예시 링크만 사용했다. 임시 그룹 `클릭 검증용`은 제거하고 예시 링크는 원래 미분류 위치로 복귀했다. 사용자 Chrome 저장소·로그인 데이터는 읽거나 수정하지 않았다.

자동화 선택자 평가 중 `MutationObserver.observe`의 Node 타입 오류 1회를 관측했다. 변경된 배포 UI 소스에는 해당 호출이 없지만 오류 출처를 확정하지는 않았다. 새 미리보기 탭의 초기 로딩에서 수집된 오류·경고는 0개였다. 위 포인터 입력 검증과 그룹 이동은 실제 화면 결과로 별도 확인했다.
