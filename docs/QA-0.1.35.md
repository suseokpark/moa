# FAVMOA 0.1.35 · 백업 복원 미리보기와 충돌 복구

검증일: 2026-09-25 KST. [개선 큐](USABILITY-IMPROVEMENT-QUEUE.md) 2번 중 JSON 복원·복원 전 안전 사본 복구를 완료했다. 기존 Moa 가져오기 확인창은 다음 범위이며 전체 충돌 복구가 완료됐다는 의미는 아니다.

## 재현과 원인

0.1.34 배포 소스의 JSON 복원을 합성 DOM·실제 저장 서비스로 실행했다. 확인창 revision 7에서 저장소가 revision 8로 바뀌면 재시도 요청은 `[7,7]`, 화면 state는 8, 실행 버튼은 활성, 저장은 0회였다. 서비스 충돌 차단은 정상이지만 확인창이 이전 revision을 붙잡고 최신 영향 확인 경로를 제공하지 않았다. 복원 전 사본 복구는 기존 boolean 존재 표시만으로 실행하고 실제 복구 내용을 보여주지 않았다.

diagnose·TDD 절차로 좁은 재현부터 수정했다. 첫 fixture의 VM JSON 객체와 외부 validator realm 불일치가 파일 파싱을 먼저 막아, 같은 realm을 사용하도록 보완하고 실제 확인창 열림을 단언했다. 보완 후 과거 HEAD 함수를 다시 실행해 `[7,7]` 원래 증상을 확인했고, 변경 소스는 읽기·확인·별도 실행 계약을 통과했다. 이전 사본 경로와 서비스/플랫폼도 각각 RED→GREEN으로 연결했다.

## 구현 계약

- 신뢰된 sidepanel 전용 `FAVMOA_PREVIEW_BACKUP` / `platform.previewBackup()`이 현재 revision·catalog·Undo/사본 존재 여부와 실제 `restoreCatalog` 또는 null을 같은 서비스 큐에서 반환한다. 읽기만 하며 저장, schema 마이그레이션 사본, 원본 legacy 조회, 데모 변경 알림을 만들지 않는다. 기존 GET 응답은 그대로다.
- JSON 파일은 파싱·검증한 뒤 확인창 수명 동안 고정한다. 최신 현재 목록과 파일의 보관함/그룹/링크 수, 제목·주소·전체 그룹 경로를 표시한다. 긴 내용은 native details에서 펼친다.
- 변경된 JSON을 가져오면 기존 안전 사본을 교체 직전 목록으로 덮어쓰는 영향을 안내한다. 미리보기에서 사라질 기존 안전 사본 내용도 확인할 수 있다. 파일과 현재 목록이 같으면 저장·사본 교체 없이 유지한다.
- JSON 충돌 후 실행을 잠근다. 미리보기는 읽기만 하고 새로운 확인 체크 후 별도 가져오기를 요구한다. 검토·재충돌마다 이전 체크를 해제한다. 최초 JSON 확인창의 기존 명시적 전체 교체 동작은 유지하고 선택적으로 최신 미리보기를 제공한다.
- 복원 전 안전 사본 복구는 최초부터 실제 내용 미리보기·체크·별도 실행을 요구한다. 사본이 교체되면 최신 사본을 다시 보여주며, 없거나 손상됐으면 실행하지 않는다. 다른 목록으로 대체하지 않는다. 성공하면 사본을 소비하며 기존 1회 Undo 계약은 유지한다.
- 실제 실행은 검토한 expectedRevision을 사용한다. 사본 교체/소비 뒤 stale 실행은 서비스가 차단한다. 미리보기 내용을 UI 전역 state에 두 번째 catalog로 남기지 않는다.
- 오래되거나 잘못된 응답, 취소/대체창 뒤 늦은 응답, 읽기 실패는 실행을 허용하지 않는다. 읽기 중 취소 가능, 중복 읽기/쓰기 차단, 확인 해제 보호, 일반 저장 실패 후 명시적 재시도를 검증했다. 파일 이름/제목은 HTML로 해석하지 않는다.
- schema 2·저장 키·권한·고정 확장 ID는 유지했다. 사용자 데이터, 원본 탭·북마크, OAuth는 범위 밖이다.

## 전달과 한계

기존 설치 경로 `artifacts/favmoa-v0.1.13`이 0.1.34 압축 해제본과 일치함을 확인하고, `artifacts/favmoa-before-0.1.35-20260925`에 백업 후 프로그램 파일만 갱신했다. 소스/0.1.35 ZIP 압축 해제본/기존 설치 경로 **39파일 바이트 일치**를 확인했다. 사용자 저장 데이터는 읽거나 변경하지 않았다. 생성 ZIP·백업·합성 원장은 ignored 로컬 산출물이며 공개 저장소에 올리지 않는다.

실제 Chrome 화면 검증은 미실행이다. 최근 내부 브라우저 연결 실패를 반복하지 않았고 차단된 관리 URL을 우회하지 않았다. 확장 카드 새로고침과 실제 런타임 반영은 사용자 확인이 필요하다. 네이티브 포인터·키보드·스크린리더, 긴 목록의 실제 가독성도 별도 확인 대상이다.

다음은 기존 Moa 가져오기 확인창의 최신 **대상 목록** 재검토다. legacy 원본은 catalog revision과 별개이므로 이번 미리보기로 원본까지 검증했다고 주장하지 않는다. 이후 우선순위 3·4번(수동 추가/이동 결과 표시, 보관함 전환 검색 정리)으로 진행한다.
