# FAVMOA 0.1.21 QA — 그룹 색상과 테마 팔레트 아이콘

기록일: 2026-09-23 KST. 이번 버전에서 실행한 증거를 기록하며 코드·합성 검증과 실제 Chrome 사용을 구분한다. 과거 버전의 통과 수치를 재사용하지 않는다.

## 변경 범위

- 상단 **테마** 버튼에 장식용 팔레트 아이콘을 더하고 텍스트 이름은 유지한다.
- 모든 그룹의 **더보기 → 그룹 색상**에서 색상 선택기·HEX 입력으로 색을 정한다. 미분류 그룹도 색은 변경할 수 있지만 이름 변경·이동·삭제 보호는 유지한다.
- **저장**으로 확정하고 취소·닫기는 기존 색을 유지한다. **기본 색상**도 저장해야 색 지정 해제가 확정된다.
- 색은 그룹 이름 옆 표식과 트리 연결선에 표시한다. 하위 그룹은 각각 독립적이며 상위 그룹 색을 자동으로 물려받지 않는다. 텍스트 이름과 폴딩 표시를 유지한다.
- Group의 선택적 `color` 값은 엄격한 `#rrggbb`이며 기본값은 필드 없이 표현한다. 색상 없는 기존 그룹·백업을 불필요하게 다시 쓰지 않는다.
- 그룹 색상은 catalog·되돌리기·JSON 백업에 포함한다. 프로필별 전체 테마 저장 계약은 바꾸지 않는다.
- 공개키·고정 ID `ebbgmhdbonpillbfjapebljagnbjembj`·권한을 유지한다. Notion 콘텐츠 스크립트는 없으며 Google 연동은 계속 보류한다.

## 수용 기준

1. **테마**는 팔레트와 읽을 수 있는 텍스트 이름을 함께 표시하고 키보드로 열 수 있다.
2. 일반 그룹·중첩 그룹·미분류 그룹의 색을 지정할 수 있다. 잘못된 HEX·CSS 값은 저장하지 않는다.
3. 색을 선택한 뒤 취소·닫기는 기존 값을 보존한다. 기본 색상도 저장 전까지는 편집 중 상태다.
4. 저장한 색은 재열기·그룹 이동·되돌리기·JSON 내보내기/복원에서 보존된다. 이름·링크·하위 구조는 색상 편집으로 변경되지 않는다.
5. 자식 그룹은 상위 색을 자동으로 상속하지 않는다. 색상 표식 외에도 이름·폴딩·현재 위치를 식별할 수 있다.
6. 지정 색이 없는 기존 schema 1·2 백업은 가져올 수 있다. 새 색상 필드가 없는 기존 그룹은 필드를 임의로 추가하지 않는다.
7. 전체 테마 저장 키·이전 `nfs:` 데이터는 그룹 색 편집으로 바뀌지 않는다. 추가 권한·원격 자원·로그인은 요구하지 않는다.
8. 오래된 revision·저장 실패를 성공으로 표시하거나 최신 목록을 덮어쓰지 않는다.

## 백업 호환성

catalog의 `schemaVersion`은 2를 유지하고 `color`만 선택적으로 확장한다. 0.1.20 이하의 엄격한 Group 검증은 색상 필드를 인식하지 못하므로 **색상이 들어간 백업은 0.1.21 이상에서 복원**해야 한다. 색상을 저장한 현재 저장소 위에 구버전을 덮어씌우는 다운그레이드는 지원하지 않는다. 업데이트 전 JSON 파일은 별도로 보관해야 한다. 기본 색상으로 돌아갈 때는 `color`를 제거하되 전체 테마는 변경하지 않는다.

## 패키지와 설치

- 산출물: `artifacts/favmoa-v0.1.21.zip`, **35개 런타임 파일**, **179,775바이트**. 같은 버전의 압축 해제 폴더도 생성했다.
- SHA-256: `d6d73d543e9466e43349936bf31be44822aa88c5105aebd99e33700c03cb1c6b`.
- Chrome의 기존 등록 경로 `artifacts/favmoa-v0.1.13`은 이름을 바꾸지 않고 0.1.21 프로그램 파일로 업데이트했다. 공개키 기반 ID `ebbgmhdbonpillbfjapebljagnbjembj`와 권한은 그대로 유지한다.
- 직전 0.1.20 프로그램 파일은 `artifacts/favmoa-before-0.1.21-20260923`으로 이동해 복구 가능하게 보존했다. 이는 **프로그램 파일 백업**이며 사용자 저장 데이터의 백업이 아니다.
- Chrome 관리 화면에서 Reload를 실행한 뒤 **0.1.21 / Reloaded**를 확인했다. 실제 확장 페이지의 그룹 색상 저장 검증과는 구분한다.
- 사용자 Chrome 프로필·저장 데이터·인증 정보를 직접 읽거나 수정하지 않았고 GitHub에 푸시하지 않았다. localhost 검증용 임시 그룹만 제거했으며 원래 데모 보관함·링크 1개는 유지했다.

## 한계와 제외 범위

- Node·모의 저장소·localhost 검사는 실제 Chrome 확장 저장·OS 색상 선택기·다른 PC의 동작을 대신하지 않는다.
- 기존에 보호된 확장 페이지에 대한 접근이 거부되어 해당 경계를 우회하지 않았다. 실제 Chrome 그룹 색상 저장·패널 재시작은 미검증이며, Chrome 관리 화면의 버전 확인만으로 이를 통과 처리하지 않는다.
- 브라우저의 네이티브 색상 선택기 대화상자는 열어 검증하지 않았다. 색 입력 연결은 모의 검사, 실제 브라우저 조작은 프리셋·HEX 입력 경로로 확인했다.
- 색 표식을 사용하는 것은 전체 화면의 접근성 인증이나 실사용자 검증을 의미하지 않는다. 200% 확대·다양한 디스플레이도 확인 범위에 없으면 미검증으로 남긴다.
- 고정·최근 링크, 키보드 위치 이동 개선, 테마 클라우드 동기화·테마 파일 내보내기는 이번 범위가 아니다.
- 종료된 Notion 전용 화면을 다시 넣거나 Google 로그인·Drive 백업을 활성화하지 않는다.
