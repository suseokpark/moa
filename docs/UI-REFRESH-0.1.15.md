# FAVMOA 0.1.15 · UI 리프레시

작성일: 2026-09-23 · 대상: Chrome 사이드 패널과 설치 도움말 · 목표 버전: 0.1.15

## 방향

**조용한 링크 서랍.** 자주 찾는 링크의 이름과 현재 위치가 먼저 보이고, 저장·분류·백업 도구는 필요한 순간 쉽게 찾을 수 있게 한다. 밝은 불투명 바탕, 절제된 초록 포인트, 읽기 쉬운 목록으로 산뜻함을 만든다. 브랜드 심벌과 그룹 → 섹션 → 링크 모델은 유지한다.

“AI가 만든 디자인”은 객관적으로 판정할 수 있는 양식이 아니다. 이번 작업에서는 사용자의 의도를 **범용 템플릿처럼 보이는 장식과 불필요한 과장을 피하고, 일상적인 사용 디테일을 다듬는 것**으로 해석한다. 새 브랜딩이나 유행 효과의 도입이 목표가 아니다.

## 개선 대상 — 0.1.14 기준

이 항목은 이전 스타일의 구조와 화면 점검에서 검토할 문제를 정리한 것이며, 새 버전의 개선 효과를 검증한 결과가 아니다.

1. **작은 메타 글씨:** 사이드 패널의 주소·개수·상태·일부 조작에 9~11px 크기가 사용됐다. 짧은 공간에서 정보를 많이 보여주지만, 긴 한글 제목과 보조 설명을 읽는 데 불리하다. 도움말의 본문과 메타 크기도 일관되지 않았다.
2. **중복되는 박스 강조:** 로컬 저장 안내, 현재 페이지, 빈 상태 등이 각각 경계선과 배경을 갖는다. 위에서 아래로 여러 안내 카드가 연달아 나타나 실제 링크 목록보다 큰 시각적 비중을 차지할 수 있다.
3. **색과 경계의 경쟁:** 초록빛 바탕·유색 카드·여러 경계선이 동시에 쓰여 링크·검색·현재 위치의 중요도가 충분히 구분되지 않을 수 있다.
4. **좁은 화면의 도움말:** 설치 도움말은 body 너비가 368px로 고정되어 있었다. 더 좁은 미리보기에서도 가로 넘침 없이 읽을 수 있는 유연한 너비가 필요하다.

## 적용 목표

- 바탕 `#fff`, 보조 면 `#f6f8f7`, 본문 `#232927`, 보조 글자 `#626b66`, 강조 `#176b55`, 경계 `#e6e9e7`의 제한된 토큰을 사용한다. 색 대비는 별도 검증한다.
- 링크·그룹 제목은 14px, 주요 조작·섹션은 12px, 주소·개수 등 메타 정보는 11px로 정리했다. 설치 도움말은 본문 13px·메타 12px이다. 기존 8~9px 글자를 없애고 한글·영문 제목과 아이콘 기준선을 확인했다.
- 설정과 보조 설명의 외곽 카드 강조를 줄이고, 그룹·섹션·링크의 기존 계층은 그대로 보이게 한다.
- 호버, 현재 선택, 키보드 초점을 구분한다. 마우스를 올리지 않아도 현재 위치를 알 수 있어야 한다.
- 과장된 그림자, 투명 배경, 장식용 그라데이션과 이모지를 추가하지 않는다. 새 이미지·브랜드 자산도 만들지 않는다.
- 어두운 환경에서는 바탕 `#191d1b`, 본문 `#e9efeb`, 보조 글자 `#afb9b2`를 중심으로 읽기 쉬운 대비를 유지한다.
- 데이터 모델·저장 키·확장 공개키·ID·권한 범위는 바꾸지 않는다. Google 연결 보류와 로컬 저장·JSON 백업 정책을 유지한다.

## 아이콘과 세부 동작

- [Phosphor Core 2.1.1](https://www.npmjs.com/package/@phosphor-icons/core)의 Regular 아이콘 8개를 그대로 번들링했다. 검색·추가·메뉴·접기·펼치기·링크·닫기·체크에 사용한다. [공식 저장소](https://github.com/phosphor-icons/core)의 MIT 라이선스를 ZIP에도 포함하며 외부 CDN 요청이나 새 런타임 의존성은 없다.
- 사용자 링크의 유효한 이모지와 기존 브랜드 마크는 유지한다. 기능 아이콘은 장식 요소로 숨기고 버튼의 접근 가능한 이름을 유지한다.
- Chrome 116~119를 위해 `-webkit-mask`도 포함한다. 접두사 없는 마스킹은 [Chrome 120에서 도입](https://developer.chrome.com/blog/chrome-120-beta?hl=en)되었으므로 최신 브라우저에서 보이는 것만으로 하위 버전 호환을 가정하지 않았다. 해당 가드는 실패 → 수정 → 통과를 확인했다.
- 메뉴는 아래 공간이 부족하면 위로 열린다. 더 작은 높이에서는 메뉴 자체를 스크롤할 수 있다. 검색창의 브라우저 기본 지우기와 앱 지우기 버튼이 중복되던 표시도 제거했다.

## 2026-09-23 검증 결과

현재 소스의 localhost 미리보기와 합성 Notion fixture를 Chrome에서 실행했다. 실제 설치 확장과 실계정 테스트는 아니다. 전체 전후 비교, 개별 증거 및 한계는 프로젝트 루트 [디자인 QA](../design-qa.md)에 기록했다.

| 확인 항목 | 결과 |
|---|---|
| 320px·360px에서 링크·폼·도움말 | 통과 — 320px 패널·도움말의 가로 넘침 없음, 긴 한글은 말줄임 |
| 밝은/어두운 색상에서 본문·보조 글자·초점 대비 | 통과 — 불투명 텍스트 조합 4.5:1 이상, 실제 입력·초점 면 3:1 이상. 전체 WCAG 인증을 뜻하지 않음 |
| 링크 추가·이름 수정·검색·검색 해제·접기·현재 위치 | 통과 — 접힌 그룹의 검색 결과 표시 및 저장 위치 자동 펼침/초점 확인 |

| 자동 테스트·기존 Notion 합성 브라우저 검사 | 328/328 및 8/8 통과, 새 디자인 회귀 검사 12개 포함 |

전후 비교는 같은 360px 폭·같은 합성 링크 2개·같은 접힘 상태의 `artifacts/design-0.1.15/01-before-tree.jpg`와 `02-after-tree.jpg`를 같은 입력에서 함께 비교했다. 최종 소스의 추가·수정 시나리오 후 화면은 `12-final-tree.jpg`이며 링크가 3개이므로 동일 상태 전후 비교에는 쓰지 않는다.

실제 설치된 확장 화면과 실계정 검증은 localhost 합성 미리보기와 구분한다. 접근이 제한된 실제 확장 화면은 미검증으로 남기고, 이를 우회해 조작하지 않는다.
