# FAVMOA 0.1.32 · 이름·그룹 색상 편집의 충돌 검토

검증일: 2026-09-25 KST. [개선 큐](USABILITY-IMPROVEMENT-QUEUE.md) 2번의 세 번째 단위다. 보관함·그룹 추가와 이름 변경, 그룹 색상 편집을 포함한다. 그룹/일괄 링크 이동과 삭제·초기화·백업 확인은 아직 후속이다.

## 재현과 원인

실제 sidepanel 소스를 합성 DOM/저장소에서 실행했다. 이름 편집 액션 네 종류에서 revision 7로 창을 열고 revision 8 충돌 응답을 받은 뒤 재제출하자 요청은 모두 `[7, 7]`이었다. 저장 버튼도 다시 활성화됐다. 최초 이름·색상 회귀 4개의 RED를 확인했다.

또한 원래 보관함이 삭제된 뒤 그룹 이름 변경 재시도의 libraryId가 다른 보관함으로 바뀌는 것을 독립 재현했다. 서비스 revision 검사가 쓰기를 차단하고 있었지만, 단순히 revision만 갱신하면 같은 ID를 가진 다른 보관함의 그룹을 바꿀 위험이 있었다. 원인은 고정된 초기 revision과 보관함 ID를 생략한 액션의 조합이었다.

## 구현 계약

- `nameDialog`와 `groupColorDialog`는 공용 `metadataDialog`를 사용한다. 액션에는 원래 보관함 ID를 명시한다.
- 충돌 후 **입력 유지하고 최신 목록 검토**로 저장 목록만 읽는다. 입력·색상 초안을 보존하고 최신 스냅샷을 확인한 뒤 별도 저장을 요구한다. 자동 저장·원본 브라우저 데이터 재조회·권한 요청은 없다.
- 대상의 보관함 이름·그룹 이름·전체 경로 ID/이름을 비교하고, 색상 편집에서는 최신 색상도 비교한다. 대상이 달라졌으면 변경 전후를 보여주고 확인 체크 후에만 저장한다. 이름이 같은 상위 그룹 사이의 이동도 감지한다.
- 이름 변경 중 원격 색상 변경은 덮어쓰지 않으며, 색상 변경 중 원격 이름 변경은 검토 후 최신 이름을 유지한다. 재충돌·새 검토마다 확인 상태를 초기화한다.
- 기존 보관함·그룹·상위 그룹이 사라졌으면 입력을 유지한 채 저장을 차단한다. 다른 보관함·동일 ID 그룹·최상위 위치로 대체하거나 그룹을 자동 재생성하지 않는다. 상위 그룹이 최대 깊이로 이동했다면 하위 그룹 추가도 차단한다.
- 새 보관함 추가는 전역 작업이므로 원래 보관함 삭제와 별개로 최신 목록을 검토한 뒤 진행할 수 있다. 성공 시 이번 제출로 생성한 ID가 정확히 하나인 경우에만 그 보관함으로 이동한다.
- 검토는 잘못된 이름/미완성 색상 코드도 그대로 보존한다. 실제 저장 시에만 검증한다. 읽기 실패·오래된/잘못된 응답은 잠금을 풀지 않으며, 닫힌/교체된 창의 늦은 응답은 무시한다. 읽는 중 입력을 잠그되 취소는 가능하다.
- 검토 전 직접 submit은 쓰기를 만들지 않는다. 일반 SAVE_FAILED는 기존 재시도를 유지한다. 일시 오류 영역이 재제출로 비워져도 별도의 지속 안내는 남는다.

## 함께 보완한 입력 초점

잘못된 색상 코드로 제출하면 busy 처리로 비활성화된 HEX 입력에 `focus()`를 호출해 실제 초점 복귀가 되지 않는 경계를 재현했다. 편집기가 오류의 `focusTarget`을 전달하고 공용 form이 입력을 재활성화한 뒤 초점을 돌려주도록 수정했다. 원래 입력값과 `aria-invalid`, 저장 호출 0회도 회귀로 확인했다. 이 테스트의 RED → GREEN을 따로 검증했다.

## 화면 검증과 전달 범위

최근 두 회차에서 내부 브라우저 webview 연결 실패와 빈 탭 목록을 확인했다. 이번에는 같은 연결을 반복하거나 다른 표면으로 우회하지 않았고 실제 화면 검증은 수행하지 않았다. 위 검증은 합성 DOM/저장소 기준이며 네이티브 포인터·키보드·색상 선택기·시각 배치·스크린리더 음성 확인이 아니다. 기존 자동 클릭 문제도 아직 원인을 분리하지 못했다.

기존 설치용 `artifacts/favmoa-v0.1.13` 폴더가 0.1.31과 일치함을 확인하고 `artifacts/favmoa-before-0.1.32-20260925`에 백업한 뒤 배포 파일만 교체했다. 소스·ZIP 압축 해제본·기존 설치 경로의 **39개 파일이 바이트 단위로 일치**한다. 실제 사용자 저장 데이터·북마크·탭·Chrome 설정은 건드리지 않았다. 이전에 보안 정책으로 차단된 Chrome 확장 관리 URL을 우회하지 않았으며, 사용자가 확장 카드에서 새로고침해야 런타임 반영을 확인할 수 있다.

ZIP·설치 백업·합성 원장은 로컬 산출물이며 공개 저장소에 올리지 않는다. 다음은 그룹/일괄 링크 이동의 충돌 후 영향 범위 검토다. 수동 저장 결과 표시와 보관함 검색 정책은 큐 3·4번에 남아 있다.
