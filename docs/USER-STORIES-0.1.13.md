# FAVMOA 0.1.13 — 연결 실패 복구와 일상 사용성

- 작성일: 2026-09-23 KST
- 요청: 계정 연결이 되지 않는 문제를 점검하고, 일반 사용자가 쓰기 쉬운 사용자 스토리를 만든 뒤 개선한다.
- 범위: Google 연결의 상태·오류·복구 안내, 로그인 없는 시작, 현재 페이지 찾기, 보관함과 검색.
- 현재 상태: 아래 여섯 스토리의 이번 버전 범위를 구현했다. 자동 테스트와 로컬 화면 흐름을 검증했으며, **실제 Chrome에서 Google 인증 실패는 여전히 재현된다.** UI 개선 완료를 계정 연동 완료로 간주하지 않는다. 상세 결과는 [0.1.13 QA](QA-0.1.13.md)에 기록한다.

## 관찰한 문제와 검증 경계

이번 점검에서 0.1.12 로컬 사이드 패널 화면을 확인했다. Google 연결 기능이 하단의 접힌 설정에 있어 찾기 어렵고, 기술적인 설명이 길다. 미리보기에서 연결을 실행할 수 없을 때 다음 확인 방법을 찾기 어렵다. 빈 보관함은 미분류 그룹·섹션과 빈 상태 안내를 함께 보여 첫 행동을 분산시킨다.

소스에서는 화면의 `requireResult`가 오류 코드를 일반 문자열로 바꾸는 점, 연결 대기 중 제출 버튼만 비활성화되고 진행 상태가 명확하지 않은 점을 확인했다. 이는 **오류를 이해하고 복구하기 어렵게 만드는 확인된 결함**이지, 사용자의 실제 Google 인증 실패 원인을 입증한 것은 아니다.

실제 Chrome의 0.1.12에서 연결 확인 뒤 Google 동의 창 없이 일반 오류가 즉시 발생하는 흐름을 재현했다. 같은 고정 ID로 0.1.13을 설치한 뒤에도 인증은 실패했지만, 이제 진단에 `AUTH_FAILED`, 단계 `authorization`이 표시된다. 설치 버전·확장 ID·공개 클라이언트 ID와 인증 API 존재는 확인했다. Google Cloud의 클라이언트 유형·Item ID 등록·테스트 사용자·조직 정책 및 Google의 원본 실패 이유는 미확인이다. Google 동의 승인이나 Drive 업로드는 하지 않았다.

## 우선순위별 사용자 스토리

### US-01 · P0 — 연결 상태와 다음 행동을 바로 알기

**사용자로서**, 목록을 열었을 때 현재 로컬로만 쓰는지 Google에 연결했는지 알고 싶다. 그래야 설정을 뒤지거나 로그인이 필수라고 오해하지 않는다.

- 상단에서 로컬 사용 / 연결 중 / 연결 기록 있음 / 연결 실패 / 미리보기 상태를 구별한다.
- 연결 또는 연결 도움말을 한 번의 선택으로 찾을 수 있다.
- 로컬 저장·검색·정리는 로그인하지 않아도 사용할 수 있다.
- 연결 기록만 있을 때 지금 Google 서버 인증까지 확인했다고 표현하지 않는다.
- **수용 검증:** 미연결·연결 대기·성공 기록·실패·localhost 미리보기 상태를 확인하고, 미연결 상태에서 링크 저장과 검색이 가능함을 확인한다.
- **상태:** 구현. 상단 상태·연결 설정 바로가기·미리보기 도움말 및 미연결 상태의 저장·검색을 이번 브라우저 실행에서 확인했다. 실제 연결 성공 상태는 모의 응답으로만 검증했다.

### US-02 · P0 — 실패 이유에 맞는 복구 방법과 안전한 진단 정보

**계정 연결이 실패한 사용자로서**, 설정 문제인지, 권한 거부인지, 네트워크 문제인지 구별하고 다음 확인 방법을 보고 싶다. 개발자에게 재현 가능한 정보를 전달하고 싶다.

- 사용자 취소·클라이언트 설정·권한 부족·시간 초과·일반 인증 실패를 가능한 범위에서 구별한다. 알 수 없는 원인은 알 수 없다고 표시한다.
- 오류 코드와 해당 오류의 재시도·설정 점검 안내를 유지한다.
- 도움말에서 확장 버전, 공개 확장 ID, 공개 OAuth 클라이언트 ID와 점검 상태를 확인·복사할 수 있다.
- 진단 정보에 액세스 토큰, 쿠키, 개인 이메일, 저장 링크·제목·URL, 원본 오류 응답은 포함하지 않는다.
- 미리보기에서는 실제 Chrome 확장에서 확인해야 함을 안내한다. Google Cloud 설정이 로컬 점검만으로 검증됐다고 표시하지 않는다.
- **수용 검증:** 오류 유형별 모의 응답과 진단 정보 허용 필드를 검사한다. 보고서를 복사할 수 없는 환경에서도 선택·복사할 수 있는 대안을 제공한다.
- **상태:** 구현. 오류별 안내·단계 유지·진단 허용 필드를 자동 테스트로 확인했다. 실제 Chrome 실패 화면과 공개 설정 진단도 확인했다. 원본 인증 실패 원인은 여전히 미확인이다.

### US-03 · P0 — 연결을 기다리는 동안 멈춘 화면으로 느끼지 않기

**Google에 연결 중인 사용자로서**, 진행 중임을 알고 오래 응답이 없을 때 다시 시도할 수 있기를 원한다. 실패 때문에 보관함을 잃거나 같은 요청을 반복하고 싶지 않다.

- 인증 중 진행 문구를 보여주고 중복 제출을 막는다.
- 응답이 없으면 90초 뒤 대기를 종료하고 복구 안내를 제공한다. Chrome 인증 요청 자체가 끝나지 않은 동안에는 중복 창을 만들지 않으며, 해당 창을 완료·닫거나 확장을 새로고침하도록 안내한다.
- 만료된 요청의 늦은 성공 응답이 연결 상태를 뒤늦게 변경하지 않는다.
- 취소·실패·시간 초과는 로컬 보관함을 삭제하거나 자동 업로드하지 않는다.
- **수용 검증:** 지연·무응답·늦은 성공·취소를 모의 테스트하고 기존 catalog가 유지되는지 검사한다. 실제 Google 동의 창의 동작은 설치 확장에서 따로 확인한다.
- **상태:** 구현. 무응답·늦은 토큰 폐기·중복 인증 차단·인증 대기 중 상태 조회·연결 해제·로컬 보존을 모의 응답으로 검증했다. 화면이 활성 상태일 때 2초 간격 및 창 포커스 복귀 시 상태를 갱신하여 인증 요청이 끝난 뒤 재시도 버튼을 회복한다. 실제 Chrome은 즉시 오류가 났으므로 실제 Google 창의 장시간 대기는 미검증이다.

### US-04 · P1 — 지금 페이지가 저장된 위치로 바로 이동하기

**여러 보관함을 쓰는 사용자로서**, 현재 페이지를 이미 저장했는지 알고 그 위치로 이동하고 싶다. 같은 링크를 다시 저장하거나 모든 보관함을 찾아보고 싶지 않다.

- 현재 페이지가 다른 보관함에 있어도 저장 여부와 경로를 알려준다.
- 저장 위치를 선택하면 해당 보관함·그룹·섹션을 열고 링크를 강조한다.
- 검색으로 항목이 가려져 있다면 검색을 해제하고 보여준다.
- 여러 보관함에 저장되어 있으면 현재 선택한 보관함을 우선하고, 없으면 보관함 순서상 첫 위치로 이동한다. 임의로 데이터를 합치거나 삭제하지 않는다. 여러 저장 위치를 모두 나열하는 선택기는 후속 개선이다.
- **수용 검증:** 현재/다른 보관함, 접힌 그룹·섹션, 검색 중, 여러 위치, 미저장 페이지를 각각 확인한다. 위치 찾기는 저장 내용을 변경하지 않아야 한다.
- **상태:** 구현. 다른 보관함 탐색·현재 보관함 우선·Notion의 같은 페이지 식별은 자동 테스트로 확인했다. 이번 브라우저 실행에서 현재 링크 강조와 접힌 그룹의 저장 위치 보기 → 펼침·링크 초점 이동을 확인했다.

### US-05 · P1 — 검색을 쉽게 되돌리고 보관함 이름을 정리하기

**링크가 늘어난 사용자로서**, 검색 결과가 없을 때 전체 목록으로 쉽게 돌아가고 보관함에 이해하기 쉬운 이름을 붙이고 싶다.

- 검색어가 있을 때 명시적인 검색 지우기 행동을 제공한다.
- 검색 결과 없음과 빈 보관함을 구별한다.
- 현재 보관함 이름을 변경할 수 있고, 빈 이름·길이 제한 오류는 입력한 값을 유지한 채 안내한다.
- 이름 변경과 검색 해제 후 키보드 초점이 예측 가능한 위치에 남는다.
- **수용 검증:** 결과 있음/없음, 검색 해제, 이름 변경·취소·잘못된 이름, 좁은 패널과 키보드 조작을 검사한다. 이름 변경 시 링크·분류·보관함 ID가 유지되는지 확인한다.
- **상태:** 구현. 이번 360px 브라우저 실행에서 검색 결과 없음 → 검색 해제와 보관함 이름 변경을 확인했다. 검색 해제 시 검색창 초점을 복원한다. 320px에서 중복 URL 입력을 보존한 채 거절하고, Escape로 대화상자를 닫은 뒤 추가 버튼으로 초점이 복귀함을 확인했다. 모든 입력 오류와 전체 키보드·보조기술 경로를 수동 점검한 것은 아니다.

### US-06 · P1 — 첫 링크를 부담 없이 저장하기

**처음 사용하는 사람으로서**, 빈 화면에서 무엇을 해야 하는지 쉽게 알고 싶다. 기본 구조를 이해하기 전에 로그인이나 복잡한 설정을 요구받고 싶지 않다.

- 빈 보관함에 현재 페이지 저장·직접 링크 추가 등 짧고 명확한 시작 행동을 제공한다.
- 내용 없는 기본 그룹·섹션과 중복 빈 상태 안내가 동시에 주의를 빼앗지 않도록 한다. 사용자 정의한 구조는 숨기거나 삭제하지 않는다.
- 가져오기는 원본을 변경하지 않는 선택 기능임을 안내한다.
- 브라우저 설정 페이지 등 저장할 수 없는 화면에서는 이유와 직접 링크 입력 경로를 제공한다.
- **수용 검증:** 초기 빈 보관함, 사용자가 만든 빈 구조, 저장 불가 주소, 첫 링크 저장 뒤 트리 표시를 확인한다. 320px 폭과 키보드로도 핵심 행동을 실행할 수 있어야 한다.
- **상태:** 구현. 이번 360px 브라우저 실행에서 기본 빈 구조의 중복 노출 제거, 첫 링크 저장, 저장 뒤 1개 링크와 현재 위치 표시를 확인했다. 로그인 없이 현재 페이지 또는 북마크로 시작하는 행동을 제공한다. 320px 화면과 진단 대화상자의 가로 넘침 없음 및 일부 키보드 복귀 경로를 확인했다. 전체 키보드 검증을 완료한 것은 아니다.

## 이번 버전에서 하지 않는 일

- 자동 기기 간 동기화, 원격 변경 병합·삭제 전파.
- Google Drive 실제 하위 폴더·파일 탐색 또는 이를 위한 추가 OAuth 범위.
- Google 로그인으로 Notion 로그인을 대신하기.
- Cloud 콘솔 설정을 확인하지 않고 변경하거나 사용자 동의를 대신하기.
- 공개키·확장 ID·저장 키 변경, 기존 목록 초기화, 구형 Notion 데이터 삭제.

## 검증 체크리스트

1. 로컬 회귀: 기존 링크·분류·이전·되돌리기 계약, OAuth 오류·대기·늦은 응답, 공개 진단 정보만 노출되는지 자동 테스트.
2. 브라우저: 이번 실행의 스크린샷으로 초기 상태, 저장/찾기, 검색/이름 변경, 연결 도움말과 좁은 패널의 흐름 확인. 합성 데이터임을 명시.
3. 배포: 0.1.13 버전 일치, 고정 ID·공개키 유지, 기존 OAuth 클라이언트·권한 범위 유지, ZIP 검사.
4. 실제 연결: 설치한 Chrome 확장에서 실패 단계와 코드를 확보했다. 다음에는 Cloud 설정과 원본 오류를 확인한 후 실계정 동의를 거쳐 연결을 다시 시험해야 한다. 실제 백업은 계정과 전송 범위를 확인한 별도 사용자 동작으로 시험한다.

위 1–3의 성공은 4의 완료를 대신하지 않는다. 실제 실행 결과와 미검증 항목은 릴리스 QA 기록에서 분리해 남긴다.
