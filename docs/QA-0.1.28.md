# FAVMOA 0.1.28 사용성 점검과 개선

점검일: 2026-09-24 KST. 대상은 북마크 가져오기 → 검색·선택 → 저장·되돌리기다. 합성 localhost 데이터로 현재 화면을 직접 캡처했으며 사용자 Chrome 북마크는 읽거나 변경하지 않았다.

## 개선 전 관찰

1. **가져오기 진입 — 개선 필요.** 0.1.27의 가져오기 창은 원본 보존과 최대 개수를 안내하고 검색에 포커스를 준다. 하지만 선택이 0개여도 저장 버튼이 활성 상태이며 선택 개수·전체 선택 기능이 없다. 캡처 `01-before-empty-selection.png`를 저장 후 다시 열어 확인했다. 실제 브라우저 권한 요청 흐름은 이 예시 화면으로 판단하지 않는다.
2. **검색·선택 — 개선 필요.** 체크한 뒤 검색 결과를 0개로 만들면 선택은 유지되지만 버튼의 `선택한 1개 담기` 외에 숨겨진 선택 안내가 없다. 네이티브 체크박스·검색 라벨은 장점이다. `02-before-hidden-selection.png`로 확인했다. 전체 읽기 순서와 실제 음성 안내는 별도 검증이 필요하다.

코드 검토에서는 비동기 북마크 조회 후 보관함/revision을 정하는 순서, 늦은 결과의 다른 입력창 덮어쓰기, 300개 표시 제한과 1,000개 선택 제한의 불일치, 300자를 넘는 원본 제목 때문에 전체 저장이 거절되는 위험을 확인했다. 이 항목들은 화면 캡처로 직접 증명한 현상과 구분하며 회귀 테스트로 검증한다. 우선순위는 조회 격리 → 선택 안내/한도 → 저장 결과 가시성이다. 새 서비스 연결이나 권한 확장은 범위에 넣지 않는다.

## 개선 후 확인

1. **가져오기 진입 — 개선됨.** 즉시 로딩 창을 열고 조회 전 보관함/revision을 고정한다. 0개 선택에서 저장을 비활성화하고 기저장·중복 제외 수를 안내한다. `03-after-empty-selection.png`에서 두 합성 후보의 이름·주소·원본 폴더와 버튼 상태를 확인했다. 안내 문구 최종 간소화 전 캡처다. 380×820 화면에서 대화상자와 제출 버튼이 함께 보이며 원본은 변경하지 않았다.
2. **검색·선택 — 개선됨.** Space로 선택한 뒤 결과 없는 검색을 해도 `1개 선택 · 화면 밖 1개 포함`을 표시하고 `선택 해제`로 전체 선택을 비울 수 있다. `04-after-hidden-selection.png`는 최종 간소화 문구로 확인한 화면이다. 후보 로딩 후 사용자가 다른 곳으로 포커스를 옮기지 않았을 때만 검색 칸에 포커스를 준다.
3. **저장 결과 — 개선됨.** 외부 검색을 결과 없는 문구로 설정하고 대상 그룹을 접은 뒤 합성 북마크 2개를 저장했다. 저장 직후 외부 검색이 비워지고 대상 그룹이 펼쳐져 포커스를 받으며, 기존 1개와 새 2개가 함께 보인다. `05-after-saved.png`를 저장·재열람해 확인했다. 원본 북마크 수정 없이 단일 되돌리기가 가능한 안내도 표시된다.

되돌리기를 한 번 누르자 새 2개가 함께 제거되고 기존 1개와 저장 전 접힘 상태로 돌아왔다(`06-after-undo.png`). 검증을 위해 접었던 그룹은 다시 펼쳐 원래 목록·배치로 복원했다. 최종 문구와 검색 포커스, 0개 선택/저장 비활성 상태는 `07-after-empty-final.png`를 추가 캡처·재열람해 확인했다. 현재 실행의 콘솔 warning/error는 0건이었다.
