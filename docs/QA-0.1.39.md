# FAVMOA 0.1.39 · 순서 독립 다중 키워드 검색

검증일: 2026-09-25 KST. [개선 큐](USABILITY-IMPROVEMENT-QUEUE.md) 5번을 메인 보관함 트리 검색으로 한정해 완료했다. 다음은 6번 대량 후보 선택 반복 줄이기의 재현·범위 검토다. 실제 사용자 데이터 대신 합성 DOM·catalog를 사용했다.

## 재현과 결정

실제 sidepanel의 검색 입력 이벤트로 `철도 여행`은 링크 1개를 찾지만 `여행 철도`는 0개인 RED를 재현했다. 기존 `projectGroup`이 전체 검색어를 연속 부분 문자열로 비교하기 때문이다. 첫 수정으로 단어 순서 독립성을 확인한 뒤, 제목·주소·조상 그룹에 흩어진 단어 조합의 실패를 별도 재현하고 범위를 확정했다. diagnose·TDD 절차로 단계별 RED→GREEN과 독립 경계 검토를 진행했다.

검색은 **공백으로 나눈 모든 단어(AND)**를 같은 링크의 제목·저장된 URL·조상 그룹 이름에서 대소문자 구분 없이 문자 그대로 찾는다. 그룹 경로만으로 모든 단어를 만족하면 그 아래 링크를 포함한다. 각 단어 자체는 한 필드 또는 한 그룹 이름 안의 부분 문자열이어야 하며, 단어 한 개를 여러 필드 경계에 걸쳐 이어 붙이지 않는다. 다른 링크·형제·사촌 그룹의 단어를 합치지 않는다. 정규식·연산자·따옴표 구문·유사어·URL 디코딩은 추가하지 않았다. 열린 탭·북마크 후보 선택창 검색은 기존 계약을 유지한다.

## 구현 계약

- 렌더마다 검색어를 정규화·분리·중복 제거한다. 각 그룹에서 이름에 일치한 단어를 제외한 새 배열을 자기 하위 분기에 전달한다. 전체 조상 경로를 링크마다 다시 만들거나 형제끼리 일치 상태를 공유하지 않는다.
- 링크마다 제목·주소를 한 번씩 소문자로 변환하고 남은 모든 단어를 검사한다. 원본 제목·URL·색상·접힘·순서·선택·catalog·revision·Undo를 변경하지 않는다.
- 결과 상위 경로, 링크 개수, 그룹 이름으로 하위 자료 찾기, 검색 중 폴딩 비활성화, 검색 해제 후 기존 접힘과 현재 페이지 표시 규칙을 유지한다. 매칭하는 빈 그룹은 0개로 표시한다. 현재 열린 페이지라도 검색과 무관하면 결과 링크로 끼워 넣지 않는다.
- 숨겨진 다중 선택을 유지하고 ‘보이는 링크 모두 선택’은 검색 결과 범위만 대상으로 한다. 결과 클릭은 저장된 전체 URL을 그대로 한 번 전달한다. 검색 자체로 링크를 열거나 저장하지 않는다.
- 검색창에 제목·URL·그룹 검색 placeholder와 짧은 안내를 추가하고 `aria-describedby`로 연결했다. HTML 연결은 확인했으나 실제 스크린리더 발화나 화면 가독성을 검증했다는 뜻은 아니다.
