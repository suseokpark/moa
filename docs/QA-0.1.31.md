# FAVMOA 0.1.31 · 링크 입력·수정·단일 이동의 충돌 검토

검증일: 2026-09-25 KST. [개선 큐](USABILITY-IMPROVEMENT-QUEUE.md) 2번의 두 번째 단위다. 수동 링크 추가·수정과 단일 링크 이동만 포함하며, 이름 변경·그룹 색상·그룹/일괄 이동·삭제/백업 확인창은 후속이다.

## 재현과 원인

실제 sidepanel 소스를 합성 DOM과 저장소 fixture에서 실행했다. 추가·수정·이동 세 창 모두 revision 7에서 연 뒤 revision 8 충돌 응답을 받았을 때 재시도는 `[7, 7]`로 전송됐고 저장 버튼이 다시 활성화됐다. 입력 값은 남아 있었으나 명시적으로 최신 목록을 검토하는 경로가 없었다. 창을 다시 열면 요청이 8로 바뀌는 것을 확인했다.

단일 이동은 추가 위험도 있었다. 최초 보관함이 삭제되면 `adopt()`가 다른 보관함을 선택하고 재시도 액션의 libraryId도 그 값으로 바뀌었다. 기존 서비스 revision 검사가 쓰기를 막고 있었으므로 실제 데이터 변경은 없었지만, 단순히 revision만 갱신하면 다른 보관함으로 의도를 재해석할 수 있었다. 최초 4개 회귀의 RED를 확인한 뒤 수정했다.

## 구현 계약

- 세 흐름을 같은 링크 대화상자 내부에서 처리하며 이동 액션도 원래 보관함 ID를 고정한다.
- 충돌 후 **입력 유지하고 최신 목록 검토**로 `platform.load()`만 실행한다. 입력·목적지 선택을 보존하고 검토한 revision으로 별도 저장을 요구한다. 자동 재시도·권한 요청·브라우저 원본 조회는 없다.
- 최신 보관함 이름·그룹 경로를 표시한다. 수동 추가의 사라진 목적지는 보관함과 그룹을 직접 다시 선택하게 한다. ID가 같은 미분류 그룹으로 자동 대체하지 않는다.
- 수정·이동할 기존 링크나 보관함이 없어졌으면 저장을 차단한다. 다른 보관함의 같은 링크 ID나 같은 URL을 대체 대상으로 삼지 않고 자동으로 새 링크를 만들지 않는다. 입력은 복사할 수 있도록 남긴다.
- 기존 링크의 이름·주소·소속 경로가 달라졌으면 처음 열었을 때와 최신 저장 내용을 비교 표시한다. 확인 체크박스를 직접 선택하기 전에는 버튼과 실제 submit을 모두 차단한다. 재충돌과 새 검토마다 확인 상태를 초기화한다.
- 수정은 사용자가 입력한 이름·주소만 적용하므로 최신 아이콘 등 다른 필드는 유지한다. 이동은 최신 링크 내용 그대로를 선택한 그룹으로 옮긴다. 서비스의 revision 충돌 검사는 그대로 유지한다.
- 읽는 동안 입력·중복 읽기·저장을 막고 취소는 허용한다. 닫힌/다른 창의 늦은 응답, 잘못된 catalog, 현재 상태보다 오래된 revision은 적용하지 않는다. 읽기 실패는 입력을 보존하고 내부 오류 원문을 노출하지 않는다.
- 일반 저장 실패 재시도와 URL·선택 이름 검증, 오류 필드 초점, 기존 disabled 상태 복원은 유지한다.

## 독립 검토에서 보완한 경계

처음 구현은 최하위 그룹 ID와 이름으로 만든 경로만 비교했다. 같은 이름의 서로 다른 상위 그룹 사이로 같은 하위 그룹이 이동하면 위치 변경을 놓쳤다. 수정·이동 각각 RED를 재현한 뒤 **전체 경로의 그룹 ID 배열**까지 비교하도록 고쳤다. 표시 이름이 같아도 다른 상위 그룹으로 이동했다는 안내와 명시적 확인을 요구한다. 최종 독립 검토에서 추가 구체적 문제는 발견하지 못했다.
